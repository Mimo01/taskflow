Component sizing:
- Discard dialog: existing `DialogContent` default `sm:max-w-sm` (384px), `showCloseButton={false}`, no size override.

## Interaction Contract

### Draft note (D-04, D-06, D-07)
- Placement: in the host's action row, left of the Cancel/Save (or Send) buttons, left-aligned in the free space; the buttons keep their current right alignment. In the composer it sits in the existing action row left of Send.
- Copy: `Draft saved · Discard` ("·" is U+00B7 with 4px each side). Shown only when a draft exists for that host and the editor content differs from base (an empty composer shows nothing).
- It appears after the debounced write (about 500ms after last keystroke), no animation, no layout shift (reserve the 24px line in hosts where the row exists regardless).
- "Discard" removes the draft, resets the editor to base text (composer: empty; edit hosts: Jira text) and returns focus to the editor. No confirmation (single click, D-07 explicit Discard). Because it is destructive of typed text, it is only offered when the draft is non-empty.
- Restore: editor reopens prefilled; caret goes to the end of the document only when the host opens focused. Comment-edit drafts reopen that comment in edit mode on issue open; the comment scrolls into view.

### Stale base line (D-05)
- Copy: `Changed in Jira since your draft` + inline action `Use Jira version`. Replaces the draft note in the same slot (never both lines at once).
- "Use Jira version" replaces the editor content with Jira's current text and clears the draft; undo (Cmd+Z) in the editor reverts it. No confirmation.
- Saving with the line showing overwrites Jira silently, as today.

### Discard changes dialog (D-08, D-09, D-10)
Built on `dialog.tsx`, structurally identical to `confirm-sprint-move-dialog.tsx`: `DialogContent showCloseButton={false}`, `DialogHeader` (`DialogTitle`, `DialogDescription`), `DialogFooter`.
- Title: `Discard changes?`
- Description: `Your unsaved changes will be lost.`
- Footer, left to right: `Keep editing` (`variant="outline"`, autofocused) then `Discard` (`variant="destructive"`). Footer order follows the existing confirm dialog (secondary first, primary last).
- Esc = Keep editing: closes only this dialog; the parent Edit Issue dialog and the editor stay as they were (nested Esc, 99 D-20). Backdrop click = Keep editing.
- Stacking: portals to body above the Edit Issue dialog (both `z-50`, later in DOM order); focus returns to the editor on Keep editing.
- Shown only on explicit Cancel button or Esc in a comment edit or the Edit Issue modal and only when the editor `unchanged` verdict is false. Never on: peek close, navigation, X, backdrop, quit (draft kept silently). Comment-edit Cancel/Esc confirm uses the same dialog.
- Confirming Discard removes the draft, then closes/exits edit mode.

### Keys (D-11..D-15)
| Context | Cmd+Enter | Esc |
|---------|-----------|-----|
| Composer | Send (no-op when empty/uploading) | Open popover/bubble/menu first; otherwise blur, keep text as draft, no dialog |
| Comment edit | Save | Popover first; otherwise Cancel flow (dialog only if changed) |
| Edit Issue modal | Submit whole form from any field | Popover first; otherwise Cancel flow (dialog only if changed); X/backdrop close silently |
| Create Issue modal | Submit whole form | Existing close behaviour (Phase 101 owns drafts) |
| Create Epic modal | Submit whole form | Existing close behaviour |

- Enter alone never sends or submits. Cmd+Enter does not fire while an IME composition is active or while a suggestion popover is open.
- Cmd+Enter in a disabled/invalid form does the same as the disabled primary button: nothing, and the first invalid field gets focus.
- Tooltips: the Save / Send / Create / Submit button tooltip shows the label plus keycaps (`keycap.tsx`, 98 D-04 style): "Send  ⌘ ↵", "Save  ⌘ ↵". Cancel tooltip: "Cancel  Esc". Hints registered in `lib/shortcuts.ts` so the ⌘/ panel lists "Submit editor or form: ⌘ ↵" and "Cancel editing / leave editor: Esc".

### Host adoption (D-02, D-16)
- Create Epic and Create/Edit Issue description: `full` preset toolbar; the Edit/Preview tabs and textarea toolbar disappear (Rich|Source toggle from 98 replaces Preview). Create Issue shows no draft note (Phase 101).
- Comment composer and comment edit: `compact` preset (bubble menu + slim footer with Attach, Mention, Emoticon, Rich|Source). The composer keeps its sticky bottom position, current min-height, and focus stays in the cleared editor after Send. The notification Reply action focuses the editor via its focus API.
- Comment edit shows Cancel (outline) and Save (primary) in the same position and sizes (`size="sm"`) as today; attach/mention controls live in the editor footer, not duplicated in the action row.
- Edit Issue modal: description editor + draft note in the description field's footer line; modal footer unchanged.
- Loading: `WikiEditorLazy` skeleton at the equal height of the final editor; no spinner.
- Description on issue detail and peek stays read-only WikiRenderer with no pencil and no click-to-edit (D-01).
