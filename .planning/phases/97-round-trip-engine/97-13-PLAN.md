Parser facts verified by scratch runs while planning (use them as the expected re-parse shapes):
- `* a\n{status:x}` parses to listItem[paragraph[text "a", hardBreak{src:"\n"}, rawInline{raw:"{status:x}"}]]: a single-line raw on its own line after an item is a continuation of the item.
- `* a\n{info}x{info}` and `* a\n{code}\nx\n{code}` parse to a list followed by a separate top-level panel / codeBlock: the parser never puts a panel or code block inside a list item.
- `|{info}x{info}|b|` parses to a tableCell whose content is a panel (cell panels are modelled); cells otherwise contain paragraphs only.
- `| |b|` parses to a 2-cell row; the first cell has `padL: " "` and an empty paragraph.
- `|a\\\\b|c|` and `h1. a\\\\b` parse with hardBreak `{src:"\\\\"}` inside the cell / heading.
- `[~accountid:abc]` parses to mention {id:"abc", src:"[~accountid:abc]"}; `!a.png|width=3!` to image {name, params, src}; `[x|^f.pdf]` to attachment {name, label, src}.
- `{code:language=java}` is a rawBlock today, so only the `{code:LANG}` open form needs the WR-02 check for code blocks.
- emit.ts `CANONICAL_DELIMS` comes from parse/marks.ts; `COLOR_OPEN` (regex, group 1 = value) is exported from parse/color.ts.
