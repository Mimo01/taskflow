<objective>
Close verification gap 1 (SAFE-06 / SC3, review CR-01): typed `a {code}x{code} b`, `{info}…{info}`, `{quote}…{quote}` and `{noformat}…{noformat}` mid-line are saved unescaped and render live. Also apply the review's WR-04 fix so typed atom look-alikes are spelled with an escaped opening delimiter. Jira documents that form as literal, and 97-15 renders it literally.

Design choice (Claude's discretion, deviates from the verifier's suggested fix): the verifier suggested always force-escaping the `{` of live macro names inside `inlineSegments`. That would also rewrite *parsed* text. While planning I checked that `panels/panel-mid-line.wiki` loads `rich` with `{note}`, `{warning}` and `{info}` held as plain text. A forced escape would remove those live callouts from Jira on the first edit of any such doc, and the save check would accept it (an escape compares as its character). Instead, the editor parser models these mid-line tokens as rawInline atoms, which is the D-10 "smallest span" rule already used for unknown macros such as `{status}`. Parsed tokens are then replayed verbatim. Typed look-alikes no longer re-parse to the same display, so the existing re-parse minimiser escapes their `{` sites, and `checkSaved` (shape rule 2 keeps `rawInline.raw`) fails closed if they are ever written unescaped. The save check therefore sees what the renderer sees for these tokens without importing the renderer.

Purpose: SAFE-06 "never read as markup" for typed text, without breaking SAFE-04/D-05 for parsed text.
Output: parser change, minimiser ordering, unit tests in raw/escape/save-check.
</objective>
