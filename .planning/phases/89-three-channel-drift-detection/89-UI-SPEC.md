# Phase 89 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds **one new section** (MR-first drift list) to the existing release detail page, re-sources one existing cell (Issues table MR column, D-05/D-06 — visual treatment unchanged), and adds **one aggregate indicator** to an already-reserved slot in `ReleasesTab.tsx` (D-15). No new page, no new route, no new shadcn primitives. Everything below is scoped to those three surfaces.

Reuses the existing release-detail scale verbatim — no new sizes introduced (D-04 compactness forbids adding a heavier type step).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|

| Row primary text (`!iid`, title) | 12px (`text-xs`) | 400 (regular) | 1.5 |

Only two weights across the whole section: 400 (row text) and 500 (headings, badges, status glyphs) — matches the codebase's existing 2-weight discipline (no semibold/bold introduced).

## Color

Reuses the app's existing OKLCH neutral theme tokens (`--background`, `--card`, `--muted`, `--border`) — no new theme tokens. The 60/30/10 split below describes this section's composition within the release-detail page, not a new palette.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--card` (existing) | Section background, row background |
| Secondary (30%) | `--muted` / `--border` (existing) | Row separators (`border-b border-border/50`), muted/merged/closed row text, section subtitle |
| Accent (10%) | `orange-600`/`orange-400` (existing warning tone, matches `IssuesSection.tsx` "Wrong milestone"/"Missing MR" and `ReleasesTab.tsx` branch-missing indicator) | The `⚠` glyph in BR/MS/TASK columns only, and the row's flagged-state left cue (see below) |
| Destructive | `--destructive` (existing) | Not used in this phase — no destructive actions here (read-only; Phase 90 owns writes) |

Accent reserved for: **the `⚠` glyph inside a status column cell, and nothing else.** Do not tint the `!iid` button, the title text, or the row background orange — D-04 compactness means the flag must be scannable from the status columns alone, not from a full-row color wash. Clean columns render `✓` in `green-600`/`green-400` (matches existing `state === 'merged'` convention); not-evaluated columns render `—` in `text-muted-foreground` (matches `IssuesSection.tsx:173` `gitlabMatchType === 'none'` treatment).

State-badge colors (author's MR open/merged/closed/draft pill) reuse the existing three-way palette from `UnmatchedMRsSection.tsx`/`IssuesSection.tsx` verbatim:
- `merged` → `green-600`/`green-400`
- `opened` (includes draft, D-10 evaluates drafts as open) → `blue-600`/`blue-400` (IssuesSection convention) — do not reuse `UnmatchedMRsSection`'s orange-for-opened variant, since orange is now reserved for drift flags per D-09/accent rule above and would collide visually with the `⚠` glyph
- `closed` → `gray-500`, muted, matches D-10's "shown muted, never evaluated"

Merged/closed rows (D-10): apply `text-muted-foreground` / `opacity-70`-equivalent muting to the row's title and key text (not full `opacity-70` on the row, which would also fade the state badge past legibility) — same visual family as `ReleasesTab.tsx:544` muted "No GitLab milestone" treatment.

## Layout Contract (D-20 — binding, not discretionary)

No `<table>`. The MR list is `div` + flex rows:

- Row container: `flex items-center gap-2 text-sm py-1 border-b border-border/50` (matches `UnmatchedMRsSection.tsx:36` row shape)
- `flex-none` cells with **explicit px widths** (not `w-*` Tailwind scale alone — verify computed px in the WebKit/Tauri webview per the narrow-column-collapse defect):
  - `!iid` — `shrink-0`, monospace, ~44px
  - Jira key — `shrink-0`, monospace, ~72px (fixed width even when absent — render `—` in the slot so BR/MS/TASK columns stay aligned across rows)
  - Author avatar — `CachedAvatar size={20}` (20px, codebase's established small-row size)
  - State badge — `shrink-0`, ~64px (`Badge variant="outline"`, matches existing `text-[10px]` treatment)
  - BR / MS / TASK columns — `shrink-0`, ~28px each, `flex items-center justify-center` for the glyph
- Title cell: `flex-1 min-w-0`, `truncate` or `line-clamp-1` — this is the only variable-width cell, and per the italic-truncate lesson in this codebase, add `pr-0.5` if any italic styling is ever applied to title text (not currently planned, but the executor should know why the padding exists if drift-derived styling is added later)
- Status pill / badge components used inside a flex row (not a bare `<td>` or bare `<span>`) — no `statusPillClass` reuse needed here since MR state badges use the existing `Badge variant="outline"` pattern, not the Jira `statusPillClass` pill; if a future variant does reuse `statusPillClass`, it must be wrapped in a flex parent (documented codebase gotcha)

Row ordering (D-03): flagged-first (any of BR/MS/TASK = `⚠`), then clean. Within each partition, sort deterministically — recommend `!iid` descending (most recent MR first) unless the planner finds a stronger signal; this is implementation detail, not a locked contract value.
