## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline cell padding |
| sm | 8px | Compact element spacing, indentation unit |
| md | 16px | Default cell padding (px-4), filter bar horizontal padding |
| lg | 24px | Page header horizontal padding (px-6), table area horizontal padding |
| xl | 32px | — |
| 2xl | 48px | — |
| 3xl | 64px | — |

**Exceptions:**
- Epic row indent: `pl-0` (no indent, full width label)
- Story row indent: `pl-4` (16px left padding inside name cell)
- Subtask row indent: `pl-8` (32px left padding inside name cell)
- Cell height: `py-3` (12px top + 12px bottom) — **deliberate carry-forward from live codebase** (see note below)
- Header cell height: `py-3` — **deliberate carry-forward from live codebase** (see note below)
- Filter bar vertical padding: `py-3` — **deliberate carry-forward from live codebase** (see note below)
- Saved filters row vertical padding: `py-2` (existing, unchanged)
- Sticky corner cell must overlap both axes: `sticky top-0 left-0 z-30`

**py-3 carry-forward rationale:** `py-3` (12px) is used on every `<th>` and `<td>` cell throughout the existing `WorklogsPage.tsx` (lines 572, 576, 580, 588, 592, 596, 618, 624, 629, 637, 639, 643, 651, 653, 657) and on the filter bar row (line 475). Replacing it would alter the established visual density of a shipping component and diverge from adjacent pages. Phase 64 carries this value forward unchanged to preserve the existing table rhythm. **Designer sign-off: pre-existing live codebase pattern confirmed by code inspection on 2026-05-22 — no new 12px values are introduced; all occurrences are directly inherited from the current WorklogsPage.**

## Color

All values use the existing CSS custom property system from `src/index.css`. No new color tokens.

| Role | CSS Token | Usage |
|------|-----------|-------|
| Dominant (60%) | `--background` / `bg-background` | Page background, sticky cell fill, popover background |
| Secondary (30%) | `--muted` / `bg-muted` | Table header row (`thead`), totals footer row (`tfoot`), non-working day columns, skeleton rows |
| Accent (10%) | `--accent` / `bg-accent` | Active date preset pill background, table row hover (`hover:bg-accent/50`), active saved filter pill |
| Destructive | `--destructive` / `text-destructive` | Delete worklog entry icon/button, delete saved filter context menu item, form submit error text |

**Accent reserved for:** active preset pill, row hover state, active saved filter pill. Not for general interactive elements.

**Epic row background:** `bg-muted/40` — visually separates epic header rows from story/subtask rows without using the accent color.

**Holiday columns:** `bg-red-50 dark:bg-red-950/30` — existing pattern from Phase 62, preserved unchanged.

**Non-working day columns:** `bg-muted/80` — existing pattern from Phase 62, preserved unchanged.

**Sticky cell bleed prevention:** All sticky cells (first column, header row, corner) must explicitly declare `bg-background` so scrolled content does not show through.

## Layout Contracts

### Sticky Table (D-15)

```
┌─────────────────────────────────────────────────────────┐
│ sticky top-0 left-0 z-30  │ sticky top-0 z-20           │
│ (corner: Issue column)    │ (date headers, each <th>)   │
├───────────────────────────┼─────────────────────────────┤
│ sticky left-0 z-10        │ scrollable data cells       │
│ (issue name column, each  │                             │
│  <td> in data rows)       │                             │
└───────────────────────────┴─────────────────────────────┘
```

- Table wrapper: `<div class="flex-1 overflow-auto px-6 py-4">` (already exists, unchanged)
- Table: `<table class="w-full text-xs border-collapse">`
- Sticky header `<thead>`: `class="sticky top-0 z-20 bg-background"`
- Corner `<th>` (Issue/Name column): `class="sticky top-0 left-0 z-30 bg-background text-left px-4 py-3 border border-border min-w-48 font-semibold text-muted-foreground"`
- Date `<th>` cells: `class="sticky top-0 z-20 bg-background text-right px-4 py-3 border border-border min-w-14 font-semibold text-muted-foreground"` + day-type class
- Total column `<th>`: `class="sticky top-0 z-20 bg-background text-right px-4 py-3 border border-border min-w-18 font-semibold"`
- First column `<td>` in data rows: `class="sticky left-0 z-10 bg-background px-4 py-3 border border-border"`
- Data cells: `class="text-right px-4 py-3 border border-border"` + day-type class + cursor-pointer on non-zero

### Row Hierarchy Visual Contract

| Level | Indent | Background | Text weight | Click behavior |
|-------|--------|------------|-------------|----------------|
| Epic | `pl-0` (no indent) | `bg-muted/40` on the sticky name `<td>` | `font-semibold` | Clickable → `onIssueClick(epicKey)` (Claude's discretion D-10) |
| Story | `pl-4` on label inside `<td>` | `bg-background` | `font-normal` | Clickable → `onIssueClick(storyKey)` |
| Subtask | `pl-8` on label inside `<td>` | `bg-background` | `font-normal text-muted-foreground` (slightly muted) | Clickable → `onIssueClick(subtaskKey)` |
| "No Epic" synthetic group | `pl-0` | `bg-muted/40` | `font-semibold text-muted-foreground italic` | Not clickable |

**Row hover:** `hover:bg-accent/50` on `<tr>` for all data rows (epic, story, subtask).

**Issue type icon:** Render a small Lucide icon or issuetype badge before the label text in the sticky name cell:
- Epic: `Layers` icon, 12px, `text-purple-500`
- Story: `BookOpen` icon, 12px, `text-blue-500`
- Subtask: `GitBranch` icon, 12px, `text-muted-foreground`

**Clickable row cursor:** `cursor-pointer` on `<tr>` for all issue rows.

### Cell Click Popover (WorklogCellPopover)

- Trigger: click on any non-zero data cell (not the sticky name column, not total column)
- Popover width: `w-72` (288px) matching `LogWorkPopover` convention
- Padding: `p-4`
- Content structure:
  1. Header line: issue key + day label, `text-xs font-semibold`
  2. Scrollable entry list (max-height: `max-h-48 overflow-y-auto`): one `WorklogEntryRow` per worklog entry
  3. Separator: `border-t border-border mt-2 pt-2`
  4. "Add entry" button: `Button` variant `outline` size `sm` full width, icon `Plus` 12px, label "Add entry"
- When "Add entry" clicked: embed `LogWorkPopover` inline (already in open state) OR open nested popover — use the same `LogWorkPopover` component with `issueKey` and `jiraBaseUrl` props, `onSuccess` invalidates tempo query cache

### WorklogEntryRow Layout

```
[time] [author]          [comment truncated]  [✏] [🗑]
```

- `time`: `text-xs font-semibold` (e.g., "2h 30m")
- `author`: `text-xs text-muted-foreground` (display name)
- `comment`: `text-xs text-muted-foreground truncate max-w-[100px]` (omit if empty)
- Edit icon: `Pencil` size-3.5, `text-muted-foreground hover:text-foreground`, click → inline `EditWorklogForm`
- Delete icon: `Trash2` size-3.5, `text-muted-foreground hover:text-destructive`, click → immediate delete (no confirmation dialog — see Copywriting Contract)

### EditWorklogForm (inline in WorklogCellPopover)

Replaces the `WorklogEntryRow` in place when pencil is clicked:
- Duration `Input` (text-xs, h-8), pre-populated with current time
- Date `Input` type=date (text-xs, h-8), pre-populated
- Comment `Textarea` (min-h-[48px] text-xs resize-none), pre-populated
- Row of buttons: `Button` size="sm" "Save Changes" (primary) + `Button` size="sm" variant="ghost" "Discard Changes"
- "Save Changes" disabled while mutation pending; shows "Saving…" label during pending

## Interaction Contracts

### Issue Row Click → Navigation
- Click anywhere on the sticky name `<td>` of a story or subtask row calls `onIssueClick(issueKey)` (prop from `main.tsx`)
- Epic rows: also clickable via `onIssueClick(epicKey)` per Claude's discretion (D-10)
- "No Epic" synthetic group: not clickable, no `cursor-pointer`
- Navigation handled by existing `handleIssueClick` — no new routing logic needed

### Cell Click → Popover
- Only non-zero cells respond to click (zero cells render blank; `cursor-default`)
- Non-zero cells: `cursor-pointer`, `hover:bg-accent/60` (slightly stronger than row hover to indicate interactivity)
- Clicking total column cells: no popover (totals are aggregated; no meaningful drill-down)
- Clicking date header cells: no action

### Delete Worklog Entry
- No confirmation dialog. Immediate `deleteWorklog` mutation on trash icon click.
- Rationale: entries are granular; accidental deletes are recoverable by re-logging. Matches IssueDetailPage pattern.
- On mutation success: invalidate `['tempo', 'worklogs', ...]` cache key (D-14 pattern)

### Loading States
- Initial page load (worklogs query pending): render skeleton table with hierarchy shape — 3 epic rows each containing 2 story rows, each skeleton name cell at varying widths using `Skeleton` component
- Jira enrichment query pending (worklogs loaded, enrichment not yet): render actual time data but replace issue labels with `Skeleton` inline in name column
- Cell popover mutation pending (edit/delete/add): show `Button` disabled + spinner; do not close popover until `onSuccess`

### Keyboard / Accessibility
- All clickable rows: `role="button"` or use `<button>` wrapper inside `<td>` for the name cell only (not full-row `<tr>` — invalid HTML)
- Cell popover triggered by click on `<td>`: wrap cell content in `<button type="button">` with `aria-label="View worklogs for {issueKey} on {date}"`
- Delete icon button: `aria-label="Delete worklog entry"`, `type="button"`
- Edit icon button: `aria-label="Edit worklog entry"`, `type="button"`
