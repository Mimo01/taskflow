<feature>
  <name>rankIssue — LexoRank midpoint calculator</name>
  <files>taskflow/src/services/jira/rank.ts, taskflow/src/services/jira/rank.test.ts</files>
  <behavior>
    Signature: `rankIssue(before: string | null, after: string | null): string`.
    Wire format: `{bucket}|{base36value}:` (e.g. `0|hzzzzz:`). `before === null` = insert at start; `after === null` = insert at end.
    Edge cases (from RESEARCH.md Pattern 2 table — all 9 required):
      E1 before=null, after='0|hzzzzz:' -> result < '0|hzzzzz:'
      E2 before='0|hzzzzz:', after=null -> result > '0|hzzzzz:'
      E3 before=null, after=null -> valid rank string (contains '|' and ':')
      E4 before='0|aaaaaa:', after='0|zzzzzz:' -> strictly between
      E5 before='0|aaaaaa:', after='0|aaaaaab:' -> strictly between (adjacent — digit extension; result !== 'aaaaaa' value)
      E6 before='0|aaaaaa:', after='0|aaaaaa1:' -> strictly between
      E7 before='0|hzzzzz:', after='1|hzzzzz:' -> result uses bucket '0' (before's bucket)
      E8 before='0|000000:', after='0|000001:' -> strictly between
      E9 before='0|zzzzzz:', after=null -> result > '0|zzzzzz:'
  </behavior>
  <implementation>
    Copy the algorithm from RESEARCH.md Pattern 2 / PATTERNS.md "Complete implementation" verbatim — it is fully specified and verified. Module-scope `const ALPHABET = '0123456789abcdefghijklmnopqrstuvwxyz'`. Helpers: `extractValue` (slice between '|' and ':'; null -> ''), `bucket` (prefix before '|'; null -> '0'), `pad` (right-pad with 'z'), `midpoint` (right-pad both with '0' to equal length, parse base-36 to BigInt, `(ia + ib) / 2n`, back to base-36 padStart; if result === before-padded, append `ALPHABET[Math.floor(ALPHABET.length / 2)]` to handle the adjacent-gap case — RESEARCH Pitfall 3). `rankIssue` reconstructs `bucket(before) + '|' + midpoint(beforeVal, afterVal) + ':'` where afterVal falls back to `pad(beforeVal, beforeVal.length + 1)` when `after` is null.
  </implementation>
</feature>
