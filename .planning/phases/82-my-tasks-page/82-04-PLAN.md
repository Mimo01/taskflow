<threat_model>
Read-only personal-task viewer over already-authenticated data. The page composes existing primitives; the only data egress is the clipboard copy of an issue key/link (no user-submitted content reaches Jira). No new auth, no new write endpoints.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → system clipboard | "Copy issue key"/"Copy link" writes an issue key and a baseUrl/browse URL to the clipboard. Both are non-sensitive identifiers the user already sees. |
| reused: LogWorkPopover → Jira | Existing, already-validated write path (createWorklog with parseDuration validation) — not modified by this plan. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-82-06 | Information Disclosure | clipboard copy actions | accept | Only the issue key and the public `${jiraBaseUrl}/browse/${key}` URL are copied — no credentials, no issue body. The user already has this data on screen. |
| T-82-07 | Tampering / Input Validation | LogWorkPopover (reused) | transfer | Worklog duration validation lives in the existing LogWorkPopover (parseDuration) — unchanged here; risk owned by the already-tested component. |
| T-82-08 | Information Disclosure | All-Assigned data render | mitigate | Page renders only what fetchAllAssignedHierarchy returns, which is assignee-scoped to currentUser at the service layer (T-82-04 in plan 03). The page adds no broadening query. |
| T-82-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan (RESEARCH confirms zero new packages). No legitimacy checkpoint required. |
</threat_model>
