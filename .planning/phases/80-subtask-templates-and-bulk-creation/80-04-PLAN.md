<objective>
Build the `BulkCreateSubtasksModal` (SUBTPL-04..08) and wire its entry point into `IssueDetailContent`. The modal lets a user apply a saved template or build an ad-hoc list against the active project's subtask createmeta, preview and inline-edit the resolved rows (with placeholder chips), reorder them, then create all subtasks sequentially with per-row status and partial-failure retry. On any success it invalidates the three cache keys so the parent's subtask list and the board refresh.

Purpose: This is the second half of the phase user story — applying templates from a parent issue. It is the riskiest plan (sequential creation, retry-no-duplicate, placeholder resolution at create time) and is covered by the Wave-1 `BulkCreateSubtasksModal.test.ts` contract.
Output: `BulkCreateSubtasksModal.tsx` (exporting an extracted `createAllRows` loop for the test), the completed modal test, and the IssueDetailContent button + modal mount.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| template/row values → createIssue (Jira DC, authenticated) | user-authored row data crosses into authenticated create API calls |
| parent issue fields → @inherit resolution | parent issue field values flow into child subtask payloads at create time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-80-07 | Injection | createAllRows payload assembly | mitigate | Resolved values passed as discrete typed fields (assignee.name, labels[], etc.) and custom fields through wrapCustomFieldValue; never string-interpolated; Jira DC server-validates |
| T-80-08 | Tampering | retry-no-duplicate guard | mitigate | `if (status === 'created') continue` at loop top is the sole dedup mechanism — unit-tested to guarantee no duplicate createIssue on retry (SUBTPL-07) |
| T-80-09 | Repudiation | unassigned clearing on DC | mitigate | @unassigned omits the assignee key entirely (never null) per DC behavior (Pitfall 7) |
| T-80-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed this phase |
</threat_model>
