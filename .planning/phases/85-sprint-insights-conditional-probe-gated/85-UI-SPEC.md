## Chart Visual Specifications

### VelocityChart (INSIGHT-01)

**Chart type:** Grouped `BarChart` with two `Bar` series per sprint.
- Series A — "Committed" (final-assigned SP): `var(--chart-1)`, 40% opacity fill, rendered behind Series B.
- Series B — "Completed" (done SP): `var(--chart-2)`, solid fill, rendered in front.
- Both bars share the same `XAxis` category (sprint name); side-by-side grouping (default Recharts `BarChart` behavior, not stacked).

**Axes:**
- X-axis: sprint short name (e.g. `Sprint 42`); `dataKey="sprintName"`; `XAxis` tick fontSize 11.
- Y-axis: story points (integer); `tickFormatter={(v) => String(v)}`; no unit suffix (SP is implied by chart title).
- No Y-axis domain clamping — let Recharts auto-scale from data.

**Reference line:** none.

**Legend:** inline `Legend` component below chart, small font (11px), labels "Committed" and "Completed".

**Height:** 240px (explicit `style={{ height: 240 }}` inner div; outer `ChartWrapper` height prop = 240).

**`isAnimationActive={false}`** on all `Bar` elements (Phase 81 D-06 mandatory).

**`responsive` prop** on `BarChart` (never `ResponsiveContainer`).

**ChartWrapper props:**
- `title="Personal Velocity"`
- `description="Committed vs completed story points · last 6 closed sprints"`
- `height={240}`
- `isLoading={showSkeleton}` via `useDelayedLoading`
- `error={error}`
- `isEmpty={false}` — the `<3 sprints` case is NOT isEmpty; it renders a custom inline message inside the chart area (see Copywriting)
- `onRetry={refetch}`

**`<3 sprints` hidden-with-message state:** when `qualifyingSprints.length < 3`, render the `VelocityChart` outer section entirely (the `div[role="region"]` wrapper and the card shell), but swap the chart area for a centered `EmptyState` with the `<3 sprints` message. Do NOT use `ChartWrapper`'s generic `isEmpty` prop for this case — use a conditional render inside the component so the custom copy appears. Pass `isEmpty={false}` to `ChartWrapper` always; the message renders as `children` of `ChartWrapper`.

**Probe-failure (runtime) omission:** if the velocity query errors and returns no recoverable data, the entire `VelocityChart` section renders its `ChartWrapper` error state with retry — never blanks the Dashboard.

### BurndownChart (INSIGHT-02)

**Chart type:** `AreaChart` (area + line) showing hours remaining over the sprint timeline.
- Series A — "Remaining" (actual hours remaining from `.changes` timeline): `var(--chart-3)` fill at 20% opacity, stroke solid.
- Guideline — ideal burndown from `.workRateData`: `var(--muted-foreground)` dashed `ReferenceLine`-style, rendered as a separate `Line` with `strokeDasharray="4 4"` and no area fill.

**Axes:**
- X-axis: date labels derived from `.changes` entry timestamps; formatted as `MMM D` (e.g. `Jun 3`); `XAxis` tick fontSize 11; show a reasonable subset of ticks (e.g. every 3rd day) to avoid crowding.
- Y-axis: hours remaining; `tickFormatter={(v) => \`${v}h\`}`; domain `[0, 'auto']`.

**Tooltip:** show date + remaining hours formatted as h+m (reuse the `formatHoursMinutes` helper from `WeeklyTrendChart.tsx`).

**Height:** 240px (same pattern).

**`isAnimationActive={false}`** on all `Line` and `Area` elements.

**`responsive` prop** on `AreaChart`.

**ChartWrapper props:**
- `title="Sprint Burndown"`
- `description="Hours remaining · active sprint · time estimate"`
- `height={240}`
- `isLoading={showSkeleton}`
- `error={error}`
- `isEmpty={!hasBurndownData}` — where `hasBurndownData` = `.changes` has at least one entry
- `onRetry={refetch}`

**Probe-failure (runtime) omission:** if the burndown query errors, `ChartWrapper` surfaces its error state with retry. The section renders independently; other Dashboard sections are unaffected (D-09 / criterion 4).

```
// "Committed" here = my final-assigned sprint scope (sum of SP for all issues assigned to me

// trend — probe confirmed 2026-06-15.
```

Mandatory probe-outcome comment (D-10) in each chart component:
- VelocityChart: `// Probe A+B PASSED 2026-06-15: closed-sprint endpoint returns sprint objects with startDate/endDate; SP field customfield_10106 confirmed on closed-sprint issues. Build is unconditional; <3-guard and error state handle runtime absence.`

## Accessibility

- Both chart sections use `role="region"` wrapper with `aria-label` (matching `WeeklyTrendChart.tsx` pattern).
  - VelocityChart: `aria-label="Personal velocity chart"`
  - BurndownChart: `aria-label="Sprint burndown chart"`
- `ChartContainer` receives an `aria-label` on the inner element:
  - `aria-label="Personal velocity bar chart — committed vs completed story points per sprint"`
  - `aria-label="Sprint burndown area chart — hours remaining over sprint timeline"`
- `<3 sprints` message: rendered as plain text inside the chart area; no special ARIA role needed beyond the parent `role="region"`.
- No interactive affordances beyond the `ChartWrapper` retry button (handled by existing `ErrorState` component — already accessible).
