<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| aio/client.ts → AIO REST API (via apiFetch) | Bearer PAT travels over HTTPS to the Jira/AIO host; PAT comes from Stronghold via caller, never stored in the service module |
| AIO API response → application types | JSON from AIO REST endpoint is parsed into AioProject[] / AioIssueRun[]; malformed response data should not propagate raw strings into any URL or DOM (Phase 54 concern, but service layer must return typed data) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51A-01 | Information Disclosure | Bearer PAT in Authorization header | mitigate | PAT retrieved via readSecret('jira-pat') by the caller and passed as a parameter — never stored in Zustand or logs. apiFetch already handles dev-tools logging and strips auth headers from the log output (verified in lib/apiFetch.ts). D-09 and ASVS V2 satisfied. |
| T-51A-02 | Tampering | AIO_API_PATH constructed from user-supplied jiraBaseUrl | mitigate | jiraBaseUrl comes from auth.store (set during Jira connection setup, which already validates the URL). No new URL inputs are accepted. The AIO_API_PATH suffix is a hard-coded constant, not interpolated from user input. ASVS V5: no raw string interpolation from AIO response data into URLs. |
| T-51A-03 | Elevation of Privilege | issueKey appended to testrun URL without encoding | mitigate | `encodeURIComponent(issueKey)` is required in issue-runs.ts per acceptance criteria. Prevents query-string injection if issueKey contains unexpected characters. Acceptance criteria explicitly verify this. |
| T-51A-04 | Spoofing | AIO response returns 200 with malformed JSON causing unhandled exception | accept | response.json() is called directly; if the AIO API returns malformed JSON it will throw naturally — the error propagates to the caller. Phase 52+ query hooks will catch this in the React Query error boundary. No special handling needed at the service layer for Phase 51. |
| T-51A-05 | Information Disclosure | client.ts exported from index.ts barrel (anti-pattern) | mitigate | Acceptance criteria explicitly verify `grep -c "from './client'" taskflow/src/services/aio/index.ts` returns 0. PATTERNS.md Pitfall 4 documents the failure mode. |
</threat_model>
