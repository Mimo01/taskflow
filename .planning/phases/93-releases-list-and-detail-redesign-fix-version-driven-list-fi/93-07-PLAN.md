**buildAgenda(versions, today):** (no breakdowns parameter, per D-09)
1. Split the versions into released (take `groupReleases(versions).released`, which is date descending), undated unreleased (source order) and dated unreleased.
2. Sort the dated unreleased versions by releaseDate ascending, breaking ties by source index (a stable sort).
3. next = the first dated version with releaseDate >= today; near = the second.
4. Walk the dated list:
   - Emit every version with date < today as kind overdue.
   - Before the first version with date >= today, emit `{ type: 'today', date: today }` once and set lastMonth = today's month key (YYYY-MM).
   - For each later version, emit `{ type: 'month', label }` when its month key differs from lastMonth, then emit the release entry.
5. If TODAY was never emitted, emit it after the loop.
6. Kinds: overdue / next / near / planned. Set `quiet = (kind === 'planned')` and `pill = kind !== 'planned'`.
   - **Quiet rule, stated explicitly (D-09):** quiet depends only on data available before the breakdown loads. The F5 sketch also promoted a planned release with started work to a full row (`isQuiet = ... !(r.d + r.p > 0)` in index.html), but in the app that would make a row grow from quiet to full when its batch resolves, which is a layout shift. A started far-planned release therefore stays quiet weight; its issues column still shows the bar and 'done/total' because every row shares the same column system (F5 round 19), so the started work stays visible.
7. Append `{ type: 'section', label: 'No date', count }` and then the undated entries (kind undated, pill true, countdown 'No date') when there are any.

**releaseSummary:** counts as described in the behavior block.

The module must have no module-level mutable state and must never call `new Date()` without an argument. `today` always comes from the caller (this matters for the React Compiler; see memory "React Compiler vs module reads").
