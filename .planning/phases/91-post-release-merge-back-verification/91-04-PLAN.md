<objective>
Close VERIFICATION gap 2 (CR-02) and warning WR-06 at the service layer.

`compareRefs` currently coerces a non-array `diffs`/`commits` to `diffCount: 0` /
`commitCount: 0`. Resolver step 9 reads `diffCount === 0` as the strongest
positive claim, so any 200 with an unexpected body (proxy/SSO interstitial, API
version change, `{message: ...}`) is read as evidence the release merged —
directly contradicting the module's own documented D-04 invariant ("an
incomplete diff must never be read as no diff"). It must fail closed so the
query errors, `compareCheckFailed` becomes true, and the resolver reaches
`couldnt-verify`.

`fetchSourceBranchMRs`'s `while (true)` loop also has no page ceiling, unlike
`searchProjectTags` (`maxPages = 20`) and `fetchAllProjectMRs`
(`MR_MAX_PAGES = 500`) in the same file.

Purpose: the compare channel is one of MERGE-02's two evidence channels; a
false "no diff" inverts the feature's core promise.
Output: hardened `compareRefs` + bounded `fetchSourceBranchMRs`, with tests that
fail against today's code.
</objective>
