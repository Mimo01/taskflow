**Types**

`export type TrackingMR = Pick<GitLabMR, 'iid' | 'state' | 'web_url'> & { merged_at?: string | null }`
— a structural narrowing so this module never depends on fields the verdict does not read.

`export interface MergeBackCompareInput { diffCount: number; commitCount: number; timedOut: boolean }`
— structurally compatible with `services/gitlab.ts`'s `GitLabCompareResult` by design, declared
locally so this module stays service-free. Comment that fact.

`export type MergeBackVerdict` — a five-kind discriminated union:
  - `{ kind: 'hidden' }`
  - `{ kind: 'loading' }`
  - `{ kind: 'couldnt-verify'; reason: 'no-mr-no-tag' | 'check-failed'; expectedTagName: string | null }`
  - `{ kind: 'merged'; via: 'tracking-mr'; defaultBranch: string; mrIid: number; mrUrl: string; mergedAt: string | null }`
  - `{ kind: 'merged'; via: 'content-compare'; defaultBranch: string; tagName: string }`
  - `{ kind: 'likely-not-merged'; defaultBranch: string; tagName: string; commitsNotInDefault: number }`

Record these two planner calls as comments on the union itself:
  - **P-01 (closes 91-RESEARCH Open Question 2):** the `loading` kind is ADDITIVE to D-09's four
    outcomes, not a deviation — D-09 enumerates the terminal/visible outcomes, `hidden` covers
    "cannot be attempted", and 91-UI-SPEC §Interaction Contract explicitly requires a loading
    treatment matching `branchState.kind === 'loading'`. `BranchState` carries its own `loading`
    kind for the same reason.
  - **P-02 (closes 91-RESEARCH Open Question 1):** the `merged` kind carries a `via` discriminant
    because D-10 only specifies the MR-sourced tooltip. Content-compare-derived `merged` keeps the
    same icon, colour, and main-line shape but has no MR and no merge date, so it gets its own
    tooltip wording (authored in Plan 03) rather than an invented MR reference or a tag-creation
    date masquerading as a merge date.

**`export function resolveMergeBackVerdict(params: { … }): MergeBackVerdict`**

Parameters, all plain data (never live query objects), mirroring `resolveBranchState`'s named-param
style: `releasedVersion: boolean`, `hasMatchedMilestone: boolean`, `defaultBranch: string | null`,
`trackingMRs: readonly TrackingMR[] | undefined`, `trackingMRsCheckFailed: boolean`,
`tagName: string | null`, `expectedTagName: string | null`,
`compareResult: MergeBackCompareInput | undefined`, `compareCheckFailed: boolean`.

Evaluate in EXACTLY this precedence order, with a comment above each step naming the decision it
implements. The order is load-bearing; do not reorder it:

  1. `!releasedVersion || !hasMatchedMilestone` → `{ kind: 'hidden' }` (D-11 — no dead `—` row).
  2. `defaultBranch === null` → `{ kind: 'loading' }` (planner call P-05: every visible verdict's
     copy names the fetched default branch per D-10, so rendering before the project query resolves
     would print an empty branch name; this is honestly "still loading", not a verdict).
  3. `trackingMRs === undefined && !trackingMRsCheckFailed` → `{ kind: 'loading' }`.
  4. `trackingMRs?.find((mr) => mr.state === 'merged')` → `{ kind: 'merged', via: 'tracking-mr', … }`
     carrying `mrIid`, `mrUrl` from `web_url`, and `mergedAt: mr.merged_at ?? null`
     (D-02 — `merged` is the ONLY positive MR signal; every other state defers to content).
  5. `tagName === null` → `{ kind: 'couldnt-verify', reason: trackingMRsCheckFailed ? 'check-failed' : 'no-mr-no-tag', expectedTagName }`
     (D-01 — tag absence is NEVER evidence a release did not ship; Phase 88 established tags are an
     incomplete record).
  6. `compareResult === undefined && !compareCheckFailed` → `{ kind: 'loading' }`.
  7. `compareCheckFailed` → `{ kind: 'couldnt-verify', reason: 'check-failed', expectedTagName }`.
  8. `compareResult.timedOut` → `{ kind: 'couldnt-verify', reason: 'check-failed', expectedTagName }`
     (D-04 — GitLab documents `diffs` as possibly INCOMPLETE under timeout, and an incomplete diff
     must never be read as "no diff").
  9. `compareResult.diffCount === 0` → `{ kind: 'merged', via: 'content-compare', defaultBranch, tagName }`
     (D-04 — diff-based, NOT commit-count-based, and never `compare_same_ref`; correct under all
     three merge methods even though D-03 confirms merge commits today).
 10. `trackingMRsCheckFailed` → `{ kind: 'couldnt-verify', reason: 'check-failed', expectedTagName }`
     (planner call P-04: a non-empty diff plus an unknown MR channel is not enough to put "Likely
     not merged" on a release — one channel failed, so the app admits the gap per D-09's principle).
 11. otherwise → `{ kind: 'likely-not-merged', defaultBranch, tagName, commitsNotInDefault: compareResult.commitCount }`.

Do not read a `merged` field off any branch object anywhere in this module (GitLab #36963), and do
not accept or reference `compare_same_ref`.

**Date formatters** — both exported, both pure, both deterministic:

`export function formatVerdictDate(iso: string | null | undefined): string | null` → `'21 Jul'`
(day-of-month without zero padding, space, three-letter English month) and
`export function formatEvidenceDate(iso: string | null | undefined): string | null` → `'21.07.2026'`
(zero-padded `DD.MM.YYYY`).

Both must build the string from `Date.prototype.getUTCDate/getUTCMonth/getUTCFullYear` against a
module-level `const MONTHS_SHORT` array — NEVER `toLocaleDateString`, which is locale-dependent and
unstable across machines (see `src/lib/standup-date.ts` L7). Both return `null` for `null`,
`undefined`, `''`, or a value where `Number.isNaN(date.getTime())`.

Do not add `useMemo`/`useCallback`/`React.memo` anywhere — React Compiler is on, and this module is
not React code at all.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-91-06 | Information Disclosure | `MergeBackVerdict` payload fields | mitigate | The union carries only `defaultBranch`, `tagName`, `mrIid`, `mrUrl`, `mergedAt`, and integer counts — never an `Error`, an error body, a response object, or a URL containing credentials. Enforced by the closed union type; Plan 03's row renders only these fields |
| T-91-07 | Spoofing | tracking-MR state as an authority signal | mitigate | Only `state === 'merged'` is accepted as positive evidence (D-02). | T-91-08 | Tampering | verdict correctness under partial failure | mitigate | Any errored channel, any compare timeout, and any missing default branch resolve to `loading` or `couldnt-verify` — never to `merged` and never to an accusatory `likely-not-merged` (precedence steps 2, 5, 7, 8, 10). Proven by dedicated unit cases |
| T-91-09 | Elevation of Privilege | — | accept | No auth, no permission, no write, and no persistence exist in this module; it is a pure function over plain data (D-15). No realistic privilege surface |
| T-91-SC | Tampering | npm/pip/cargo installs | accept | Zero package installs in this phase (91-RESEARCH §Package Legitimacy Audit: not applicable) |
