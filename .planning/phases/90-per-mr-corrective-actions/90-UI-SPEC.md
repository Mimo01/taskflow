# Phase 90 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds no new pages, dialogs, or components — it makes two existing 28px table cells (`DriftMarkCell` at `MrDriftSection.tsx:54`, BR and MS columns only) conditionally interactive. Every visual decision below was locked during `/gsd-discuss-phase` (90-CONTEXT.md D-01…D-16) and is treated here as a design contract, not a re-litigated question.

---

## Design System

| Property | Value |
|----------|-------|

No new shadcn components are needed. This phase reuses existing primitives only: `Badge` (`@/components/ui/badge`), lucide icons, and native `<button>`. No registry pulls required.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-tooltip affordance, gap-1.5 badge spacing |
| sm | 8px | `gap-2` between row cells |
| md | 16px | (not used within this phase's scope) |
| lg | 24px | (not used within this phase's scope) |
| xl | 32px | (not used within this phase's scope) |

Exceptions:
- **28px fixed cell width** (`w-[28px]`, existing, non-negotiable) — `DriftMarkCell` is explicitly px-sized per P89 D-20 (narrow flex columns collapse to 0 in this app's WebKit/Tauri webview). This phase must not change the cell's width, only what renders inside it and its click/focus behavior.
- **44px touch/tab target** is NOT introduced — the cell stays 28px square per D-01 ("no trailing button column, no permanent extra row width"). This is a deliberate exception to typical 44px touch-target guidance, justified by desktop-mouse-first usage and the row-hover-reveal pattern already established.

## Color

This phase adds no new color tokens. It reuses the app's existing semantic palette and Tailwind color utilities already present in `MrDriftSection.tsx`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | existing app background (`--background`) | Page/card surfaces — unchanged |
| Secondary (30%) | existing card/border surfaces (`--border`, `--muted`) | Row dividers, badges — unchanged |
| Accent (10%) | `text-orange-600 dark:text-orange-400` (existing flag color) | Reserved for: the `⚠` flagged-but-not-hovered state, and the D-14 inert missing-branch BR cell (stays orange, never turns red) |
| Interactive hover swap | inherit `text-foreground` / icon default | `GitBranch` / `Milestone` lucide icons on row-hover reveal — no new accent color, just icon shape change |
| Success | `text-green-600 dark:text-green-400` (existing `Check` color) | `✓` on settle (D-06) — reused unchanged |
| Failure (new usage of existing destructive token) | `text-red-600 dark:text-red-400` (parallel to existing `--destructive` semantic, applied at Tailwind utility level to match the file's existing `text-orange-600`/`text-green-600` pattern rather than introducing the CSS-variable-based `--destructive` into this file) | `⚠` in red on write failure (D-07) — reserved exclusively for the two BR/MS cells when their mutation has failed; never used elsewhere in this row |
| Pending | inherit `text-muted-foreground` (spinner default) | `Loader2` spin icon (D-06) while a mutation is in flight |

Accent reserved for: the orange flagged-warning glyph (unchanged from Phase 89) and the red failure variant introduced by this phase — both scoped strictly to the BR/MS `DriftMarkCell` glyph, never to row background, badges, or any other row element (background/ring emphasis on cell-hover per D-02 uses a neutral `bg-accent`/`ring` utility, not a semantic color).

Destructive: not applicable — this phase has no destructive actions (retarget/assign are direct writes but reversible in GitLab, and per D-16 carry no warning UI regardless).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (BR cell action) | Icon-only button; tooltip: `Retarget to release/<branch-name>` (e.g. `Retarget to release/33.7.0`) — exact branch name interpolated from `releaseBranchName` |
| Primary CTA (MS cell action) | Icon-only button; tooltip: `Assign milestone <milestone-title>` (e.g. `Assign milestone 33.7.0`) — exact title interpolated from `matchedMilestone.title` |
| Empty state | Unchanged from Phase 89 — `No merge requests found` / `No MRs were discovered via Jira linkage, milestone, or branch target for this release.` — this phase does not touch the empty state |
| Error state (in-cell tooltip, D-07/D-10) | The flattened GitLab error message only — e.g. `Target branch can't be blank`, not `[object Object]`. No generic "Something went wrong" fallback; if the error body cannot be flattened, fall back to `<status code> — retry`. Clicking the red cell retries. |
| Unavailable state (D-14, MRFIX-04) | BR cell tooltip when release branch doesn't exist: `Release branch doesn't exist yet — create it above to enable retargeting` (or equivalent copy pointing at the existing P88 create-branch control on the page). Cell stays inert (`⚠` orange, no hover icon swap, no click handler). |
| Destructive confirmation | Not applicable — no confirm dialogs in this phase (D-16, hard user decision: no warning on retarget regardless of approval-reset side effects) |

**Accessible naming (checker recommendation, D2):** every icon-only button in this phase carries an `aria-label` mirroring its `title` text verbatim (e.g. `aria-label={`Retarget to release/${releaseBranchName}`}`). `title` alone is not a reliable accessible-name mechanism for icon-only controls — set both.

Tone: terse, technical, consistent with the existing tooltip style already in the file (e.g. `channelsTitle` → `Found via: Jira link, GitLab milestone`). No exclamation points, no marketing voice.

## Interaction Contract

(Non-standard section — this phase is interaction-heavy with minimal new visual surface, so the contract is captured explicitly here rather than only in prose.)

| State | Trigger | Visual | Source |
|-------|---------|--------|--------|
| Rest (flagged) | default | `⚠` orange, `size-3.5` | existing (P89) |
| Rest (ok) | default | `✓` green, inert, no hover swap | existing (P89), D-05 |
| Rest (na) | default | `—` muted, inert, no hover swap | existing (P89), D-05 |
| Row-hover reveal | pointer anywhere on row | every actionable (flagged) cell on the row swaps `⚠` → its action icon (`GitBranch` for BR, `Milestone` for MS) | D-02 |
| Cell-hover emphasis | pointer over the specific 28px cell | that cell additionally gets a background/ring treatment (neutral `bg-accent`/`ring-1`, not a semantic color) | D-02 |
| Focus-visible | Tab to the cell button | same reveal as row-hover; `:focus-visible` shares the selector | D-04 |
| Pending | click fires mutation | `Loader2` spinner, `animate-spin`, replaces the icon; cell is locked (ignores further clicks) | D-06, D-09 |
| Success | mutation settles 2xx | `✓` green in place; row does NOT re-sort (D-11); header `MR Drift` badge count decrements immediately (D-12) | D-06, D-11, D-12 |
| Failure | mutation settles non-2xx | `⚠` in **red** (not orange); tooltip carries the flattened GitLab error message; sticky until retried (component state, not query cache); clicking again retries | D-07, D-08, D-10 |
| Unavailable (BR only, no release branch) | `releaseBranchName` doesn't exist | `⚠` stays orange, inert — no hover icon swap, no click handler, tooltip explains blocker | D-14, MRFIX-04 |
| Degraded (no matched milestone) | `hasMatchedMilestone === false` | BR and MS both render `—`, inert — unchanged from P89 D-18, no new action added | D-15 |
| TASK column | always | never actionable — no glyph swap, no click handler, unaffected by this phase | P89 D-11, D-05 |

Concurrency: BR and MS cells lock independently (per-cell, not per-row) — one can be pending while the other is fired concurrently (D-09).
