## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, issue-key inner padding, cursor-target gaps |
| sm | 8px | Subtask row vertical padding (py-2 = 8px), button icon gap |
| md | 16px | Peek panel inner horizontal padding, section spacing |
| lg | 24px | Peek header bar vertical area, section separator |
| xl | 32px | Stacked-layout block gaps inside the peek |
| 2xl | 48px | Not used in peek |
| 3xl | 64px | Not used in peek |

Exceptions:
- Drag resize handle: 4px wide hit area, 16px grip indicator height (token: md)
- Peek panel default width: 480px; min: 360px; max: 720px (persisted, source: CONTEXT.md D-03)
- Issue key touch/click target in cards: minimum 32px height (cards are already taller; key text is inline so no special padding needed beyond existing card padding)

## Typography

Reuses the typographic idioms already established in IssueDetailContent.tsx and TaskCard.tsx. No new type ramp is introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / subtask row text | 14px (text-sm) | 400 (regular) | 1.5 |
| Label / section heading | 14px (text-sm) | 400 (regular) | 1.5 |
| Issue title (in peek) | 20px (text-xl) | 600 (semibold) | 1.3 (leading-snug) |
| Issue key / monospace meta | 12px (text-xs, font-mono) | 400 (regular) | 1.5 |

Notes:
- Body and label rows share 14px/400; visual distinction between body text and section headings comes from size context and color (e.g. `text-muted-foreground` for labels), not weight.
- The two-column full-page layout uses text-xl for the title at weight 600 — identical in peek (source: IssueDetailContent.tsx:222 `text-xl font-semibold leading-snug`)
- Peek header bar issue key label: text-xs font-mono (consistent with existing rendering)
- Parent breadcrumb above title: text-xs font-mono for the key + text-sm for the summary text (matches the FieldsSection parent rendering pattern)

## Color

All colors use the shadcn CSS variable system (OKLCH). Values below are the semantic token names; exact hex depends on light/dark mode.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (oklch(1 0 0) light / oklch(0.145 0 0) dark) | Peek panel body surface, app background behind squeeze |
| Secondary (30%) | `--card` / `--sidebar` (oklch(1 0 0) light / oklch(0.205 0 0) dark) | Peek panel itself uses `--card` as its background to visually distinguish it from the live underlying content |
| Accent (10%) | `--accent` (oklch(0.97 0 0) light / oklch(0.269 0 0) dark) | Hover state on subtask rows, issue key hover highlight in underlying lists |
| Destructive | `--destructive` (oklch(0.577 0.245 27.325) light) | Not used in this phase — no destructive actions |

Accent reserved for:
- Hover background on subtask/epic-story rows inside the peek (`hover:bg-accent`)
- Hover background on linked-issue rows inside the peek (`hover:bg-accent`)
- Issue key hover highlight in card/row bodies when cursor enters the key element

Peek panel left border: `border-l border-border` — uses `--border` token, matching existing `border-l` idioms (Phase 76 priority stripe, subtask markers). No dimming/backdrop applied to underlying content — underlying content stays at full `--background` brightness (source: CONTEXT.md D-04).

Priority stripe on TaskCard: unchanged — `border-l-4` + `priorityStripeClass()` color (existing behavior, not modified by this phase).

## Interaction Contract

This section is specific to Phase 77 and captures the interaction rules that go beyond standard design tokens.

### Peek Panel — Layout & Anatomy

```
┌─────────────────────────────────┬──────────────────────────────────┐
│  Underlying view (live)         │ ▐ Peek panel (480px default)     │
│  — board / backlog / standup    │ ┌──────────────────────────────┐  │
│  — fully interactive            │ │ [PROJ-123]  [Open full page] X│ │
│  — no dimming                   │ ├──────────────────────────────┤  │
│                                 │ │ ↗ PARENT-KEY Parent summary  │  │
│                                 │ │ Issue Title                  │  │
│                                 │ │                              │  │
│                                 │ │ [Status] [Assignee] [Prio]   │  │
│                                 │ │ — sidebar fields stacked —   │  │
│                                 │ │                              │  │
│                                 │ │ Description                  │  │
│                                 │ │ Comments / Subtasks          │  │
│                                 │ └──────────────────────────────┘  │
└─────────────────────────────────┴──────────────────────────────────┘
                                  ↑ drag divider (4px hit, cursor-col-resize)
```

### Peek Panel — Structural Rules

| Rule | Contract |
|------|----------|
| Mounting | App/layout level, wrapping routed outlet (not per-route). Source: CONTEXT.md D-02 |
| Default width | 480px |
| Min / max width | 360px / 720px |
| Width persistence | settings store, versioned migrate() chain — follow Phase 76 v25 pattern |
| Left border | `border-l border-border` — 1px, no shadow beyond existing card shadow idioms |
| Underlying brightness | 100% — no overlay, no dimming, no backdrop |
| Single-column layout inside peek | Status / assignee / priority and sidebar fields stacked first, then description, then comments/subtasks. Source: CONTEXT.md D-06 |
| Drag divider cursor | `cursor-col-resize` on the resize handle element |
| Skeleton | Reuse existing `IssueDetailSkeleton` (IssueDetailSheet.tsx:157) |

### Peek Header Bar

| Element | Contract |
|---------|----------|
| Left | Issue key (text-xs font-mono) |
| Right — primary action | "Open full page" button: icon (`ExternalLink`, 14px) + text label "Open full page". On click: navigate to `/issue/:key` (different route → naturally closes peek per D-07). Size: Button variant="ghost" size="sm" |
| Right — close | X icon button (`X`, 16px). Aria-label: "Close preview". Button variant="ghost" size="icon". On click: dismisses peek |
| Height | 40px (h-10), px-4, border-b border-border |
| Keyboard | Escape key dismisses peek from anywhere in the app while peek is open |

### Issue Key vs. Body Click Split (all surfaces)

| Element | Cursor | On click |
|---------|--------|----------|
| Issue key (PROJ-123 text) | `cursor-pointer`, `hover:underline` | `stopPropagation()` → navigate to `/issue/:key` (full page) |
| Card / row body (everything else) | `cursor-pointer` (existing) | Opens peek (calls new peek-open handler instead of navigate) |

This split applies uniformly to: TaskCard, BacklogRow, DashboardInProgressCard, Standup notes, CommandPalette results, NotificationPopover items.

### In-Peek Link Behavior (D-13)

| Context | Parent link click | Subtask row click | Linked-issue click |
|---------|-------------------|-------------------|--------------------|
| Inside peek | Swaps peek to that issue key (no navigation) | Swaps peek | Swaps peek |
| Full-page `/issue/:key` | Navigates full-page (existing behavior) | Navigates full-page | Navigates full-page |

Seam: `onOpenIssue` prop — wired to swap-peek when rendered inside the peek, navigate otherwise.

### Peek Close Conditions

| Trigger | Result |
|---------|--------|
| Escape key | Dismiss peek |
| X button in header | Dismiss peek |
| "Open full page" click | Navigate → different route → peek naturally closes |
| Click a sidebar nav item (route change) | Peek closes (D-07) |
| Click empty space in underlying view | No effect on peek (D-08) |
| Click another issue in underlying view | Swaps peeked issue, peek stays open (PEEK-04) |
| Click-away on open background | No dismissal — underlying view is live (D-08) |

### DETAIL-01 — Parent Breadcrumb Relocation

| Property | Contract |
|----------|----------|
| Location | Above the issue title in `IssueDetailContent`, NOT in sidebar `FieldsSection` |
| Visual form | `↗ PARENT-KEY Parent summary` — upward-right arrow icon (lucide `ArrowUpRight`, 12px), then key in `text-xs font-mono text-muted-foreground`, then em-dash separator, then summary in `text-sm text-muted-foreground` |
| Cursor | `cursor-pointer`, `hover:underline` on the entire row |
| Spacing | `mb-1` between breadcrumb and title (`text-xl` heading) |
| Removal | Delete the parent MetaRow from `FieldsSection.tsx` (~line 641) |

### DETAIL-02 — Pointer Cursor Sweep

Every clickable area in `IssueDetailContent`, `IssueDetailSidebar`, `FieldsSection`, `LinkedIssuesSection`, and the subtask list must have `cursor-pointer`. Specific targets confirmed missing today:

| Component / area | Fix |
|------------------|-----|
| Subtask rows in IssueDetailContent | Add `cursor-pointer` |
| Parent breadcrumb (new, above title) | Include `cursor-pointer` from creation |
| Linked-issue rows in LinkedIssuesSection | Add `cursor-pointer` |
| Field chips (assignee, priority, status in sidebar) | Add `cursor-pointer` where actionable |
| New parent link in FieldsSection (existing sidebar) — REMOVED | N/A (link relocated) |
