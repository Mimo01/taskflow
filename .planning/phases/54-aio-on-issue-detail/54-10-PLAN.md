Alternative: keep `collectAioImageAttachments` as-is for runs, dedup at the useMemo as `[...descriptionImages, ...runImages]` then dedup. The latter is less invasive.

- **Lines 342-346: `AioTestRunsSection({ issueKey, jiraBaseUrl, jiraIssueId })`.** Destructure `description` from props alongside the existing three fields.

- **Lines 579-596: `aioAttachments` useMemo.** Currently calls `collectAioImageAttachments([...data.runs, ...impactedAsRunData])`. Change to merge in description-derived attachments AND apply dedup-by-URL across the merged list:
  ```typescript
  const aioAttachments = useMemo(() => {
    const descriptionImages = extractInlineImageAttachments(description);
    const data = stepsQuery.data;
    if (!data) {
      // Even without test-run data, description images should populate the grid.
      return descriptionImages;
    }
    const impactedAsRunData: AioIssueRunData[] = data.impactedExecutions.map((ie) => ({
      run: { id: ie.runRef.runId, status: ie.status, testCaseKey: ie.testCase.key, cycleKey: ie.runRef.cycleKey },
      testCase: ie.testCase,
      steps: ie.steps,
    }));
    const runImages = collectAioImageAttachments([...data.runs, ...impactedAsRunData]);
    // Dedup across description + runs by URL.
    const merged = [...descriptionImages, ...runImages];
    const seen = new Set<string>();
    return merged.filter((a) => (seen.has(a.url) ? false : (seen.add(a.url), true)));
  }, [stepsQuery.data, description]);
  ```

- **Line 622: `if (data === null) return null;`** Sentinel for no-linked-test-cases. Description images should NOT render the AIO section in this case (no AIO data at all → section hidden). Keep the early-return. If the user explicitly wants description images surfaced even when there are no linked test cases, that's a separate scope expansion — out of scope here.
