## Spacing Scale

Declared values (must be multiples of 4). All values inherit from existing page patterns (EpicsPage.tsx confirmed usage).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding within badges |
| sm | 8px | Compact element spacing, badge padding |
| md | 16px | Default element spacing, page content horizontal inset |
| lg | 24px | Section padding, page header horizontal padding (`px-6`) |
| xl | 32px | Layout gaps between major content blocks |
| 2xl | 48px | Major section breaks (not used in this phase) |
| 3xl | 64px | Page-level spacing (not used in this phase) |

Exceptions:
- Page header vertical: `py-4` (16px) — matches EpicsPage.tsx pattern
- Skeleton padding: `p-4` (16px) around rows — matches EpicsSkeleton.tsx pattern
- Skeleton row height: `h-10` (40px) — matches EpicsSkeleton.tsx pattern
- Nav link vertical: `py-2` with `density-compact:py-1` and `density-comfortable:py-3` — matches Sidebar.tsx NAV_LINK_BASE

Note on table cell padding: EpicsPage.tsx uses `py-3` (12px) and `px-3` (12px) on table cells. These values are inherited from the mirrored EpicsPage.tsx component and are not new spacing decisions made for this phase. They exist in the codebase as pre-existing Tailwind utilities and are used here by mirror convention only.

## Typography

Tokens from `index.css` `@theme inline` block. All body text uses Geist Variable.

| Role | Size | Weight | Line Height | Usage in This Phase |
|------|------|--------|-------------|---------------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 | Table cell content, nav item labels, badge text |
| Label | 12px (`text-xs`) | 400 (regular) | 1.4 | Table header labels, muted sub-text, project key monospace labels |
| Heading | 20px (`text-xl`) | 600 (semibold) | 1.2 | Page-level `<h1>` titles ("AIO Projects", "AIO Cycles — {project name}") |
| Monospace | 12px (`text-xs font-mono`) | 400 (regular) | 1.4 | Cycle key column (e.g. "PROJ-CY-2"), project key badge |

Two weights only: 400 (regular) for Body/Label/Monospace and 600 (semibold) for Heading. The `--muted-foreground` color token provides sufficient visual separation for table header labels without requiring a distinct weight.

Source: EpicsPage.tsx observed usage (`text-xl font-semibold` heading, `text-sm` rows, `text-xs text-muted-foreground` headers, `text-xs font-mono` key column).

## Color

All color values are CSS custom properties from `index.css`. No new color tokens are introduced in this phase.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (light: `oklch(1 0 0)`, dark: `oklch(0.145 0 0)`) | Page background, main content surface |
| Secondary (30%) | `--muted` (light: `oklch(0.97 0 0)`, dark: `oklch(0.269 0 0)`) | Table header row (`bg-muted/10`), hover rows (`hover:bg-muted/30`), skeleton blocks |
| Sidebar surface | `--sidebar` (light: `oklch(0.985 0 0)`, dark: `oklch(0.205 0 0)`) | Navigation sidebar background — already in use |
| Accent (10%) | `--accent` + `--accent-foreground` | Active nav link highlight (`bg-accent text-accent-foreground font-semibold`) — ONLY for the active AIO nav item |
| Border | `--border` (light: `oklch(0.922 0 0)`, dark: `oklch(1 0 0 / 10%)`) | Table row dividers, page header bottom border, input borders |
| Muted foreground | `--muted-foreground` | Table header text, project key badge text, empty state icon |
| Destructive | `--destructive` | Error state alert variant only — no destructive user actions in this phase |

Accent reserved for: the active sidebar nav item only. Status badges use semantic color utilities listed below — NOT the accent token.

**AIO Cycle Status Badge Colors** (new — extends existing `statusStyles.ts` pattern):

| AIO Status | Badge classes |
|------------|--------------|
| Active | `bg-blue-500/15 text-blue-600 dark:text-blue-400` |
| Closed | `bg-muted text-muted-foreground` |
| Unknown / other | `bg-muted text-muted-foreground` (fallback) |

Source: Matches `statusCategoryBadgeClass` precedent in `statusStyles.ts`. AIO cycle status is a plain string from the API (e.g. "Active", "Closed"). A new helper `aioCycleStatusBadgeClass(status: string): string` must be added to `statusStyles.ts` using the same pattern.

## Page Layout Contracts

### AIO Projects Page (`/aio-projects`)

```
┌─────────────────────────────────────────────────────────┐
│ Page header: px-6 py-4 border-b border-border flex-shrink-0 │
│   h1 "AIO Projects" — text-xl font-semibold             │
├─────────────────────────────────────────────────────────┤
│ Content: flex-1 overflow-auto                           │
│                                                         │
│  [Loading] AioProjectsSkeleton (5 rows, p-4 wrapper)   │
│  [Error]   ErrorState in p-4 wrapper                   │
│  [Empty]   EmptyState icon=FlaskConical                 │
│  [Data]    <table class="w-full text-sm">              │
│    <thead class="border-b bg-muted/10">                │
│      Name | Project Key                                │
│    </thead>                                            │
│    <tbody>                                             │
│      [rows — clickable, navigate to project overview]  │
│    </tbody>                                            │
│  </table>                                              │
└─────────────────────────────────────────────────────────┘
```

Table columns (AIO Projects):

| Column | Width | Classes | Content |
|--------|-------|---------|---------|
| Name | auto | `px-4 py-3` | Project name as plain text, clickable row → `/aio-project/:projectKey` |
| Project Key | `w-28` | `px-3 py-3 text-xs text-muted-foreground font-mono` | `projectKey` value |

Row interaction: entire `<tr>` is clickable. `cursor-pointer`, `hover:bg-muted/30 transition-colors`, `border-b border-border`.

### AIO Project Overview Page (`/aio-project/:projectKey`)

```
┌─────────────────────────────────────────────────────────┐
│ Page header: px-6 py-4 border-b border-border flex-shrink-0 │
│   h1 "Cycles — {projectKey}" — text-xl font-semibold   │
├─────────────────────────────────────────────────────────┤
│ Content: flex-1 overflow-auto                           │
│                                                         │
│  [Loading] AioCyclesSkeleton (5 rows, p-4 wrapper)     │
│  [Error]   ErrorState in p-4 wrapper                   │
│  [Empty]   EmptyState icon=FlaskConical                 │
│  [Data]    <table class="w-full text-sm">              │
│    <thead class="border-b bg-muted/10">                │
│      Cycle Key | Name | Status                         │
│    </thead>                                            │
│    <tbody>                                             │
│      [rows — Name column is NavLink to cycle detail]   │
│    </tbody>                                            │
│  </table>                                              │
└─────────────────────────────────────────────────────────┘
```

Table columns (AIO Cycles):

| Column | Width | Classes | Content |
|--------|-------|---------|---------|
| Cycle Key | `w-28` | `px-3 py-3 text-xs text-muted-foreground font-mono` | `cycle.key` (e.g. "PROJ-CY-2") |
| Name | auto | `px-4 py-3` | `cycle.name` as `<NavLink to="/aio-cycle/{projectKey}/{cycleKey}">` — underline on hover |
| Status | `w-32` | `px-3 py-3` | Inline `<span>` with `aioCycleStatusBadgeClass(cycle.status)` classes |

Row interaction: only the Name column cell is a link (NavLink, not full-row click). Row has no cursor change — only the name cell is interactive. Reason: full-row click is not appropriate since the cycle detail route is not yet built (Phase 53); NavLink on name makes intent clear without implying the full row leads somewhere.

### Sidebar "Testing" Section

The new sidebar section follows the existing pattern exactly:

```
[separator line — same border-border style as between existing sections]
TESTING (section label — text-xs text-muted-foreground px-3 mb-1)
  [FlaskConical icon] AIO Projects     ← nav item
```

Visibility rule: entire "Testing" section hidden when `aioEnabled === false`. When `aioEnabled === true`, section inherits normal sidebar show/hide logic from `sidebarItems` settings. Active state: `bg-accent text-accent-foreground font-semibold` on the active nav item.

## Interaction States

| State | Component | Visual Treatment |
|-------|-----------|-----------------|
| Loading | AioProjectsPage, AioProjectOverviewPage | `AioProjectsSkeleton` / `AioCyclesSkeleton` — 5 `<Skeleton className="h-10 w-full" />` rows, `p-4` wrapper, `flex flex-col gap-2` |
| Error (no cached data) | Both pages | `<ErrorState>` in `p-4` wrapper — uses `alert` variant="destructive", "Retry" triggers `queryClient.invalidateQueries` |
| Empty | Both pages | `<EmptyState icon={FlaskConical} title="..." subtitle="..." />` — centered, `py-8`, icon `size-12 text-muted-foreground` |
| Data loaded | Both pages | `<table>` with header and rows |
| Row hover (projects page) | `<tr>` | `hover:bg-muted/30 transition-colors` |
| Cycle name hover (cycles page) | `<NavLink>` in name cell | underline |
| Active sidebar item | NavLink in Sidebar | `bg-accent text-accent-foreground font-semibold` |
| Sidebar hidden (aioEnabled=false) | Testing section | `display: none` — entire section absent from DOM by conditional render |
| 200ms delay gate | Skeleton display | `useDelayedLoading(isLoading)` — no skeleton flash for fast responses |
