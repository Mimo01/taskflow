## Interaction Contract

### Progressive Reveal Order

1. **Base fetch resolves** → Header section unmasks immediately (no skeleton delay beyond the 200ms `useDelayedLoading` gate). This is the first-meaningful-paint target (PERF-DETAIL-01).
2. **Description / Fields / Attachments / Links** → resolve with the same base fetch response; they unmask together with the header. No separate skeleton needed beyond the initial full-page skeleton while the base is in-flight.
3. **Comments, Subtasks (enriched), Changelog** → each independently transitions from skeleton → content as its own query resolves.

### 200ms Flash-Prevention Gate

Every section that has its own query MUST gate its skeleton through `useDelayedLoading(isPending, 200)`. A section skeleton only appears if the pending state persists beyond 200ms. Cache hits (TanStack Query `gcTime: Infinity`) will never show a skeleton.

### Inline Error States

- **Each independent section** (comments, subtasks, changelog): on query error, render `<ErrorState error={error} onRetry={refetch} viewName="{section name}" />` in the section slot. All other sections remain functional.
- **Base fetch failure**: render the existing panel-level `IssueDetailSkeleton` or a full-panel `ErrorState` — this is the only case that may blank the panel (D-08).

### No Layout Shift

Sections are positioned statically in JSX order and always occupy their reserved slot (skeleton or content). Content does not reflow as sections arrive. The two-column layout (left `flex-1` + right sidebar `w-[42%]`) is established by the base structure and never collapses.
