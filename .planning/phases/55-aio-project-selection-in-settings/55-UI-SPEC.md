# Phase 55 — UI Design Contract

> Visual and interaction contract for the AIO Project Selection in Settings phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase has **no new visual primitives** — it adds a single `<Select>` picker inside the existing `IntegrationsSection.tsx` and gates a sidebar entry. All design tokens listed below are pre-existing in `taskflow/src/index.css` and `taskflow/components.json`. The contract pins which tokens are used and locks copywriting, behavior, and state rendering so the executor matches the surrounding Settings sections exactly.

Specific spacing rules for this phase:

1. The picker block sits **inside the same `<div className="flex flex-col gap-4">` subsection** as the `aioEnabled` toggle (`IntegrationsSection.tsx:9`). One subsection — toggle on top, picker below. No `gap-8` separator between them.

3. Inline loading row uses `gap-1.5` between `Loader2` icon and text — matches `ConnectionsSection.tsx:137`.
4. Inline error row uses `gap-1.5` between `XCircle` icon and message — matches `ConnectionsSection.tsx:149`.

## Copywriting Contract

All copy below is **prescriptive** — the executor uses these exact strings.

### Picker label + helper

| Element | Copy |
|---------|------|
| Picker `<Label>` text | `AIO Project` |
| Helper text below label (one line, `text-xs text-muted-foreground`) | `Pick the AIO Test Management project this app shows.` |

### Picker states

| State | Copy |
|-------|------|
| Trigger placeholder (no selection) | `Choose a project...` *(matches `GitLabStep.tsx:123` verbatim)* |
| Trigger value (selection present) | Project `name` only — no `projectKey` suffix in the trigger. Inside the dropdown each item is rendered as the project `name` only. (CONTEXT.md D-03 stored value is `projectKey`, displayed value is `name`. Planner has discretion under CONTEXT.md "Claude's Discretion" to add `(PROJECTKEY)` after the name in the dropdown items if name collisions look likely; default is name-only for simplicity.) |
| Loading row | `Loading projects…` |
| Error row | `Couldn't load AIO projects.` followed by an inline `Retry` button (text-only, `text-sm underline text-destructive hover:no-underline`) |
| Empty (`projects.length === 0`) | `No AIO projects available` (rendered inside a disabled trigger, no dropdown content) |

### Primary CTA

This phase has **no primary CTA**. Selection is silent-persist on `onValueChange` (CONTEXT.md D-14). No "Save" button, no "Apply" button, no toast. The Settings pattern in this codebase is identity-on-change (`AppearanceSection.tsx`, `WorkflowSection.tsx`, `IntegrationsSection.tsx`).

### Empty state heading / body

The picker's only empty surface is the inline `No AIO projects available` text inside a disabled trigger. There is no full-section empty state — the deleted `AioProjectsPage` had one, but Settings sub-controls do not (consistent with `IntegrationsSection.tsx`).

| Element | Copy |
|---------|------|
| Empty state heading | n/a — Settings sub-control does not render a heading-level empty state |
| Empty state body | `No AIO projects available` (inline, inside disabled Select trigger) |

### Error state

| Element | Copy |
|---------|------|
| Error message | `Couldn't load AIO projects.` |
| Recovery action | Inline `Retry` text-button next to the message; clicking calls `refetch()` from the picker's `useQuery` |

No full-page `<ErrorState>` component (CONTEXT.md D-05 — too heavy for a sub-control).

### Destructive actions / confirmations

This phase has **no destructive actions in the picker UI itself**. However, it deletes routes and files at the codebase level (CONTEXT.md D-11, D-12). User-visible behavior change:

| Action | User-visible effect | Confirmation |
|--------|---------------------|--------------|
| `/aio-projects` route removed | Existing bookmarks / deep-links to `/aio-projects` will hit the route fallback. Bookmarks are unlikely (Phase 52 shipped 2026-05-13, two days before this phase). | None — route removal is a one-line edit. No banner, no migration toast. The sidebar entry now deep-links to `/aio-project/${selectedAioProjectKey}` so the only path the user actually clicks still works. If they manually paste `/aio-projects`, the existing route fallback handles it. |

Per CONTEXT.md D-08: toggling `aioEnabled` to `false` does **NOT** clear `selectedAioProjectKey` and the user is **not warned** about this. This is intentional ("the toggle is a gate; the selection is data") and requires no confirmation copy.

## Sidebar Behavior Contract

The sidebar `'aio-projects'` nav item is the only consumer of this phase's persisted state outside Settings. Visual contract:

| State | Visibility | Label | Icon | Click target |
|-------|------------|-------|------|--------------|
| `aioEnabled = false` | hidden (filtered out at `Sidebar.tsx:277`) | n/a | n/a | n/a |
| `aioEnabled = true` AND `selectedAioProjectKey === null` | hidden (filtered out) | n/a | n/a | n/a |
| `aioEnabled = true` AND `selectedAioProjectKey !== null` | visible inside the existing `'testing'` section | `AIO Projects` (label unchanged from Phase 52) | `FlaskConical` from lucide (unchanged from Phase 52) | `/aio-project/${selectedAioProjectKey}` |

No transition animation is added when the entry appears/disappears on toggle/selection — the existing sidebar render is identity (no enter/leave animation declared in Phase 52). Re-render via Zustand subscription is sufficient.

The label `AIO Projects` remains plural even though the item now points to a single configured project. Renaming to `AIO Project` is **out of scope** for this phase to avoid sidebar-items.ts label drift (the persisted `id` `'aio-projects'` and the user-visible label are decoupled in `sidebar-items.ts`, but consistency with Phase 52 documentation wins). Planner may revisit if user feedback demands it.

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Toggle `aioEnabled` ON | Picker block mounts immediately. `useQuery(['aio', jiraBaseUrl, 'projects'])` fires. Loading row appears until response. |
| Toggle `aioEnabled` OFF | Picker block unmounts immediately. Selection value is preserved in store (D-08). |
| Open picker dropdown | Native Radix Select behavior — keyboard nav (↑/↓, Home/End, type-ahead), focus ring uses `--ring`. No search input (CONTEXT.md D-03). |
| Select an item | `setSelectedAioProjectKey(projectKey)` fires synchronously. Dropdown closes. Trigger label updates to project `name`. **No toast, no redirect, no banner** (D-14). |
| Selection cleared (programmatically — only path is migration of corrupted persisted state) | Trigger reverts to placeholder `Choose a project...`. Sidebar entry hides. |
| Network error during initial load | Inline error row replaces the loading row. `Retry` button calls `refetch()`. Trigger remains rendered (not removed) so the user knows where the picker is. |
| `projects.length === 0` after successful load | Trigger renders with disabled state and placeholder text `No AIO projects available`. No dropdown opens on click. |

Keyboard: the picker is fully reachable via `Tab` in document order — it sits below the toggle inside `IntegrationsSection`. Focus ring uses the existing `--ring` token (no override).

ARIA: `<Label htmlFor="aio-project">` and `<SelectTrigger id="aio-project">` — same pattern as `GitLabStep.tsx:110,115`. Inline error uses `role="alert"` (matches `GitLabStep.tsx:102`).
