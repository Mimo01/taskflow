<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tauri Store persistence | `settings.json` on disk is written by the Tauri plugin; treated as user-owned local state (no remote attacker surface for a single-user desktop app). |
| Migration callback (`migrate`) | Untrusted persisted state from a prior install version crosses into the store; values are read and conditionally defaulted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-01 | Tampering | `migrate()` v17 guard | mitigate | Guard checks `=== undefined` (does NOT trust arbitrary string content). Stored value is later coerced into a URL path by Sidebar.tsx (Plan 03); the value originates from a server-controlled enum (AIO `projectKey` from `fetchAioProjects`) in normal flow (Plan 02), so injection from the API surface is the bounding risk and is addressed there. This plan adds no new attack surface. |
| T-55-02 | Information Disclosure | Persisted `selectedAioProjectKey` | accept | The selected project key is non-secret (it's a Jira project key like `PROJ`). No PII, no credentials. Tauri Store file is per-user app data. |
| T-55-03 | Denial of Service | Migration chain corruption | accept | A bad persisted state could in theory cause migration failure, but the migrate callback's `if (version < N)` chain is idempotent and mutates `s` in place; existing v14/v15/v16 chain already handles this pattern without DoS. No new DoS surface. |
</threat_model>
