<feature>
  <name>Issue draft snapshot rules</name>
  <files>taskflow/src/lib/issue-draft-snapshot.ts, taskflow/src/lib/issue-draft-snapshot.test.ts</files>
  <behavior>
    hasUserContent(state, stagedCount):
    - all empty, stagedCount 0, type 'Bug', assignee set, priority set, epic set → false (D-12)
    - summary '  x ' → true; description 'a' → true; stagedCount 1 → true
    - linkRows [{linkTypeId:'1', issueKey:''}] → false; [{linkTypeId:'1', issueKey:'ABC-1'}] → true
    hasEpicContent(name, description, stagedCount): ('', '', 0) → false; (' n', '', 0) → true; ('', '', 1) → true
    toIssueSnapshot(state, fieldNames) / snapshotToFormPatch(snapshot):
    - snapshot omits apiError, customFieldAutoResults, customFieldShowResults, assigneeUnassignPicked
    - snapshot.customFieldNames maps each customFieldValues key to fieldNames[key] (missing name falls back to the key)
    - snapshotToFormPatch(toIssueSnapshot(s)) applied over buildInitialState() deep-equals s for every persisted key
    keptFieldsAfterCreate(state):
    - returns selectedIssueType, epicLinkKey, parentKey, selectedAssignee, selectedAssigneeName, assigneeUnassignPicked, priority, labels, fixVersions, customFieldValues, customFieldInputValues
    - does NOT contain summary, description, storyPoints, timeEstimate, linkRows
    validateSnapshot(snapshot, ctx):
    - ctx.epicExists false with epicLinkKey 'EP-1' → patch.epicLinkKey null, notes.epic 'Epic EP-1 no longer exists'
    - ctx.epicExists null (unknown / lookup error) → epic kept, no note (never clear on uncertainty)
    - ctx.parentExists false with parentKey 'P-2' → patch.parentKey null, notes.parent 'Parent P-2 no longer exists', selectedIssueType stays 'Subtask'
    - custom field 'customfield_1' not in ctx.createmetaFields → removed from customFieldValues and customFieldInputValues, notes.customFields['customfield_1'] = '{customFieldNames name} is no longer available on this screen'
    - custom field present with allowedValues not containing the stored id → value cleared, note '{input label} is no longer an option, choose another'
    - ctx.createmetaFields undefined (not loaded) → custom fields untouched, no notes
    - ctx.fixVersionIds Set without stored id '9' (name 'v9') → that version removed, notes.fixVersions 'v9 is no longer an option, choose another'; ctx.fixVersionIds null → untouched
    - valid snapshot → empty patch-diff and no notes
  </behavior>
  <implementation>Export `type StaleNotes = { epic?: string; parent?: string; fixVersions?: string; customFields: Record<string, string> }` and `validateSnapshot(snapshot: IssueDraftSnapshot, ctx: { createmetaFields?: CreatemetaField[]; epicExists: boolean | null; parentExists: boolean | null; fixVersionIds: Set<string> | null }): { snapshot: IssueDraftSnapshot; notes: StaleNotes }` returning a corrected copy (never mutate input). `toIssueSnapshot(state: FormState, fieldNames: Record<string, string>): IssueDraftSnapshot`; `snapshotToFormPatch(s: IssueDraftSnapshot): Partial<FormState>` (used with the HYDRATE action). `hasUserContent(state: Pick<FormState, 'summary' | 'description' | 'linkRows'>, stagedCount: number)` and `hasEpicContent(name, description, stagedCount)`. `keptFieldsAfterCreate(state: FormState): Partial<FormState>` (used with RESET_KEEP). Per Claude's discretion (RESEARCH A4, orchestrator-resolved): Create another keeps ALL custom field values. No React, no store, no Tauri imports; type-only imports from the store and form modules. Placeholder data only in tests.</implementation>
