| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), inline padding, sub-item indentation unit |
| sm | 8px | Compact element spacing (`gap-2`), sub-item vertical padding |

- Page header: `px-6 py-4` (24px / 16px) — matches `WorklogsPage` header pattern
- Sub-items beneath an issue group: `pl-8` (32px) left indent to clear the icon column
- Issue group row height: `py-2` (8px top/bottom) per row
- Column divider: 1px solid `border-border`

Source: existing `WorklogsPage` header (`px-6 py-4`), scouted from codebase.

## Interaction Patterns

### Data loading

Each data source loads independently via a separate `useQuery` hook. Sections render their own `Skeleton` while loading and their own `ErrorState` or `EmptyState` on failure/empty — they do not block each other.

Loading order (parallel): Tempo worklogs, Jira changelog, GitLab commits, GitLab MR events.

### Issue group structure (D-07)

```
[icon] [IssueKey] [Summary text]                    [Xh right-aligned]
  ├─ [branch-icon] Commit message  (git commits)
  ├─ [arrow-icon]  To Do → In Progress  (status transition)
  ├─ [mr-icon]     Opened !2104  (MR opened/updated)
  └─ [chat-icon]   Comment: "..."  (Jira comment / MR comment)
```

Icon assignments (Lucide):
- Git commits: `GitBranch`
- Status transitions: `ArrowRight`
- MR activity (comments on MRs): `MessageSquare`
- Approvals: `CheckCircle`
- Jira comments: `MessageCircle`
- MR opened/merged: `GitMerge`
- Issue group icon (type indicator): `CircleDot` (Story), `Bug` (Bug), `ChevronRight` (Subtask), `Layers` (Epic)

Source: D-07 (CONTEXT.md). Exact icon names are Claude's discretion per CONTEXT.md.

### Summary stat line (D-10)

Rendered beneath the "Yesterday · [date]" column heading in `text-xs text-muted-foreground`:

```
7.5h logged across 3 stories · 7 commits · 2 MR events
```

Separators: `·` (middle dot, U+00B7) with single space on each side.
Rendered only when at least one data source returns data. Hidden (not shown as "0h · 0 commits") when all sources are empty.

### Copy markdown (D-12)

Button in the page header: `<Button variant="default" size="sm">Copy markdown</Button>`. Uses Tauri clipboard API (same pattern as other copy actions in the app). On success: button label changes to "Copied!" for 2 seconds then reverts — no toast or modal. No confirmation step required.

### Refresh

`<Button variant="ghost" size="sm">Refresh</Button>` next to "synced Xm ago" text. Triggers `refetch()` on all four `useQuery` hooks simultaneously. While refetching, each section shows its existing data (stale) — no full skeleton replay.

### "Yesterday" date resolution (D-15)

Computed client-side before any API call. Logic:
1. Start from today minus one calendar day.
2. While the result is Saturday or Sunday, subtract one more day.
3. If Tempo is enabled (`tempoEnabled === true`), additionally check the Tempo schedule API result (`fetchUserSchedule`) and skip any day marked as a public holiday.
4. The resolved date is `yesterdayDate` (YYYY-MM-DD format, via `.slice(0, 10)`).

### Today column placeholder (D-06, Phase 69 scope)

Render the column shell with:
- Column heading: `Today` (`text-xl font-semibold`) + current date in `text-xs text-muted-foreground`
- Body: `EmptyState` with `Clock` icon, title "Today section coming soon", subtitle "Planned tasks, pinned issues, and worklog targets will appear here."

## Page Header Anatomy (D-11)

```
┌─────────────────────────────────────────────────────────────────────────┐
│  Standup notes                    • synced 3m ago  [Refresh]  [Copy markdown] │
│  Monday, 26 May 2026 (muted)                                            │
└─────────────────────────────────────────────────────────────────────────┘
```

- Title: `<h1 className="text-2xl font-semibold">Standup notes</h1>` — lowercase 'n' in "notes" (matches mockup)
- Date line: `<p className="text-xs text-muted-foreground">Monday, 26 May 2026</p>` — full weekday + day + month + year format
- Sync status: `<span className="text-xs text-muted-foreground">• synced Xm ago</span>` — bullet separator, minutes since last successful fetch
- Refresh: ghost small button, no icon
- Copy markdown: default (primary) small button, `Copy` icon from Lucide (`Copy`) to the left of label

Header container: `<header className="px-6 py-4 border-b border-border flex items-center justify-between">` — matches existing page header pattern.

## States per Section

Each of the four Yesterday sections (Tempo, Jira, Commits, MR Activity) must implement all four states:

| State | Trigger | Rendered output |
|-------|---------|-----------------|
| Loading | `isLoading === true` | 3× `<Skeleton className="h-4 w-full" />` stacked with `gap-2` |
| Empty | Success + zero items | `<EmptyState>` with section-specific copy |
| Error | `isError === true` | `<ErrorState error={...} onRetry={refetch} viewName="..." />` |
| Populated | Success + ≥1 items | Issue group list |

Integration-disabled state (not an error): render a muted inline notice using `text-xs text-muted-foreground` with a link to Settings. Do not use `ErrorState` for disabled integrations.
