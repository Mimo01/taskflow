Accent reserved for:
- The **insertion line** rendered at the target drop position between rows (`border-primary`)
- The **focused-row left border** (existing `border-l-2 border-primary` pattern from `BacklogRow`)
- The **Confirm button** in the cross-section confirmation dialog (default `Button` uses `--primary`)

**Drag ghost:** `opacity-60` on the cloned row + `shadow-lg` for elevation. No new color — inherits row background.

**Section hover highlight:** `bg-accent/20 ring-1 ring-border` on the `<tbody>` / section wrapper when a dragged item hovers over a different section. Uses existing `--accent` token at reduced opacity — subtle, not alarming.

**Inline error banner:** reuses `StaleDataBanner` pattern — `bg-muted border border-border text-muted-foreground`. No destructive color; rank failure is transient/retryable, not destructive.

## Interaction Contract

This section is specific to Phase 78's drag interaction. Required by the executor in lieu of a design mockup.

### Drag Initiation (D-06)
- Entire `<tr>` is the drag trigger.
- `PointerSensor` activation: `{ delay: 150, tolerance: 5 }` — prevents accidental drags from clicks.
- `justDragged` ref guard: suppresses the `onClick` (peek open) that would fire immediately after drag end.
- Cursor: `cursor-grab` while draggable rows are in drag-ready state; `cursor-grabbing` during active drag. Apply via `data-dragging` attribute on the `<tr>`.

### Drag Ghost (D-07)
- Use dnd-kit `DragOverlay` with a cloned `<BacklogRow>` at `opacity-60` + `shadow-lg`.
- The ghost is positioned absolutely following the pointer (dnd-kit default). No snap-to-row.
- Ghost width: match source row width exactly (pass explicit width from `getBoundingClientRect`).

### Insertion Line (D-07)
- A `<div>` with `h-0.5 bg-primary rounded-full` rendered between rows at the computed insertion index.
- Rendered inside the sortable list, not the overlay — it shows in-list, not following the cursor.

### Section Highlight (D-05)
- When the drag pointer crosses into a **different** section (i.e., cross-section move candidate), wrap that section's `<tbody>` with `ring-1 ring-border bg-accent/10` to signal pending sprint-membership change.
- Remove highlight immediately on drag end or return to original section.

### Intra-List Drop (D-01, D-02)
- Drop fires rank PUT immediately, no dialog.
- Optimistic update: list re-orders instantly; mutation runs in background.
- On success: nothing visible changes (already ordered correctly).
- On failure: roll back to pre-drag snapshot + show inline error banner.

### Cross-Section Drop (D-03, D-04)
- Drop into different section: show `ConfirmSprintMoveDialog` (existing component at `src/components/ui/confirm-sprint-move-dialog.tsx`).
- Dialog shows: "Move {ISSUE-KEY} from {Source Sprint / Backlog} to {Target Sprint / Backlog}?"
- Confirm fires: sprint-membership API call + rank PUT.
- Cancel: rolls back optimistic position, no API call.
- API failure on confirmed move: roll back + show inline error banner (same as intra-list failure).

### Flicker Prevention (D-08)
- `cancelQueries` for `useGhBacklogData` query key in `onMutate`.
- `isDraggingRef` gates local order state as the rendered source of truth while drag is active.
- Background 60s poll does not update list order while `isDraggingRef.current === true`.
