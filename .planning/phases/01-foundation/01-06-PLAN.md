<!-- Root cause — named import in production code that tests must mock -->

From taskflow/src/services/jira.ts (line 20):
```typescript
import { fetch } from '@tauri-apps/plugin-http';
```
The fetch identifier inside jira.ts is the module binding, not globalThis.fetch.
vi.stubGlobal('fetch', ...) is invisible to this file.

From taskflow/src/services/gitlab.ts (line 16):
```typescript
import { fetch } from '@tauri-apps/plugin-http';
```
Same situation as jira.ts.

<!-- Correct mock pattern — vi.mock intercepts the ES module at module resolution time -->

```typescript
// At module scope (before any describe/it blocks):
import { vi } from 'vitest';

vi.mock('@tauri-apps/plugin-http', () => ({
  fetch: vi.fn(),
}));

// Capture mock ref for per-test configuration:
import { fetch as mockFetch } from '@tauri-apps/plugin-http';

// Per-test usage:
vi.mocked(mockFetch).mockResolvedValue({ ok: true, status: 200, json: async () => data });
vi.mocked(mockFetch).mockResolvedValue({ ok: false, status: 401, json: async () => ({}) });
vi.mocked(mockFetch).mockRejectedValue(new Error('Network failure'));
```

Why vi.mock works where vi.stubGlobal does not:
vi.mock() is hoisted by Vite/Vitest and intercepts the module at import resolution time.
When jira.ts resolves `import { fetch } from '@tauri-apps/plugin-http'`, it receives
the mock factory's return value. vi.stubGlobal patches globalThis.fetch only, which
the service files never reference after the Plan 05 import change.
