    2. JiraStep.tsx line 112
       Change: `<Select value={selectedProject} onValueChange={setSelectedProject}>`
       To:     `<Select value={selectedProject} onValueChange={(v) => v && setSelectedProject(v)}>`
       Reason: setSelectedProject has type Dispatch<SetStateAction<string>>; shadcn Select's
       onValueChange is typed as (value: string) => void; passing the setter directly causes TS2322.
       The null guard `v &&` satisfies the type without changing runtime behaviour.

    3. GitLabStep.tsx line 108
       Change: `<Select value={selectedGroup} onValueChange={setSelectedGroup}>`
       To:     `<Select value={selectedGroup} onValueChange={(v) => v && setSelectedGroup(v)}>`
       Reason: Identical TS2322 issue as JiraStep — same fix.

    4. stronghold.ts lines 73-74 — replace the readSecret function body:
       Old:
         const data = await store.get(key);
         return new TextDecoder().decode(new Uint8Array(data));
       New:
         const data = await store.get(key);
         if (data === null) throw new Error(`Secret not found: ${key}`);
         return new TextDecoder().decode(new Uint8Array(data));
       Reason: store.get() returns Uint8Array | null; passing null to new Uint8Array()
       throws a TypeError at runtime (TS2769). Throwing a predictable error makes
       callers handle missing keys explicitly rather than crashing opaquely.
