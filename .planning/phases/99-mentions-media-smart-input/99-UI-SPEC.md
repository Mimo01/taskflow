# Phase 99 — UI Design Contract

> Visual and interaction contract for the input features of the shared `<WikiEditor>`: suggestion popovers (`@`, `/`, `:`, issue keys), upload placeholders and embeds, paste behaviour, and the compact-host bubble menu. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: 99-CONTEXT.md D-01..D-20 and Claude's Discretion defaults, 98-UI-SPEC.md (tokens and frame inherited, not re-specified), `WikiRenderer.tsx` (mention pill), `components.json`. No user questions were needed. Sketch-findings skill (Releases pages) not applied.

## Spacing Scale

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between glyph/name/token in a row; popover outer padding; chip icon gap |
| sm | 8px | Suggestion row horizontal padding; bubble menu padding; footer row gaps |
| md | 16px | Not used inside popovers; error-line vertical rhythm only |
| lg | 24px | Not used |
| xl | 32px | Not used |
| 2xl / 3xl | 48 / 64px | Not used |

Component sizing:
- Suggestion popover: width 288px (`w-72`), min 224px, max 320px; max-height 280px with internal scroll; `rounded-lg`, 1px `border`, `bg-popover`, `shadow-md`; 4px padding.
- Suggestion row: 32px high, 8px horizontal padding, 8px gap, `rounded-md`; leading check slot NOT used (these are insert actions, not selection states).
- Mention avatar in row: 20px (CachedAvatar explicit px sizing). Emoticon glyph slot: 20px. Slash item icon slot: 16px lucide in a 20px slot.
- Bubble menu: 32px high, 4px padding, buttons 24px square icon-only ghost, 4px gap, 1px vertical separators; `rounded-lg`, `border`, `bg-popover`, `shadow-md`. Offset 8px above the selection.
- Compact footer row: 32px high, 8px horizontal padding, 4px gap, buttons 28px (same as toolbar), top border 1px.
- Upload placeholder chip: 20px high inline, `px-2` (8px), 4px gap, spinner 12px.
- Upload error line: 24px high line under the editor frame content area, 8px horizontal padding.
- Embedded image: capped to column width, `max-height` none; staged and uploaded identical.

Exceptions: 1px borders/separators; 12px spinner and 20px/24px controls are multiples of 4; 288px/224px/320px popover widths are multiples of 4.

## Typography

Inherits 98 (two weights only: 400 and 600). New surfaces use existing roles.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (document text, query text in doc) | 14px | 400 | 1.5 (WikiRenderer parity) |
| Label (suggestion primary text, bubble/footer tooltips, placeholder chip, error line, toast) | 12px | 400 | 1.5 |
| Label emphasis (section heading inside slash menu: "Recent", "Blocks", "Insert") | 12px | 600 | 1.5 |
| Mono token (`:smile:` wiki token column, key column of issue suggestions) | 12px | 400 | 1.5 |

Suggestion secondary text (username, issue summary, emoticon token) is 12px `text-muted-foreground`. Heading/Display roles are not introduced in this phase.

Parity exception: the in-document mention pill reuses the shipped WikiRenderer classes verbatim (`mention-badge inline-flex items-center rounded bg-primary/15 text-primary px-1.5 py-0.5 text-xs font-medium`, which renders at weight 500). This is content parity with the read view (EDIT-01), not a chrome weight; do not alter it in this phase.

## Color

Neutral base-nova tokens; no new colours.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--popover` | Editor content, popover, bubble and footer surfaces |
| Secondary (30%) | `--muted` / `bg-muted/30-40`, `--accent` | Placeholder chip fill, footer row fill, highlighted suggestion row (`bg-accent`), unresolved mention pill |
| Accent (10%) | `--primary` / `--ring` | See list below |
| Destructive | `--destructive` | Upload error line text and its icon only |

Accent reserved for: the mention pill (`bg-primary/15 text-primary`, existing WikiRenderer look); focus ring on the editor frame; selected image node-selection outline (`ring-1 ring-ring`); active/pressed state of bubble mark buttons; the matched-substring emphasis in suggestion rows is NOT accent (use weight 600). Never for hover/highlight backgrounds (use `accent`/`muted`).

Content colours:
- Unresolved mention: same pill geometry, `bg-muted text-muted-foreground`, raw username as text, no icon, no warning colour (D-02).
- Issue-key decoration: reuse the exact WikiRenderer issue-key link classes (class constant extracted and imported, not copied); it is a ProseMirror decoration, never a node, never a mark.
- Upload placeholder chip: `border border-dashed border-border bg-muted/30 text-muted-foreground` (matches 98 raw-atom chip language).
- Attachment chip node (`[^file]`): reuse the DescriptionEditor/WikiRenderer attachment chip look; do not fork.

## Component & Interaction Contract

### Suggestion popover infrastructure (D-19, D-20) — shared by `@`, `/`, `:`, keys
- One shared component/plugin wrapper (`@tiptap/suggestion` allowed). Caret-anchored via the caret rect (virtual anchor), portaled to `body`, flips above when below-space < 160px, never covers the caret line, re-anchors on scroll/resize of the editor scroller.
- Keyboard: Up/Down move highlight (wraps), Enter and Tab select, Esc dismisses, Left/Right/Home/End and any click outside dismiss. The editor keeps DOM focus the whole time (popover items are `onMouseDown preventDefault`, `role="listbox"`/`option`, `aria-activedescendant` on the editor).
- Esc nesting: the popover (and the bubble menu, and node-view menus) handle Esc in capture, call `stopPropagation`, and only then does an enclosing Dialog see the next Esc. A dismissed `/`, `:` or `@` leaves the typed characters in the document.
- Lifecycle: on unmount, blur, mode switch to source, doc replace or editor destroy the popover DOM node is removed (no leaked portal; test asserts `document.body` has no residual `[data-suggestion]` nodes).
- Highlight is `bg-accent`; first item highlighted on open; no mouse-hover highlight change while the pointer is stationary (prevents the stale-hover jump).
- Loading: first query shows 3 `Skeleton` rows (32px); subsequent queries keep the previous results visible (no blink) until new ones arrive. Empty and error states below.
- Max 8 visible rows before scroll (mentions, keys, emoticons); slash menu max 10.

### `@` mention (INPUT-01, D-01..D-03)
- Trigger: `@` at start of line or after whitespace/open punctuation; not mid-word (`a@b.com`). Query debounced 250ms, server-side `fetchAssignableUsers` for the issue's project.
- Row: 20px avatar, display name (12px, 400), username right-aligned muted. Empty query shows the first assignable users (no "type to search" dead state).
- Select inserts a `mention` node (pill) followed by a space; caret after the space. Serialises `[~username]`.
- Pill in editor = WikiRenderer pill; display name from `useMentionUserMap`; tooltip (existing `tooltip.tsx`) shows the username. No avatar inside the pill.
- Pill is an atom: Backspace removes it as a unit; arrow keys step over it; node-selection outline uses `ring-1 ring-ring`.
- Source mode: same popover anchored to the textarea caret (mirror-div measurement allowed only for source mode); inserts `[~username]` text.

### Issue-key autocomplete and decoration (INPUT-05, D-04)
- Decoration: any token matching a known project key pattern is rendered with the issue-key link look; no markup written. Plain click in the editor places the caret (no navigation); Cmd+click opens the issue via existing internal-link handling.
- Autocomplete opens when the user types a known project prefix plus dash (`ABC-`) with at least one more character not required (opens on the dash). Row: key (mono 12px, 600 only if the match is exact), summary (12px, truncate), status pill NOT shown. Source: global-search query, server-side, 250ms debounce. Select inserts the plain key text (no node) and closes.
- Does not fire inside URLs, code blocks, `{noformat}`, or after a letter (`XABC-1` token boundary rule). No `#` trigger.

### `:` emoticon autocomplete (INPUT-06, D-18)
- Opens on `:` + one letter at the start of a word (line start or after whitespace). Never after a digit (`10:30`), never inside a URL (`http:`), never in code blocks.
- Row: 20px glyph (rendered like WikiRenderer emoticon), name (12px), wiki token right-aligned (`:smile:`-style, 12px mono muted). Max 6 rows shown before scroll. Filter is prefix-first then substring on name and token.
- Select replaces `:query` with the emoticon node and a trailing space is NOT added. Typed `:)` and `(y)` keep converting through input rules (the popover must not intercept `:)` since `)` is not a letter).
- No match: popover closes silently (no empty row) and the typed text remains literal.
- Only `JIRA_EMOTICON_MAP`; no Unicode emoji, no skin-tone or category tabs.

### `/` slash menu (BLOCK-05, D-16, D-17)
- Trigger: `/` at start of line or after a space; not in URLs/paths, code blocks, or table header-less raw atoms. Query filters as typed; no match for the query closes the menu and leaves a literal `/`.
- Content (12px label headings, 600): "Recent" (last 3 used, persisted in the settings store; hidden when none and while a query is typed), "Text" (Paragraph, Heading 1 to 6, Quote, Bullet list, Numbered list), "Blocks" (Table, Code block, Noformat, Panel, Info, Note, Warning, Tip, Horizontal rule; data from `insert-items.ts`, single source), "Insert" (Mention, Attachment or image, Emoticon).
- Row: 16px lucide icon (same icon as toolbar Insert menu for the same item), label 12px, optional shortcut hint right-aligned muted (e.g. `# ` for lists are NOT shown; only existing registered shortcuts).
- Mention/Emoticon rows insert the trigger char (`@`, `:`) and open that popover. Attachment row opens the attachment picker (below). Table inserts the default 3x3 header-on table directly (the 6x6 grid picker stays toolbar-only).
- Selecting deletes the `/query` text first, then applies the block; a single undo reverts both.

### Compact host: bubble menu and footer (INPUT-07)
- `compact` preset replaces the 98 fixed toolbar with: (1) a selection bubble, (2) a slim footer row. `full` is unchanged and gets no bubble. Fixed toolbar and bubble are never both visible.
- Bubble contents: Bold, Italic, Underline, Strikethrough, Monospace | Link | Colour. Appears on non-empty text selection in rich mode, after the pointer/keys settle (150ms), hides on collapse, on scroll out of view, in code blocks, and while a suggestion popover is open. Tooltips as in 98 ("Bold ⌘B" etc.). Link and Colour reuse the 98 popovers, portaled, anchored to the bubble.
- Esc with the bubble visible collapses/hides the bubble first (selection retained), consuming the event.
- Footer row (left to right): Attach (paperclip), Mention (`@` icon), Emoticon (smile), flexible space, Rich|Source toggle (98 control). Lists, quote, table and block inserts are reached through `/`. Footer buttons: ghost, 28px, tooltips "Attach file", "Mention someone", "Emoticon". Row never wraps; below `@[320px]` the Emoticon button is dropped, then Mention (they stay reachable by typing `@`/`:`).
- Source mode in compact: bubble is hidden; footer row stays (Attach, Mention, Emoticon insert markup at the textarea caret; Rich|Source toggle visible).
- Focus returns to the editor after any footer or bubble action (WKWebView caret quirk from 98 UAT).

### Attachment picker (INPUT-02, D-05)
- Reuse the existing picker from DescriptionEditor/CommentComposer (popover, portaled). Choosing an image-type attachment inserts an `image` node; any other inserts an `attachment` chip. Inserted at the caret, caret placed after the node.
- Embedded image display: as WikiRenderer (respects `|thumbnail`, `|width=`, otherwise capped to column width). Click selects the node (`ring-1 ring-ring`) and does not open the lightbox. Delete/Backspace removes it.

### Paste and drop uploads (INPUT-03, D-06..D-11)
- Paste or drop of one or many files inserts one placeholder chip per file, in order, at the caret (drop: at the drop position resolved from `posAtCoords`; a 2px `--ring` drop-cursor line shows while dragging over the editor; the frame shows `ring-1 ring-ring` while a file drag is over it).
- Placeholder chip: filename (12px, truncate to 160px) + 12px spinner, `aria-busy`. Not selectable, not emitted to wiki (serialiser drops it). Typing is never blocked; the chip is an inline atom that moves with edits.
- Success: chip becomes `image` node (`!name!`) for images (extension classification for generic MIME) or `attachment` chip (`[^name]`) otherwise. Files processed in order; each resolves independently.
- Failure: chip removed; an inline error line appears directly under the editor content (inside the frame, above the footer row in compact): `AlertCircle` 12px + text, `text-destructive` 12px, a quiet ghost-xs "Dismiss" button at the right. Multiple failures stack up to 3 lines then summarise ("and 2 more files failed to upload."). Auto-clears on the next successful paste/drop.
- Staged create-flow: image shows a real preview from the local file immediately (data: URL preferred, blob: only if verified in WKWebView; never blank), the file also appears in the existing staged-files strip, markup keeps the filename. No spinner (nothing uploading yet); a staged embed has no placeholder state.
- Clipboard image without name: `image-YYYYMMDD-HHMMSS.png` (extension from MIME).
- Source mode: pasted files upload (or stage) and insert `!name!` / `[^name]` at the textarea caret; same error line.
- Tauri: `dragDropEnabled: false` so DOM drop events arrive; host `stopPropagation` against the AttachmentsSection drop zone preserved. Manual WKWebView drag/drop and caret check is required UAT (success criterion 5).

### Removing an embed (D-10)
- Deleting an image/attachment embed of a file uploaded this session (and not referenced elsewhere in the text, nor cheaply known in description/comments) shows one toast, 6s, bottom of window per existing toast placement: "Also delete attachment?" with action "Delete" and auto-dismiss otherwise. One toast at a time (replace, don't stack). Nothing happens on dismiss. Undo (Cmd+Z) of the embed removal dismisses the toast.
- Staged embed removal: no toast; the file stays in the staged strip.

### Paste handling (INPUT-04, D-12..D-15)
- Wiki-looking plain text: parsed into rich nodes; no visible UI beyond content. One Cmd+Z restores the literal pasted text. Non-wiki text pastes as plain paragraphs.
- HTML paste: mapped per D-13/D-14; no confirmation UI, no paste-options popup. Remote images that cannot be fetched fall back to a plain link to the image URL (never blocks paste).
- Cmd+Shift+V: plain-text paste. Registered in `src/lib/shortcuts.ts` as "Paste as plain text" `⌘⇧V` (also shows in the ⌘/ panel).
- Paste of a lone URL over a selection still links it (98 behaviour wins over wiki heuristic).

### Keyboard additions (registered in `src/lib/shortcuts.ts`)
Paste as plain text `⌘⇧V`. Trigger characters `@`, `/`, `:` are documented in the panel as "Mention @", "Insert menu /", "Emoticon :" (informational rows, no binding). Global hotkeys continue to ignore events whose target is contenteditable.

### Dev-tools "Editor" tab additions
Extend the 98 tab; no new layout. Add a "Host context" control row: project key input (default placeholder `DEMO`), "Staged mode" switch (create-flow simulation) and an upload outcome switch (Succeed | Fail | Slow 3s) driving a stub `onUploadFiles`. Placeholder-only fixtures for paste samples (Word, web, Jira HTML) are listed as a SearchableSelect "Paste sample" that dispatches into the editor. Caption "Local only. Never saved."

| Slash group headings | "Recent", "Text", "Blocks", "Insert" |
| Shortcut row | "Paste as plain text" |
| Unresolved mention tooltip | "{username}" (raw) |

Destructive actions in this phase: (1) deleting an uploaded attachment via the toast (confirmation = explicit "Delete" action on a time-limited toast, defaults to keeping the file); (2) deleting an embed node (reversible by Cmd+Z, no confirmation). Nothing else is irreversible.
