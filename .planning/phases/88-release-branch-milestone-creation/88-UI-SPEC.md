# Phase 88 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase adds **no new visual system** — it extends an existing, mature design system (Phase 87's `release-detail/` folder + `ReleasesTab.tsx`) with two dialogs, two sidebar status rows, and a per-row list indicator. Every value below is taken directly from code already shipping in this codebase; there are no open typography/color/spacing questions for this phase.

## Typography

Matches the exact scale already used in `ReleaseDetailSidebar.tsx` and `ReleasesTab.tsx`. Do not introduce a third size.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / row label | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label / meta / badge text | 12px (`text-xs`) | 400 (regular) | 1.5 |
| Emphasis (row title, active field) | 14px (`text-sm`) | 500 (`font-medium`) | 1.5 |
| Dialog title | 16px (browser default `DialogTitle`, per `ui/dialog.tsx`) | 600 (semibold, component default) | 1.2 |

Only two weights are used anywhere in this phase's surfaces: 400 (regular body/meta) and 500/600 (`font-medium`/dialog-title semibold — treat as the single "emphasis" weight tier). Badge text is always `text-xs font-medium` (baked into the `Badge` primitive — do not override).

## Color

This project uses OKLCH CSS-variable semantic tokens (light/dark pairs in `src/index.css`), not fixed hex values. Reference by token name, not hex.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--foreground` | Page/sidebar/dialog background and default text |
| Secondary (30%) | `--card`, `--muted`, `--border` | Sidebar container border, `hover:bg-muted/50` row hover, dialog surfaces |
| Accent (10%) | `--primary` | Reserved for: the primary "Create branch" / "Create milestone" confirm button, and clickable GitLab links (`text-primary hover:underline`, matching the existing `gitlab-link-exact` pattern in `ReleaseDetailSidebar.tsx`/`ReleasesTab.tsx`) |
| Destructive | `--destructive` | Not used by this phase — there are no destructive actions (branch/milestone creation only; no delete/edit) |

Additional **status tint colors already established** in this codebase and reused verbatim (not new tokens — Tailwind utility classes used directly in `ReleaseDetailSidebar.tsx`):

| State | Class | Usage |
|-------|-------|-------|
| Missing / warning | `text-orange-600 dark:text-orange-400` + `AlertTriangle` icon (size-3) | "No milestone matched" pattern (`ReleaseDetailSidebar.tsx:135`) — reuse identically for "No release branch" / "No GitLab milestone" rows (D-20) and for the `ReleasesTab` row icon (D-19) |
| Success / matched | `text-green-600 dark:text-green-400` + `Check` icon (size-3) | Branch/milestone exists, confirmed state |
| Muted / loading / unavailable | `text-muted-foreground` | "Loading…", "—" placeholders |

Badge tones (from `Badge` component's `tone` prop, `lib/statusStyles.ts` `CHIP_TONE_CLASS`) already cover: `green`, `amber`, `red`, `blue`, `orange`, `muted`. This phase does not need a new tone — the orange/AlertTriangle text pattern (not a Badge) is the correct precedent per D-19 ("icon with tooltip, not a text badge").

Accent reserved for: primary dialog confirm buttons (Button default variant), GitLab external-link text. Never apply `--primary` to the missing-state indicator (that stays orange/muted per the warning-tint convention).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Branch — missing indicator (sidebar row) | Icon: `AlertTriangle`. Row label follows `MetaRow` pattern: label "Release Branch", value `<AlertTriangle className="size-3" /> No release branch` in orange, exactly mirroring the existing "No milestone matched" row |
| Branch — missing indicator (list row tooltip, D-19) | Tooltip text: **"No release branch"** |
| Branch — blocked-on-milestone state (D-10) | Value text: **"Create the milestone first"** in muted-foreground, no icon, Create button disabled |
| Branch — unresolvable title state (D-11) | Value text: **"Branch name can't be derived from this milestone title"** in orange w/ AlertTriangle, Create button disabled |
| Branch — create button (row-level, sidebar) | **"Create branch"** — opens confirm dialog |
| Branch — confirm dialog title | **"Create release branch"** |
| Branch — confirm dialog description | Create <code className="font-mono font-medium text-foreground">release/&#123;version&#125;</code> off <span className="font-medium text-foreground">&#123;default_branch&#125;</span>? — mirrors `ConfirmSprintMoveDialog`'s inline-emphasis sentence pattern exactly |
| Branch — confirm dialog primary action | **"Create branch"** (idle) / **"Creating…"** (pending) — matches `isPending ? 'Moving...' : 'Confirm'` convention (ellipsis + present participle) |
| Branch — confirm dialog cancel | **"Cancel"** |
| Branch — creation failure (inside dialog, D-16) | Show GitLab's `message` body verbatim beneath the description, dialog stays open. No custom wrapper copy needed beyond a small "Couldn't create branch:" prefix label if the raw message alone is unclear |
| Milestone — missing indicator (sidebar row) | Reuses the existing `IssuesSection.tsx:64` "No GitLab milestone matched" alert as-is (D-20) — **do not** write new copy for this; it is out of scope to change |
| Milestone — missing indicator (list row tooltip, D-19) | Tooltip text: **"No GitLab milestone"** |
| Milestone — create button | **"Create milestone"** |
| Milestone — confirm dialog title | **"Create GitLab milestone"** |
| Milestone — confirm dialog description | Short explanatory line: "Create a milestone for this release. Recent milestones are listed below for reference." |
| Milestone — reference list label | **"Recent milestones"** (small muted label above the read-only list, per D-03) |
| Milestone — title input label | **"Milestone title"** with helper text **"Format: X.Y.Z (DD.MM.YYYY)"** shown persistently beneath the field (not just on error) |
| Milestone — title input format error | **"Title must match X.Y.Z (DD.MM.YYYY), e.g. 33.5.0 (21.07.2026)"** — shown inline below the field, submit disabled while invalid |
| Milestone — duplicate detected (client-side, D-05/D-07) | **"A milestone named '&#123;title&#125;' already exists in this project."** — shown inline below the field, submit disabled while a match exists in the windowed+ancestor-filtered list |
| Milestone — confirm dialog primary action | **"Create milestone"** (idle) / **"Creating…"** (pending) |
| Milestone — confirm dialog cancel | **"Cancel"** |
| Milestone — creation failure (server-side duplicate or other, D-08/D-16) | Show GitLab's `message` body verbatim beneath the field, dialog stays open |
| Destructive confirmation | Not applicable — this phase has no destructive actions (create-only; no delete/edit paths) |

All copy is sentence case, matches the terse/direct tone already established in `ConfirmSprintMoveDialog` and `BoardResolutionDialog` (no exclamation marks, no marketing voice, states the action and its target plainly).

## Component/Placement Inventory (phase-specific, non-template addendum)

For the planner/executor — where each new UI element lands, per CONTEXT.md D-17…D-20:

| Element | Location | New component? |
|---------|----------|----------------|
| Branch status + Create action | New `MetaRow` entries in `ReleaseDetailSidebar.tsx`, placed near the existing "GitLab Milestone" row | No new file required if kept inline; extract a small presentational subcomponent only if the JSX exceeds ~40 lines (matches Phase 87 D-08 discretion) |
| Milestone status + Create action | New `MetaRow` entry in `ReleaseDetailSidebar.tsx`, adjacent to branch row | Same as above |
| Create-branch confirm dialog | New file, e.g. `release-detail/CreateBranchDialog.tsx` | Yes — copy `ConfirmSprintMoveDialog`'s structure (controlled `open`/`onOpenChange`, `showCloseButton={false}`) |
| Create-milestone dialog (with input + reference list) | New file, e.g. `release-detail/CreateMilestoneDialog.tsx` | Yes — copy `BoardResolutionDialog`'s structure (controlled state, `showCloseButton={false}`, inline validation, disabled-until-valid primary button) |
| Releases-list row indicator | Inline addition inside the existing row `<button>` in `ReleasesTab.tsx`, next to the existing GitLab-match indicator block (`shrink-0` flex group) | No new file — reuse the orange `AlertTriangle` + tooltip pattern already established |

**Icon sizing:** all status icons in this phase use `size-3` (12px), matching every existing icon in `ReleaseDetailSidebar.tsx`/`ReleasesTab.tsx`. Never introduce a larger icon size for these indicators — the rows are dense and consistency with existing MetaRow icons is required.

**Button sizing:** inline "Create branch"/"Create milestone" trigger buttons in the sidebar use `variant="ghost" size="sm"` matching the existing "Edit" button (`ReleaseDetailSidebar.tsx:67-75`) unless the row is disabled (D-10/D-11), in which case render the button with `disabled` and a `title` attribute carrying the disabled reason (no separate tooltip component needed — native `title` matches the codebase's existing lightweight-tooltip convention, e.g. `title={\`Fuzzy match: ${...}\`}` at line 118).
