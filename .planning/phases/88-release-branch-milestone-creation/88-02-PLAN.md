| Boundary | Description |
|----------|-------------|
| app → GitLab REST API | Every call crosses the network carrying the PAT; derived branch names and user-typed milestone titles are interpolated into URLs and request bodies |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-88-INJ | Tampering | `fetchBranch` URL path segment (`gitlab.ts`) | mitigate | `encodeURIComponent(branchName)` on the branch-name path segment, matching the existing convention at `gitlab.ts:658`. Without it the `/` in `release/33.5.0` splits into two path segments and the request targets the wrong resource; `..` segments in a hostile title would traverse. Asserted by a `release%2F33.5.0` URL test. |
| T-88-INJ-BODY | Tampering | `createBranch` / `createMilestone` request bodies | mitigate | Both writes send values via `JSON.stringify` in the request body (never string-interpolated into the URL), so no encoding ambiguity exists. Pre-flight validation is Plan 88-01's `isValidGitRefName` / `MILESTONE_TITLE_FORMAT_RE`; GitLab's server-side validation remains the authority (D-08). |
| T-88-ID | Information Disclosure | PAT in devtools/instrumentation for the two new write calls | transfer | Already mitigated by `apiFetch`'s existing `PRIVATE-TOKEN` → `[REDACTED]` header redaction (`apiFetch.ts:85`). Both new writes and all three new reads go through `apiFetch('gitlab', ...)`; raw `fetch` would bypass redaction and is a defect (D-21/D-12a). Asserted by a no-raw-fetch grep. |
| T-88-ERR | Information Disclosure | GitLab error bodies rendered verbatim to the user | accept | The error body is GitLab's own validation message for a resource the PAT holder already has access to; it discloses nothing beyond the user's existing authorization. Surfacing it verbatim is a deliberate requirement (D-08/D-16). |
| T-88-AUTH | Elevation of Privilege | 403 responses on write endpoints | accept | Permission/role gating is explicitly out of scope (team is all Developer+, per REQUIREMENTS.md Out of Scope + CONTEXT `<domain>`). | T-88-SC | Tampering | npm installs | accept | This plan installs zero packages (88-RESEARCH.md § Package Legitimacy Audit: not applicable). No `[ASSUMED]`/`[SUS]` packages, so no legitimacy checkpoint required. |
