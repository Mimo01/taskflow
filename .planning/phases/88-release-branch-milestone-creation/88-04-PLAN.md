<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → GitLab branches list endpoint | A search term is placed in the query string of a paginated read |
| GitLab branch names → React render | Branch names from GitLab are compared and (indirectly) surfaced in tooltips |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-88-INJ | Tampering | `fetchProjectBranches` search query-string parameter | mitigate | The search value is the fixed `RELEASE_BRANCH_PREFIX` constant (`release/`) and is `encodeURIComponent`-encoded by `fetchProjectBranches` (Plan 88-02). No user-supplied or GitLab-supplied string reaches the query string from this plan. |
| T-88-DOS | Denial of Service | Unbounded pagination in a list view | accept | `fetchProjectBranches` is filtered by `search=release/`, bounding the result set to release branches only (the explicit D-18 rejection of an unfiltered all-branches fetch). One request per project per 5-minute `staleTime`, not per row — the per-row alternative is the actual DoS-shaped risk and is prohibited here. |
| T-88-XSS | Tampering | `title` tooltip attributes and rendered branch names | accept | Tooltip strings are hardcoded literals from the UI-SPEC copy contract; branch names are rendered as React text children and escaped by default. No `dangerouslySetInnerHTML`. |
| T-88-ID | Information Disclosure | PAT used by the new branch query | transfer | The query calls `apiFetch('gitlab', ...)` via `gitlab.ts`; redaction is handled in `apiFetch.ts:85`. The token never enters a query key. |
| T-88-SC | Tampering | npm installs | accept | Zero packages installed by this plan (88-RESEARCH.md § Package Legitimacy Audit: not applicable). No legitimacy checkpoint required. |
</threat_model>
