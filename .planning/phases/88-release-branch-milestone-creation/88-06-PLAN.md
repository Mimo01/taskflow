<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user keyboard input → GitLab write body | The milestone title is free text typed by the user and sent verbatim as the `title` field |
| cached windowed milestone list → duplicate decision | A client-side authorization-free check gates the submit button |
| GitLab error body → dialog render | Server rejection text is rendered back verbatim |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-88-V5 | Tampering | `isValidMilestoneTitle` gating in `CreateMilestoneDialog.tsx` | mitigate | ASVS V5 input validation as defense-in-depth: the anchored `^\d+\.\d+\.\d+ \(\d{2}\.\d{2}\.\d{4}\)$` regex constrains the title to digits, dots, spaces and parentheses before submit — no control characters, markup, or unbounded free text can reach the write. GitLab's server-side validation remains the authority (D-08). |
