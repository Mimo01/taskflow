| md | 16px | Page horizontal padding (px-4), card padding |
| lg | 24px | Page header horizontal padding (px-6 = 24px) |
| xl | 32px | Section vertical separation |
| 2xl | 48px | Empty state top padding |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Page header uses `px-6 py-4` (24px / 16px) — matches `AioProjectOverviewPage` predecessor exactly.

- Individual pinned tabs: 36px tall (h-9) — locked by existing `PinnedTabStrip` implementation.

## Interaction Contracts

### Filter Chips

- Four chips: **Not Run**, **Pass**, **Fail**, **Blocked** (in this order, left to right).
- Default state: all four chips active (all runs shown).
- Click a chip: toggles that status on/off. OR logic — run list shows any run matching at least one active chip.
- Keyboard: `Space` / `Enter` toggles; `ArrowLeft` / `ArrowRight` moves focus between chips.
- `role="switch"` + `aria-checked` on each chip (matches `QuickFilterChipRow` pattern).
- If all chips are toggled off: show empty state "No runs match the selected filters."

Source: CONTEXT.md D-13; `QuickFilterChipRow.tsx` chip pattern.

### Pin / Unpin Button

- Placement: page header row, right-aligned relative to heading block.
- Label: **"Pin cycle"** when `isPinned(cycleKey) === false`; **"Unpin cycle"** when `isPinned(cycleKey) === true`.
- Component: `<Button variant="secondary" size="sm">`.
- No confirmation dialog — pin/unpin is reversible.
- On pin: call `togglePin(cycleKey)` + `setPinnedCycleMeta(cycleKey, { name: cycle.name, projectKey })`.
- On unpin: call `removePin(cycleKey)` + clear meta entry.

Source: CONTEXT.md D-08, D-18.

### Tab Click Routing

- Cycle tab click: if key matches `/CY-/` → `navigate('/aio-cycle/${meta.projectKey}/${key}')`.
- Issue tab click: existing `handleIssueClick(key, true)` path — unchanged.
- Right-click context menu: "Move to start", "Move to end", separator, "Unpin" (destructive). Same menu as existing issue tabs.

Source: CONTEXT.md D-06; `PinnedTabStrip.tsx` context menu.

### Defect Links

- Each defect renders as a `<NavLink>` to `/issue/${defectKey}` with `hover:underline` (matches cycle name link pattern in `AioProjectOverviewPage`).
- No external link — navigate within the app to the existing issue detail page.
- Deduplicated list (unique keys only across all runs with non-empty defects).

Source: CONTEXT.md D-15.

### Loading / Error / Empty States

| Scenario | Component | Trigger |
|----------|-----------|---------|
| Runs loading | `<AioCycleDetailSkeleton>` | `useDelayedLoading(isLoading)` — 200ms delay |
| Runs error | `<ErrorState onRetry={...} viewName="cycle detail">` | `isError && !data` |
| No runs | `<EmptyState icon={FlaskConical} title="No test runs found" subtitle="...">` | `data.length === 0` |
| Filters show no results | Inline message (no `EmptyState` component) | filtered array length === 0 |
| Defects section absent | Section hidden entirely | no runs have non-empty defects array |

Source: `AioProjectOverviewPage.tsx` state pattern; CONTEXT.md D-17.

## API Shape Decisions (D-10, D-11, D-14 Resolution)

These decisions affect `types.ts` updates the planner must spec.

### AioTestRun — confirmed additional fields

From AIO REST API docs (web research 2026-05-13):
- Test case name is exposed via a nested `testCase` object on the run response: `testCase.title` (string). This is NOT a flat `testCaseName` field.
- Run date: the run-level timestamp field is not confirmed from public docs. Executor must probe the live endpoint. Fallback: use `testCase.updatedDate` if no run-level date field exists. The planner should spec the `AioTestRun` interface update as conditional on executor probe.
- Defects: `defects` is a standard run field (confirmed by AIO Field Configurations docs). The run object carries a `defects` array containing Jira issue keys. **AIOC-03 remains in scope.**

Updated `AioTestRun` interface (to be added in types.ts):
```ts
export interface AioTestRun {
  id: string;
  status: string;           // "PASS" | "FAIL" | "NOT_EXECUTED" | "BLOCKED"
  testCaseKey: string;
  cycleKey: string;
  testCase?: {              // nested object — verify field names against live endpoint
    title: string;          // display name of the test case
    updatedDate?: string;   // ISO date string, fallback run date
  };
  defects?: string[];       // Jira issue keys, e.g. ["PROJ-42", "PROJ-99"]
  executedDate?: string;    // run-level date — verify field name against live endpoint
}
```

**D-11 resolution:** Use the `testCase` join branch — no separate `/testcase` endpoint fetch needed for display. The `testCase.title` field is available on the run response from `GET /rest/aio-tcms-api/1.0/project/{projectKey}/testcycle/{cycleKey}/testrun`.

**D-14 resolution:** Defects are inline on the run object (`defects?: string[]`). AIOC-03 is in scope. Defects section renders if any run has `defects` with length > 0.
