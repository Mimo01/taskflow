<objective>
Fix Gaps 1 and 2: the cycles page renders a flat list of all cycles and fires `CycleStatsCell` queries for every row simultaneously. This is both slow under real network latency and does not match the AIO hierarchy where cycles live inside folders/test-sets.

The fix replaces the flat table with an accordion grouped by folder (or status as fallback). Only the open folder's cycle rows render `<CycleStatsCell>` — collapsed folders render no stats queries. A probe step must confirm the raw folder field name before the UI is implemented.

User's explicit design constraint: "When there is the folder structure of cycles it only loads the current open folder, not everything. That makes it fast."

Purpose: Satisfies AION-03 performance requirement and folder-hierarchy UX expectation from Gap 1+2.
Output: Accordion-grouped cycles page, lazy stats per open folder, updated skeleton, passing tests.
</objective>

    function groupCyclesByFolder(cycles: AioCycle[]): Map<string, AioCycle[]> {
      const map = new Map<string, AioCycle[]>();
