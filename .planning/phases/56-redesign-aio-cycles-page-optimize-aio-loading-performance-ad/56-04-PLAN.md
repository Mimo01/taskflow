  <how-to-verify>
    Prerequisites:
    1. Start the dev server: `cd taskflow && npm run tauri dev`
    2. Make sure AIO is enabled in Settings → Integrations → AIO Test Management (toggle ON if not already)
    3. Select an AIO project in Settings → Integrations → AIO Project (this is needed because Phase 55 routes the sidebar to the configured project)
    4. Click "AIO Projects" in the sidebar — this should land on `AioProjectOverviewPage` for the configured project

    ---

    **A. Cycles page (AION-03) — progressive loading + perceived performance**

    1. Open dev tools Network tab. Filter to fetch/XHR.
    2. Hard-refresh the cycles page (Cmd+R or Ctrl+R).
    3. Observe — within ~200ms the page should render the cycle table with row skeletons in the Progress column. Network tab should show:
       - One `fetchAioCycles` call (or equivalent endpoint)
       - Then N `fetchAioTestRunsForCycle` calls firing in parallel (one per cycle row)
    4. Expected: cycle rows are visible and interactive BEFORE all stat queries complete. As each row's query resolves, the skeleton in its Progress column is replaced by a mini progress bar + counts text formatted `{N}P {N}F {N}B {N}N`.
    5. Visual check: progress bar uses the four colors (green-500 for pass, red-500 for fail, orange-400 for blocked, bg-muted for not-run). Bar height should be slim (h-1.5 = 6px).
    6. Hover a row → background tints `bg-muted/30`. No layout shift between skeleton and loaded state.
    7. Click a cycle name → navigates to the cycle detail page; the run stats query should be a CACHE HIT (Network tab shows no fresh fetchAioTestRunsForCycle call for that cycle).
    8. Navigate back to the cycles page → all rows render with stats from cache (no skeleton flash on second visit).

    ---

    **B. Cycle detail page (AIOC-03 + D-05..D-13) — tabs + enriched defects**

    1. From cycles page, click any cycle name to land on `AioCycleDetailPage`.
    2. Page header (cycle name + pin button) renders as before.
    3. **Progress section** (progress bar + counts row) is visible at the top, BELOW the breadcrumb header. This is OUTSIDE the tab content area.
    4. **Tab bar** appears immediately below the progress section with two triggers: `Executions` (active by default) and `Defects`.
    5. **Executions tab content:**
       - Filter chips toolbar (NOT_EXECUTED / PASS / FAIL / BLOCKED) is visible at the top of the Executions tab content area. Toggle each chip — clicked-off rows disappear from the table.
       - Run table shows Test Case | Status | Date columns as before.
       - Hover a row → background tints + cursor changes to pointer. NEW: the entire row is now clickable.
       - Click a run row → navigates to `/aio-cycle/{projectKey}/{cycleKey}/run/{run.id}`. Breadcrumb header on the run detail page should show a back trail entry for the cycle.
       - Click the breadcrumb back arrow on the run detail page → returns to the cycle detail page, Executions tab still active.
       - Focus a row via Tab key (it should be focusable), press Enter → same navigation. Press Space → same navigation.
    6. **Defects tab — populated case:**
       - Find a cycle that has at least one defect linked to a failed run (e.g. a recent FAIL cycle).
       - Click the `Defects` tab → tab bar updates active state, content area shows the defects table with columns Key | Title | Status | Triggered By.
       - Title column initially shows a small skeleton; within ~500ms it should resolve to the Jira issue summary.
       - Status chip shows the Jira status name (e.g. "Open", "In Progress") with the muted chip styling.
       - Triggered By column shows the test case key(s) from runs that linked this defect (e.g. "PROJ-TC-12" or comma-separated).
       - Click the defect key → navigates to `/issue/{key}` (existing issue detail page).
    7. **Defects tab — empty case:**
       - Open a cycle with NO defects (e.g. a PASS-only cycle).
       - Click the `Defects` tab → EmptyState appears: "No defects" / "No defects are linked to runs in this cycle." with the FlaskConical icon.

    ---

    **C. Token-flash-fire pitfall (D-15 / Pitfall 1) — verify the !tokenLoading guard**

    1. Open dev tools Network tab BEFORE first opening any AIO page in this session.
    2. Open `AioProjectOverviewPage` for the first time after a fresh app start.
    3. Expected: No 401 / 403 / "Couldn't load cycles" error flash on first paint. The page should go from skeleton → loaded data with no intermediate auth-error state.
    4. Same check for `AioCycleDetailPage` and `AioTestRunDetailPage`.

    ---

    **D. Graceful degradation for defect enrichment (Manual-only V2 from VALIDATION.md)**

    1. Find a cycle with a defect that links to a Jira issue you do NOT have permission to view (or a deleted issue key). If no such case exists in the live data, manually edit `taskflow/src/services/jira/issues.ts` `fetchJiraIssueByKey` temporarily to return `null` and reload — but undo before approving.
    2. Expected: The defect row still renders. Title cell shows the defect key as fallback (the `data?.fields.summary ?? defectKey` branch). Status cell shows `—`. Row does not crash, the table does not collapse, neighbor rows render correctly.

    ---

    **E. Skeleton no-jump check (Pitfall 2)**

    1. In dev tools, throttle network to "Slow 3G".
    2. Reload the cycles page. Observe the initial skeleton (AioCyclesSkeleton).
    3. Expected: When real data arrives, the row positions DO NOT JUMP. Each skeleton row should match the dimensions and column alignment of its loaded counterpart (Key | Name | Status | Progress).

    ---

    **F. Regression smoke check**

    1. Pin a cycle from the cycle detail page → pinned tab appears in header (Phase 53 behavior — should not regress).
    2. Unpin → tab disappears.
    3. Switch tabs (Executions ↔ Defects) several times → no flicker, no state loss for the filter chips (chips stay where they are when you come back to Executions).
    4. Navigate Settings → Integrations → AIO Test Management toggle OFF → sidebar AIO Projects entry should hide (Phase 55 behavior, should not regress).
    5. Toggle AIO back ON → entry reappears.
