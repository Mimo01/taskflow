## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React component ↔ AIO API | Each `CycleStatsCell` fires `fetchAioTestRunsForCycle(baseUrl, token, projectKey, cycleKey)` via authenticated apiFetch; `cycle.key` originates from the trusted `fetchAioCycles` response, not user input |
| Render performance ↔ data fan-out | N cycles → N parallel useQuery calls; cap by waiting for AIO API's intrinsic rate limit (TanStack Query handles batching) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-56-02-01 | Information Disclosure | `CycleStatsCell` props (token) | mitigate | Token is prop-drilled from page component, not stored in DOM attributes; React renders props as JS props, not HTML — token is not serialized to data-* or aria-* attributes. Verified by absence of `token` in any JSX attribute on the component. |
| T-56-02-02 | Tampering | `cycle.key` used in URL path of fetchAioTestRunsForCycle | accept | `cycle.key` comes from the trusted AIO API response (`fetchAioCycles`); the underlying `apiFetch` already URL-encodes path segments. No new injection surface. |
| T-56-02-03 | Denial of Service | N parallel useQuery calls on cycle list | mitigate | TanStack Query deduplicates identical query keys and batches via microtask queue; cycle keys are unique. Browser HTTP/2 multiplexing handles parallel fetches against same host. No additional throttling required for typical AIO project (<100 cycles). |
| T-56-02-04 | Information Disclosure | Run data in dev tools cache | accept | TanStack Query devtools show fetched run data in development; this matches existing AIO behavior on cycle detail page. No new exposure. |
</threat_model>
