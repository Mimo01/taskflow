### SaveFilterDialog

- Trigger: "Save Filter" button in UnifiedFilterBar (visible when filters are active)
- Fields: Name (Input, required), Description (Textarea, optional)
- JQL is auto-populated from current active filters (read-only display, `text-muted-foreground`, `font-mono text-xs`)
- Actions: "Cancel" (ghost variant), "Save Filter" (default variant)
- Loading state: "Save Filter" button shows spinner, disabled during save
- Success: Dialog closes, toast notification "Filter saved", filter appears in sidebar list

### EditFilterDialog

- Trigger: "Edit" item in context menu on SavedFilterList item
- Fields: Name (Input, pre-filled), JQL (Textarea, pre-filled, editable), Description (Textarea, pre-filled)
- Actions: "Cancel" (ghost variant), "Update Filter" (default variant)
- Loading state: "Update Filter" button shows spinner, disabled during update

### SavedFilterList

- Location: Sidebar, below sectioned nav items, above bottom settings area
- Header: "Saved Filters" label (11px/500, uppercase, `text-muted-foreground`) with chevron toggle for collapse
- Items: Bookmark icon (size-3.5) + filter name (14px/400), full-width clickable
- Active state: `bg-sidebar-accent text-sidebar-accent-foreground` on the active filter item
- Hover state: `bg-sidebar-accent/50` on non-active items
- Context menu (right-click): "Edit" (Pencil icon), "Delete" (Trash2 icon, `text-destructive`)
- Empty state: "No saved filters" in `text-muted-foreground` at 12px
- Data fetching: `useQuery` in Sidebar.tsx syncs to `useSavedFilterStore`

### UnifiedFilterBar Addition

- "Save Filter" button: `variant="ghost" size="xs"`, BookmarkPlus icon (size-3), label "Save Filter" at 11px
- Visible only when `hasActiveFilters` is true and user is not in the inline save-as-quickfilter flow
- Position: after existing filter action buttons in the bar

### CommandPalette Addition

- New CommandGroup "Saved Filters" with Bookmark icon per item
- Each item shows filter name, triggers `setActiveFilter` and navigates to sprint board
- Group hidden when savedFilters array is empty

## Interaction States

### Save Flow
1. User applies filters on sprint board (quick filters, labels, text search)
2. "Save Filter" ghost button appears in UnifiedFilterBar
3. User clicks "Save Filter" -- SaveFilterDialog opens
4. JQL preview shown (read-only) so user knows what they are saving
5. User enters name (required) and optional description
6. User clicks "Save Filter" -- button shows loading spinner
7. On success: dialog closes, toast "Filter saved", filter appears in SavedFilterList
8. On error: inline error message below form, dialog stays open

### Execute Flow
1. User clicks a filter in SavedFilterList (sidebar) or CommandPalette
2. Filter becomes active (highlighted in sidebar list)
3. Sprint board re-filters using the saved JQL
4. Clicking the active filter again deactivates it (clears filter)

### Edit Flow
1. User right-clicks a filter in SavedFilterList
2. Context menu shows "Edit" and "Delete"
3. User selects "Edit" -- EditFilterDialog opens with pre-filled values
4. User modifies fields and clicks "Update Filter"
5. On success: dialog closes, toast "Filter updated", list refreshes

### Delete Flow
1. User right-clicks a filter, selects "Delete"
2. Confirmation popover appears anchored to the context menu item
3. Popover shows: "Delete [filter name]? This removes it from Jira. This cannot be undone."
4. User clicks "Delete" (destructive variant) or "Cancel"
5. On confirm: filter removed from list, toast "Filter deleted"
6. On error: toast "Could not delete filter. Try again."
