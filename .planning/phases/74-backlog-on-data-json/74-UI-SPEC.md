# Phase 74 — UI Design Contract

> Visual and interaction contract for Phase 74 (Backlog on `data.json`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase character:** This is primarily a **data-layer rewrite** of `BacklogPage.tsx`. Visual surface change is minimal and follows the precedent set by Phase 73's "Reload board" toolbar action on `SprintBoardTab.tsx`. UI deltas in this phase:

1. New "Reload backlog" toolbar action (replaces per-section ad-hoc refresh callbacks).
2. Removal of the label filter chip/dropdown on the backlog (D-05a — `GhIssue` carries no `labels[]`).
3. Removal of subtask count chip on backlog rows if currently rendered (D-05b).
4. Removal of `flagged` indicator on backlog rows if currently rendered (D-05c).

All other backlog UI (virtualized list, sprint sections, epic/assignee filter chips, move-to-sprint, create story, drag-to-rank) is preserved verbatim from the existing implementation. Adopt all existing tokens, components, and patterns already established in the codebase. Do not introduce new visual primitives.

## Interaction Contract — "Reload backlog" toolbar action

Mirrors `SprintBoardTab.tsx:776-808, 1198-1203` precedent.

- **Placement:** In the backlog toolbar, in the same relative slot as Phase 73's "Reload board" lives on SprintBoardTab. Single icon-button (Lucide `RefreshCw` — same as Phase 73).
- **State:** `idle | reloading | success | error`. While `reloading`, button is disabled and icon spins (Tailwind `animate-spin`).
- **A11y:** `aria-label="Reload backlog"`, `title="Reload backlog"`, status text rendered into an `aria-live="polite"` region. Status auto-clears after 3000ms (matches Phase 73 timeout).
- **Invalidations on click (per D-07):**
  - `['gh-backlog', boardId]`
  - `['jira-epics-basic', projectKey]`
  - `['jira-statuses']`
- **Removal of legacy refresh affordances:** Any pre-existing per-section refresh buttons (sprint-list refresh, story refresh) are removed in favor of this single control (D-07a). Executor inventories existing refresh buttons in BacklogPage during planning.
