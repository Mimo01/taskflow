<objective>
Fix the Releases tab showing versions from the wrong Jira project by guarding against stale numeric project IDs persisted in the Tauri Store, and rename a misleading parameter to prevent future regression.

Purpose: UAT Test 3 failed — user sees releases but they are from the wrong project. Root cause: `activeJiraProject` in `auth.json` contains a numeric ID string (e.g. `"12345"`) from a prior app version. `fetchFixVersions` passes this to `GET /rest/api/2/version?projectKey=12345` and Jira silently returns versions for that numeric project ID, which does not match the project the user sees selected in the UI (which resolves by key, e.g. `"PROJ"`).

Output: auth.store.ts gains an `onRehydrateStorage` hook that clears any persisted numeric-only `activeJiraProject` value. TokenSection.tsx gets a parameter rename from `projectId` to `projectKey` to prevent future confusion. User will see "Select project..." after clearing, select their project, and Releases will show the correct data.
</objective>
