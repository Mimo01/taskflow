## Color

Derived from `src/index.css` CSS custom properties and existing board Tailwind usage.

| Role | Tailwind token | Light value | Dark value | Usage |
|------|---------------|-------------|------------|-------|
| Dominant (60%) | `bg-background` | oklch(1 0 0) white | oklch(0.145 0 0) near-black | Board surface, scroll area |
| Secondary (30%) | `bg-card` / `bg-muted/10` | oklch(1 0 0) / near-white | oklch(0.205 0 0) / near-black | Card surfaces, swimlane rows |
| Accent (10%) | `bg-accent/50` | oklch(0.97 0 0) @ 50% | oklch(0.269 0 0) @ 50% | Card hover, drop-zone hover |
| Destructive | `text-destructive` | oklch(0.577 0.245 27.325) | same | Transition error text below card |

**Accent reserved for:** card hover (`hover:bg-accent/50`), active drop-zone highlight (`bg-accent/60`), drop-zone hover ring. Never used for neutral surfaces or inactive drop zones.

**Drop-zone state colors (this phase):**

| State | Background | Border | Label color |
|-------|-----------|--------|-------------|
| Idle (drag active, not hovered) | `bg-muted/20` | `border border-border/30 border-dashed` | `text-muted-foreground` |
| Hover / DragOver | `bg-accent/60` | `border border-border ring-1 ring-ring/30` | `text-foreground` |
| Invalid column (dimmed) | `bg-background` | existing border — unchanged | `text-muted-foreground` — N/A (no zones shown) |

**Invalid-column dim treatment (D-06):**
- Apply `opacity-40` to the entire column cell `div` (the `flex-1 min-w-0` wrapper) when dragging and that column has zero reachable+allowed transitions from the dragged card's current status.
- `opacity-40` is the contract value — visible enough to see the column exists, clearly "not here". Do NOT use `opacity-50` or lower.
- `pointer-events-none` is NOT applied — the column still receives the drop event and silently rejects it (snap-back). `onDragOver` / collision detection handles rejection.
- Transition: `transition-opacity duration-150` so dim appears smoothly at drag start.

**DragOverlay ghost card (D-12, this phase):**
- Appearance: full `TaskCard` clone, `opacity-100`, `shadow-lg`, `border border-border`, `bg-card`
- Identical to the P78 BacklogPage ghost pattern (`border border-border bg-background shadow-lg`) adapted to card surface (`bg-card`).
- No dim, no color change, no transform. `dropAnimation={null}` — ghost disappears instantly on drop.

## Interaction States

### Column split at drag start (D-01 / D-02)

- **Multi-status column (≥2 valid+allowed transitions):** The column cell replaces its normal card list with a vertical stack of labelled drop-zone boxes. Each box is a full-width `div` with a centred label showing the transition name (D-03).
- **Single-transition column:** Column remains whole. No split. The entire column cell is the drop target. No label overlay is shown — existing card layout unchanged.
- **Invalid column (0 transitions):** Column remains whole. `opacity-40 transition-opacity duration-150` applied to the column cell wrapper. Drop is silently rejected; card snaps back.
- **Own column (card's current category):** Shown whole and undimmed. Dropping a card back onto its own column is a no-op (no transition fired). Silent snap-back, no error.

### Drop-zone within a split column

- **Minimum height:** `min-h-[80px]` — each zone must be tappable and visually distinct.
- **Idle state:** `bg-muted/20 border border-dashed border-border/30 rounded-md flex items-center justify-center`
- **DragOver (hover) state:** `bg-accent/60 border border-border rounded-md ring-1 ring-ring/30 flex items-center justify-center` — ring replaces dashed border on hover.
- **Label:** `text-xs font-semibold text-muted-foreground` (idle) / `text-foreground` (hover)
- **Transition name casing:** As returned by the Jira API — no forced transformation. Capitalisation is Jira's responsibility.

### Ghost overlay (DragOverlay)

- Portaled to `boardRef` at the same z-level as `stickyOverlayRef` (z-[9]), following D-13.
- `dropAnimation={null}` — no float-back animation.
- Ghost is a TaskCard rendered with the card's existing props. No special overlay-only styling beyond `shadow-lg border border-border`.
- `touch-action: none` applied to all draggable card elements (D-13).

### Inline error on failed API transition (D-10)

- Reuse `cardErrors: Map<string,string>` — same path as `handleTransition` in `SprintBoardTab.tsx` line 868.
- Error string rendered by existing `TaskCard` — `{transitionError && <p className="text-xs text-destructive px-1">{transitionError}</p>}` (TaskCard.tsx line 335).
- Error appears BELOW the card, inline, no banner, no toast. Cleared on next successful transition attempt for that card.
- Error copy: see Copywriting Contract section.

## Accessibility Notes

- Drag-and-drop is pointer-only for this phase (D-12 — `PointerSensor`). No `KeyboardSensor` (out of scope per CONTEXT.md deferred).
- `touch-action: none` on all draggable card elements (D-13) is required for Tauri/WebView2 pointer event compatibility.
- `DragOverlay` ghost has `aria-hidden="true"` to avoid screen reader confusion.
- Invalid-column dim (`opacity-40`) meets WCAG 1.4.3 contrast for the column's existing visible content against the board background (muted-foreground on background exceeds 4.5:1 before dimming; post-dim at 40% opacity the content is visually de-emphasized but the dim communicates state to sighted users only — keyboard path is right-click StatusPopover which is unchanged).
- Transition error `text-destructive` (`oklch(0.577 0.245 27.325)`) against `bg-card` (white) is approximately 4.6:1 — passes WCAG AA for normal text (12px bold equivalent). Source: REQUIREMENTS.md VISUAL-05 precedent for WCAG ≥ 3:1.
