<objective>
Close UAT gap 4 (MAJOR, test 7). With the Full preset at 360px the toolbar clips after "Insert": ⋯ More and the Rich/Source toggle are pushed out of view.

Root cause: the overflow list is right. At 360 all six Full items overflow, so More IS rendered. But the items left inline (text-style, Bold, Italic, Underline, two Dividers, Bullet, Numbered, "+ Insert" with its label) plus More and ModeToggle are wider than 360px. Everything sits in one `flex-nowrap` row with no shrinking region, so the tail (More, ModeToggle) is what gets clipped. Compact fits only because it has fewer inline items.

Fix (two parts, both needed):
1. Config: below 420/400px the Full preset also moves Numbered, Bullet and Underline into ⋯ More. That leaves exactly the UI-SPEC "Always visible" set: text-style, Bold, Italic, + Insert, ⋯, Rich|Source. Below 400px the "+ Insert" label text is hidden (icon-only; aria-label/title stay "Insert"). In source mode the preview toggle hides below 35rem, where SourceView already auto-hides the preview (`@max-[35rem]:hidden`, D-05).
2. Layout: split the row into a formatting-item region `data-toolbar-items` (`flex min-w-0 shrink items-center gap-1 overflow-hidden`), which is the only part that can shrink or clip, followed by flex-none Insert, More, a flex-1 spacer, the preview toggle and ModeToggle. Even if the measured breakpoints are slightly off in WebKit, the mode toggle and More can never be clipped. Wide-width visual order is unchanged.

Project memory notes: Tailwind @container variants never style the container element itself. The `@container` is the WikiEditor outer div, and the toolbar is a descendant, so the INLINE_CLASS approach is valid. Don't use `@[N]:not-sr-only` for the Insert label (it resets white-space/overflow). Use `hidden @[25rem]:inline` on a span.
</objective>
