## Row & sub-line anatomy

### Q1 — Underlying markup for the unified primary table

| Option | Description | Selected |
|--------|-------------|----------|
| div + flex rows | Follow MrDriftSection's shape; per-row sizing works; P90 28px cells port over untouched; no native table semantics | ✓ |
| One `<table>`, MR as sub-`<tr>` | Native semantics and free column alignment; but table layout syncs widths across all rows (the "everything truncates at the same point" problem) | |
| Table for tasks, nested block for MRs | Clean task columns + independent MR sizing; but BR/MS no longer align with the task row — two stacked grids | |

**User's choice:** div + flex rows
**Notes:** Directly consistent with the recorded project lesson on table-vs-flex row sizing.

### Q2 — Alignment of MR sub-line fields against task columns

| Option | Description | Selected |
|--------|-------------|----------|
| Shared column grid | Same span widths for both line types; !iid in key column, title in summary, author in assignee, state in status, BR/MS in gutter | ✓ |
| Own widths, gutter aligned only | MR lines tuned for MR content, only BR/MS guaranteed aligned; loses vertical columns for author/badge | |
| Indented block, no column reuse | Visually distinct block, no echo of task columns; least "one table" feel | |

**User's choice:** Shared column grid

### Q3 — Visual distinction between an MR sub-line and its task row

| Option | Description | Selected |
|--------|-------------|----------|
| Indent + muted, no borders | Separators mark task boundaries only; task + its MRs read as one block | ✓ |
| Indent + tint band | bg-muted/20 band; busy over a long release, fights hover states | |
| Indent + tree connector | ├/└ glyphs in the gutter; box-drawing appears nowhere else in the app | |

**User's choice:** Indent + muted, no borders

### Q4 — Hover/click scope with MR lines nested under tasks

| Option | Description | Selected |
|--------|-------------|----------|
| Task row clickable, MR line not | Task row keeps click-anywhere peek; MR line has only !iid / linkified keys / BR / MS; P90 reveal group scopes per MR line | ✓ |
| Both clickable, different targets | MR line click opens GitLab; bigger targets but easy accidental navigation out | |
| Nothing click-anywhere | Only explicit controls act; loses the existing peek affordance | |

**User's choice:** Task row clickable, MR line not

## Task-row rollup & zero-MR state

### Q1 — What sits in the BR/MS gutter on the task row

| Option | Description | Selected |
|--------|-------------|----------|
| Nothing — gutter empty | Drift is per-MR; flags are one line below in the same columns | ✓ |
| Worst-of rollup glyph | ⚠ if any MR flagged; scannable but inert, so the glyph means two different things | |
| Flagged-count badge | "1 flagged" chip; needs its own space, doesn't fit the 28px gutter | |

**User's choice:** Nothing — gutter empty

### Q2 — How a task with zero MRs renders (criterion 4)

| Option | Description | Selected |
|--------|-------------|----------|
| One muted sub-line saying so | "⚠ No merge request" in the sub-line slot; keeps parent/child rhythm | ✓ |
| Marker in the task row, no sub-line | Compact, but puts meaning back into the gutter we just emptied | |
| Nothing at all | Fails criterion 4; indistinguishable from still-loading | |

**User's choice:** One muted sub-line saying so

### Q3 — The degraded (no matched milestone) variant

| Option | Description | Selected |
|--------|-------------|----------|
| Distinct "not checked" line | Neutral grey "— MR status unavailable" + tooltip; never claims an unverified problem | ✓ |
| Same "No merge request" line | Simpler, but false-positive ⚠ on every unstarted task | |
| Suppress the line in degraded mode | Can't tell missing from unchecked | |

**User's choice:** Distinct "not checked" line
**Notes:** Mirrors today's IssuesSection `—` + "No milestone matched — cannot check for MRs" tooltip.

### Q4 — An MR carrying two in-fix-version keys

| Option | Description | Selected |
|--------|-------------|----------|
| Under every matching task | Truthful; each task honestly shows coverage; duplicate cells share one cache state | ✓ |
| First key wins, once only | No duplicates, but falsely flags the second task as uncovered | |
| Under first, cross-referenced in others | "also covered by !412" line; no false alarm but a third line type to design | |

**User's choice:** Under every matching task
**Notes:** Flagged to the planner that the P90 sticky per-(mr.id, action) error state must behave sanely across duplicate copies.

## Secondary table scope

### Q1 — Do BR/MS fix cells operate in the secondary table?

| Option | Description | Selected |
|--------|-------------|----------|
| Yes, same cells | These are the most-drifted MRs; read-only would regress today's drift list | ✓ |
| Read-only secondary | Arguably not this page's job; but loses existing capability | |
| Only for out-of-scope-key rows | Two behaviours in one small table; keyless ones most need the milestone | |

**User's choice:** Yes, same cells

### Q2 — Distinguishing out-of-scope-key from keyless

| Option | Description | Selected |
|--------|-------------|----------|
| Key shown + inline reason | Key + warning glyph + tooltip naming the fix version; keyless shows muted — | ✓ |
| Two labelled groups | Structural and countable, but heavy chrome for a 2–3 row table | |
| Dedicated reason column | Always visible, but breaks grid alignment and duplicates the key column | |

**User's choice:** Key shown + inline reason

### Q3 — Does the secondary table share the primary's column grid?

| Option | Description | Selected |
|--------|-------------|----------|
| Same grid, aligned | Same row renderer as an MR sub-line with the key column repurposed | ✓ |
| Its own widths | Better density, weaker "one surface" read | |

**User's choice:** Same grid, aligned

### Q4 — The healthy case with no uncovered MRs

| Option | Description | Selected |
|--------|-------------|----------|
| Hide it entirely | Presence of the section is the signal | ✓ |
| Show heading with empty state | Confirms the check ran, but a permanent empty block on every clean release | |

**User's choice:** Hide it entirely

## Header, counts & degraded/loading

### Q1 — What the unified header carries

| Option | Description | Selected |
|--------|-------------|----------|
| Both progress and drift count | Different questions, both drove a now-removed section | ✓ |
| Progress only | Loses the at-a-glance drift number P89 D-13 deliberately built | |
| Drift count only | Loses the progress bar on the page today | |

**User's choice:** Both progress and drift count

### Q2 — Definition of the flagged count

| Option | Description | Selected |
|--------|-------------|----------|
| Distinct MRs with BR or MS flagged, both tables | Dedupes multi-key duplicates by mr.id; counts actionable secondary rows | ✓ |
| Distinct MRs, primary table only | Header says clean while fixable flags sit below | |
| Count flagged tasks, not MRs | Changes meaning mid-milestone; secondary MRs belong to no task | |
| Total flag glyphs | "Clicks to clean", but diverges from P89 D-13's per-row unit and inflates | |

**User's choice:** Distinct MRs with BR or MS flagged, both tables

### Q3 — The two orange banners

| Option | Description | Selected |
|--------|-------------|----------|
| One banner above the primary table | One condition, one message, stated once, with the release-date hint | ✓ |
| Keep both, differently placed | Same sentence twice on one screen for one root cause | |
| Move it to the release header/sidebar | Closer to the fix, further from the results it explains | |

**User's choice:** One banner above the primary table

### Q4 — What renders while MR queries are in flight

| Option | Description | Selected |
|--------|-------------|----------|
| Tasks render immediately, MR lines stream in | Per-task "loading merge requests…" placeholder; no false "No merge request" while pending | ✓ |
| Wait for both, one skeleton | No churn, but the whole table waits on the slowest (GitLab) query | |
| Tasks render, MR slot simply empty | Indistinguishable from genuinely having no MRs; rows jump | |

**User's choice:** Tasks render immediately, MR lines stream in
