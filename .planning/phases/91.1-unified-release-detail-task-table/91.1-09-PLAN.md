## Counting rules — DECIDED HERE, not inherited

**Rule 1 (BR+MS double flag).** Each badge counts its own predicate independently:
`⚠ N wrong branch` counts distinct MRs with `br === 'flag'`; `⚠ N no milestone` counts
distinct MRs with `ms === 'flag'`. **An MR flagged on both appears in BOTH badges**, so the
two counts may sum to more than `countBrMsFlaggedMRs`'s deduplicated union.
*Rationale:* each badge is a work queue. Clicking "wrong branch" must surface every MR that
needs a retarget; excluding double-flagged MRs from one badge would hide actionable work and
make the filtered list incomplete. The union total is no longer displayed as a headline
number, so `sum > union` is never visibly self-contradictory. The existing D-15 tests
asserting union semantics for `countBrMsFlaggedMRs` stay valid and MUST keep passing
unchanged — they now describe the retained tooltip aggregate, not the badges.

**Rule 2 (multi-key MR, IN-04).** Counts are taken over `driftRows`, which is already one
entry per distinct `mr.id` (deduped at `unionMRs`). **An MR attached under two fix-version
tasks therefore renders twice but increments each badge once.** *Rationale:* the badge counts
problems to fix, and one retarget/milestone write fixes both rendered copies — the D-09
duplication tests already establish that the copies share the underlying MR. Both rendered
copies remain visible under an active filter; the filter selects MRs, not rendered rows.

Purpose: the bare integer read as a second progress metric next to `N / M done`, and
collapsed two different defects into one undifferentiated total that told the user nothing to
go do.

Output: two per-category count functions, hook wiring, and a filtering badge pair.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-91.1-16 | Repudiation | A badge under-reporting actionable work by excluding double-flagged MRs | mitigate | Rule 1 counts each predicate independently, test-enforced by the explicit `toBeGreaterThan(union)` assertion in task 1 |
| T-91.1-17 | Tampering | A filtered row firing a fix against the wrong MR | mitigate | Filtering only removes entries from the rendered arrays; each `DriftActionCell` still receives `mr` from its own `DriftRow` and sub-lines stay keyed by `row.mr.id`, never by index |
| T-91.1-18 | Denial of service | Filter predicate recomputed per render over large MR sets | accept | Arrays are release-scoped (tens of rows); a plain `filter` per render is well within budget and avoids a memo whose deps would be easy to get wrong |
| T-91.1-SC | Tampering | package installs | accept | No installs in this plan |
