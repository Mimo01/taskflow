<objective>
Fix the react-hotkeys-hook key-naming mismatch that prevents mod+/ from firing at runtime.

Purpose: Plan 19-04 changed the hotkey from `?` to `mod+/`, but react-hotkeys-hook v5.2.4 has a known bug (GitHub issue #1125) where the parser stores the key literal `"/"` but the key normalizer converts `event.code="Slash"` to `"slash"`. Since `"/" !== "slash"`, the handler never fires. The fix is to use `"mod+slash"` (the full code name) which the normalizer produces from real keyboard events. Tests pass with `"mod+/"` because jsdom synthetic events bypass the normalizer — this is a runtime-only failure.

Output: main.tsx binding changed from `'mod+/'` to `'mod+slash'`; test comments updated; all tests pass.
</objective>

Root cause from debug session (.planning/debug/mod-slash-hotkey-broken.md):
- react-hotkeys-hook v5.2.4 parser splits "mod+/" by "+" → keys = ["/"]
- Key normalizer takes event.code "Slash" → .toLowerCase().replace(/key|digit|numpad/, "") → "slash"
- Matcher compares "/" !== "slash" → handler never fires
- Fix: use "mod+slash" so parser produces keys = ["slash"] matching the normalized code
