<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client (TypeScript service code) → AIO TCMS REST API | PAT in Authorization header crosses this boundary on every fetch call |
| AIO API response body → typed TypeScript runtime | Untrusted JSON parsed into typed structures used by UI without runtime validation (Zod not in stack per RESEARCH) |
| AIO_STATUS_MAP constant → UI rendering | Status ID lookup is the basis of progress bar coloring; an incorrect mapping would silently mis-color cycles |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57-02-01 | T (Tampering) | aioFetch response JSON → fetch* return value | mitigate | All four new functions parse with `as <Type>` cast and rely on TypeScript's structural typing only. Acceptable per existing fetchAioCycles convention (no runtime validation library in stack). Mitigation: Plan 04 component code defensively handles `undefined` / `null` on every nested access (e.g. `cycle.detail?.title ?? cycle.detail?.key`). |
| T-57-02-02 | I (Information Disclosure) | URL parameter encoding for projectKey + folderID | mitigate | Use `encodeURIComponent(projectKey)` for projectKey on every new URL — matches existing fetchAioCycles. `folderID` is a number from the folder tree API (server-trusted), so no encoding required; still cast through `String(folderID)` defensively. Acceptance criteria require encodeURIComponent usage. |
| T-57-02-03 | E (Elevation of Privilege) | PAT in URL query string | mitigate | PAT MUST NEVER appear in URL — only in `Authorization: Bearer <PAT>` header. aioFetch handles header injection internally. Acceptance criteria require new functions call `aioFetch` (not raw `fetch`), enforcing this. |
| T-57-02-04 | I | AIO_STATUS_MAP correctness | mitigate | The five-ID mapping is the single source of truth (D-05). Unit tests (Plan 01 RED stubs) assert exact mappings — incorrect implementation fails CI immediately. UI-SPEC explicitly cross-references this map. |
| T-57-02-05 | D (Denial of Service) | fetchAioCycleSummaries with very large ids[] | mitigate | If A3 says GET with `?ids=`, very long ID lists could exceed URL length limits (typical: 2048 chars; AIO sample shows allIDs up to 7 items — well under limit, but production tenants could have hundreds). Mitigation: early-return on empty `ids`; Plan 04 derives ids from `allIDs` (real cycles only). If A3 reports POST, this threat is moot. Accept residual risk for >500 ID case as out-of-scope for v1.8 (CONTEXT.md "Future Requirements"). |
| T-57-02-06 | T | URL path injection via projectKey | mitigate | `encodeURIComponent(projectKey)` prevents `..` traversal or query-string injection. AIO has no public projectKey enumeration that could be abused; even so, encoding is the established pattern. |

No high-severity threats. All mitigations enforced via acceptance criteria + existing aioFetch contract.
</threat_model>
