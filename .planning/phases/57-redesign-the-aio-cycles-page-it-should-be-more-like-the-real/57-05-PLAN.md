  <how-to-verify>
    Developer steps (run by the human, not Claude):

    1. Build and run the app:
       ```
       cd taskflow && pnpm tauri dev
       ```
       Wait for the app window. Enable AIO in Settings → AIO if not already enabled. Make sure an AIO project is selected in Settings (Phase 55 deliverable).

    2. Navigate to the configured AIO project's overview page (sidebar "AIO Projects" entry should deep-link to `/aio-project/{selectedProjectKey}`).

    3. **Check 1 — Two-panel layout**
       - Left panel: ~256px wide (w-64), light-muted background, with a border on its right edge
       - Right panel: fills remaining width, contains the cycle table
       - On window resize, panels keep their proportions (left fixed, right flex)
       - PASS if matches UI-SPEC layout diagram; FAIL → record gap

    4. **Check 2 — Folder tree renders all levels**
       - Verify root folders render (e.g. "2023 - DONE", "2024 - DONE", "AUTOMATION" — names per API-EXAMPLES.md sample, may differ on real instance)
       - Click a root folder with children — chevron rotates 90°, children appear indented
       - Drill multiple levels deep (4+ if available) — each level indented further
       - PASS if all levels render correctly; FAIL → record gap

    5. **Check 3 — Cycle count badges**
       - Each folder name has a small `<Badge>` to its right with a number
       - Numbers match what the `/count` endpoint returned (verify by checking DevTools Network → request to the folder-count endpoint → response body → match a sample folderID's count to the badge)
       - Folders with count 0 → no badge visible
       - PASS / FAIL → record gap

    6. **Check 4 — "Ungrouped" entry**
       - If `countMap['-1']` is non-zero (i.e. some cycles aren't in any folder), an "Ungrouped" row appears at the BOTTOM of the tree
       - Clicking it loads the unassigned cycles in the right panel
       - If countMap['-1'] is 0 or absent, "Ungrouped" does NOT appear
       - PASS / FAIL → record gap

    7. **Check 5 — Folder selection loads cycles**
       - Click a folder with count > 0
       - DevTools Network: a request fires for the cycles endpoint (with or without `?folderID=` per A5 finding)
       - Right panel populates with cycles matching that folder
       - PASS / FAIL → record gap (especially if cycles for one folder appear under another — A5 misimplementation)

    8. **Check 6 — 5-column table**
       - Columns from left to right: Key (monospace), Name (link), Owner, Total tests (right-aligned), Progress
       - Column widths approximately: w-28 / flex-1 / w-32 / w-20 / w-44
       - Header row has muted background
       - PASS / FAIL → record gap

    9. **Check 7 — Progress bar segments and colors**
       - Pick a cycle with a known distribution (cross-reference DevTools Network → summary response → testRunDistribution for that cycle's ID)
       - Verify the bar's segments use these colors:
         - green-500 for status ID 901 (Pass)
         - red-500 for status ID 51 (Fail)
         - orange-400 for status ID 55 (Blocked)
         - blue-400 for status ID 54 (In Progress)
         - muted for status ID 53 (Not Executed)
       - Segment widths roughly match the percentages (e.g. 60 / 261 ≈ 23% for a 60-pass / 261-total cycle)
       - PASS / FAIL → record gap (also flag if any unknown status ID appears as a 6th color)

    10. **Check 8 — Owner column resolves displayName**
        - Owner cells show real human names (e.g. "Alice Smith") not raw "JIRAUSER23429" / "ext94772"
        - DevTools Network: confirms one request per unique ownedByID (NOT one per cycle row — dedup working)
        - For a known-deleted Jira user, the cell falls back to the raw username string (D-08)
        - Owner cell shows a Skeleton briefly while resolving (within the first second after folder selection)
        - PASS / FAIL → record gap

    11. **Check 9 — "Show closed" toggle**
        - Initially OFF: closed cycles (where `detail.isClosed === true`) are hidden
        - Toggle ON: closed cycles appear with a `<Badge>Closed</Badge>` next to the name
        - Closed cycles render Key + Name in muted text color
        - Toggle is keyboard-accessible (Tab focus + Space activates)
        - PASS / FAIL → record gap

    12. **Check 10 — No first-load auth flash**
        - Hard refresh the page (Cmd-R)
        - Observe the first 500ms: no 401 toast or "Invalid token" error banner flashes
        - Loading skeletons appear, then resolve to data
        - DevTools Network: NO requests fire BEFORE the Stronghold readSecret('jira-pat') resolves (verify by checking timing — AIO requests start AFTER the readSecret promise)
        - PASS / FAIL → record gap

    13. **Check 11 — No skeleton-to-data layout jump**
        - Hard refresh
        - Watch the column positions during skeleton phase → data phase
        - Key column width stays the same; Name column flex stays the same; etc.
        - No content shift visible to the eye
        - PASS / FAIL → record gap

    14. **Check 12 — Cycle Name NavLink works**
        - Click a cycle name in the table
        - Browser navigates to `/aio-cycle/{projectKey}/{cycleKey}`
        - AioCycleDetailPage renders correctly (Phase 53/56 deliverable — unchanged)
        - Back button returns to AioProjectOverviewPage with the previously-selected folder still selected (URL state if any — accept either behavior; this is informational)
        - PASS / FAIL → record gap

    15. **Check 13 — Regression smoke test**
        - Navigate to /aio-cycle/{projectKey}/{cycleKey} directly — page works (Phase 53/56)
        - Navigate to an issue detail page with AIO test runs — page works (Phase 54)
        - Sidebar AIO entry still shows correct nav (Phase 52/55)
        - Settings → AIO project picker still works (Phase 55)
        - PASS / FAIL → record gap
