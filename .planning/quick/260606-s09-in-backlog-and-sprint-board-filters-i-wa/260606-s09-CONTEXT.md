# Quick Task 260606-s09: Filter stories by "Unassigned" in Backlog + Sprint Board - Context

**Gathered:** 2026-06-06
**Status:** Ready for planning

<domain>
## Task Boundary

In the Backlog view and the Sprint Board view, let users filter stories by **Unassigned** (issues with no assignee). This must be merged into the existing assignee filter (the `UnifiedFilterBar` assignee dropdown), not a separate control.
</domain>

<decisions>
## Implementation Decisions

User answered "you decide" on all gray areas — captured below as Claude's Discretion.

### Sentinel representation
- Use a **dedicated reserved sentinel constant** (e.g. `UNASSIGNED_FILTER = '__unassigned__'`) as the value stored in `activeAssignees`, matched against `issue.fields.assignee === null`.
- Rationale: robust against collision with a real `displayName` of "Unassigned"; the existing predicate uses case-insensitive substring matching, so a plain "Unassigned" string would be fragile.
- The sentinel must render as the human-readable label **"Unassigned"** in the dropdown UI.

### Dropdown visibility
- Show the "Unassigned" option **only when the current view contains at least one unassigned issue** — mirrors how named assignee options are derived from visible issues. No dead option.

### Dropdown placement
- Pin "Unassigned" to the **top** of the assignee option list (above the named assignees).

### Filter predicate semantics
- OR semantics: an issue matches if it is unassigned AND the sentinel is selected, OR its `displayName` matches one of the selected named assignees. Consistent across both views.

### Claude's Discretion
- Exact constant name and where it lives (shared module vs inline), label rendering mechanism in `FilterDropdown`, and whether the two view predicates are refactored into a shared helper — left to planner/executor, but the two predicates MUST stay behaviorally identical.
</decisions>
