<objective>
Split the Executions and Defects tabs on the AIO test cycle detail page into two stacked tables,
**Not done** first and **Done** second. Each table gets a section heading with a count. When a
section has no rows, it shows a compact empty state instead of the table. The empty state tells apart
"nothing here at all" and "nothing matches the filters". The existing toolbar, filters, search and
sort stay as they are and drive both tables.

Purpose: Users can see at a glance what is still outstanding in a cycle, apart from what is finished.
Output: An updated ExecutionsList, an updated DefectsList, a compact EmptyState variant, and updated
tests. All of this is implemented per locked decisions D-01..D-05 (see the numbering below).

Decision IDs (mapped from CONTEXT.md, in order):
- D-01: Executions Done = `normalizeStatus(run.status) === 'pass'` only. Everything else is Not done.
- D-02: Defects Done = `fields.status.statusCategory.key === 'done'`. Everything else, including loading rows, is Not done. Never drop a row.
- D-03: Stack the sections vertically with Not done first and Done second. Both are always open. Each has a header with a label and a count.
- D-04: Keep every filter, search and sort. One shared toolbar drives both tables. Each section shows its own filtered count.
- D-05: A section's empty state tells apart "nothing here at all" and "nothing matches the filters".
</objective>
