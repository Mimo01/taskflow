<objective>
Stop main content (most visibly My Tasks) from getting squished at small window widths while the app sidebar is open.

Root cause (found in code, not assumed): the My Tasks page already compacts via `@container` tiers (MyTaskRow tiers at 1024/860/720/580, header donut `@[1000px]`), so it does react to the sidebar. The problem is the space itself. In main.tsx the app shell is `flex` with `<Sidebar />` in normal flow at a persisted width (default 224px, resizable 160-320) whatever the window width, and PeekPanel (default 480px, min 360) also sits in flow to the right of `<main>`. At the default 1100px Tauri window with peek open, main gets 1100-224-480 = 396px. At a 900px window it gets 676px even without peek. Nothing collapses the sidebar automatically. A smaller secondary issue: the My Tasks stat-tile grid uses viewport `sm:grid-cols-3`, the one viewport breakpoint left on that page.

Fix: an auto icon-rail. When there isn't room, the sidebar shows as its existing 64px collapsed rail and expands as an overlay on demand, as the shadcn offcanvas/mobile sidebar does. The peek panel stays side-by-side, per the user's narrow-layout preference that side panels stay beside main and shrink.

Output: pure layout helper + tests, auto-rail hook, overlay store, Sidebar/main.tsx wiring, My Tasks tile grid moved to a container query.
</objective>
