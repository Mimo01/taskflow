# Quick Task 261013-l97: AIO Cycles page — dashboard redesign - Context

**Gathered:** 2026-10-13
**Status:** Ready for planning

<domain>
## Task Boundary

The AIO Cycles page (`taskflow/src/routes/dashboard/AioProjectOverviewPage.tsx`, just redesigned in quick 261013-jl3 and UAT-approved) currently shows a folder tree (`AioFolderPanel`) on the left and the cycle list (`AioCycleList`) on the right. Make it more dashboard-like: add KPI tiles and charts that summarise the cycles in the selected folder scope, so the page looks polished and professional. Keep the existing data-fetching logic: it works, so don't rewrite it.

User's words: "The existing logic is fine and works but I want to make the page more 'dashboard like' with graphs and so on. You decide what to put there. Make it nice and professional looking."

</domain>

<decisions>
## Implementation Decisions

### Layout
- KEEP the folder tree as the left rail. It's the scope filter: the selected folder (All cycles / Ungrouped / folder subtree) scopes every KPI and chart.
- The right pane becomes a scrollable dashboard: KPI tile row at the top, then a chart grid, then the existing cycle list below.

### Cycle list placement
- Below the charts on the same page (no tabs). Keep the list's existing behaviour: Open|All filter, virtualization above 100 rows, row click, all-closed notice.
- Watch the scroll containers: today the list owns its own scroll/virtualizer. With the dashboard above it, either the whole right pane scrolls (the virtualizer must then use the pane as its scroll element) or the list keeps a bounded height. Avoid nested double scrollbars.

### Interaction
- Cross-filter: clicking a chart segment or a KPI tile (e.g. an owner bar, the "Overdue" tile, a status segment) filters the cycle list below. Show an active-filter chip near the list header that clears it. Folder changes reset the filter. Charts stay keyboard reachable.

### Claude's Discretion
- Which KPIs and charts to show. Starting proposal, which research and planner may refine:
  - KPI tiles: Open cycles, Overdue, Test runs executed / total, Pass rate.
  - Execution status mix across scope (aggregate testRunDistribution, stacked bar or donut).
  - Cycles by owner (horizontal bar, open vs closed or by progress).
  - Schedule / due-soon view (cycles ending in the next N days plus overdue), or a timeline of cycle end dates.
- Visual details, within the user's established taste below.

</decisions>

<specifics>
## Specific Ideas — established user preferences (from prior UAT rounds, MUST follow)

- **Colour = status only.** Status categories keep their colours everywhere. Non-status things (owners, counts) get neutral colours or glyphs.
- **Little text, detail on hover.** Tooltips ≤ 4 rows plus ≤ 1 short note. No chart legends (hover names the series). Don't repeat what the card already shows.
- **Identical, fixed-size cards.** Same height across the row and in every state. Loading skeletons match the final geometry, rendered through the same Card shell. No layout shift.
- **Everything hoverable; things that list cycles are clickable** and keyboard reachable.
- **Spacing:** separate blocks clearly. Sub-dividers look lighter than section borders.
- **One row = one line** at every density in the list. Drop columns rather than wrap.
- Shared `<Card>` (`components/ui/card.tsx`) is `rounded-xl ring-1`, with token-driven padding and no implicit role (pass `role="region"`, and on CardTitle `role="heading" aria-level`). Never nest a non-`bare` `<ChartWrapper>` inside a Card.
- Reuse existing primitives: StatTile, ChartWrapper, and the Sprint/Epic dashboard sections (recharts ^3.8 is installed).
- AIO status colours and canonical keys come from the project config (`statusConfig`, `normalizeStatusById` / `initializeAioStatusMap` in `lib/aioUtils.ts`). Reuse the mapping `AioCycleList`/`cycleProgress` already uses.
- Don't reintroduce a "Show closed" Switch. Keep the Open|All segmented filter.
- Live-unverified data assumptions remain: effort unit (assumed seconds), date format.

</specifics>

## Post-research decisions (orchestrator, Claude's discretion)

- StatTile/ChartWrapper are gone (guard test forbids recreating routes/dashboard/StatTile.tsx). Use Aio*-named components built on <Card>, EpicStatCard tile geometry, TooltipBody/TooltipRow, BandBar.
- Open|All segmented filter MOVES to a scope bar above the KPI row so KPIs, charts and list all follow it (one shared truth). It keeps its persisted store and its behaviour, including the all-closed notice.
- Pass rate = passed ÷ total test runs (same as the per-row % in the list). Executed/total goes in as secondary text or tooltip.
- Clickable chart targets are HTML buttons, not recharts click handlers, so they're keyboard reachable.
