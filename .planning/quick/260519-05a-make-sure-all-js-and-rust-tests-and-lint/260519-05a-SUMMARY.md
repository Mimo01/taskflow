### Task 1: JS/TS Gate

**1. Biome auto-format (38 files)**
- Ran `npm run fix` (biome check --write) to apply formatter and organizeImports
- All 38 files were formatting-only changes (no logic)

**2. `lint/suspicious/noGlobalIsNan` in AioCycleDetailPage.tsx:1066**
- Fixed: `isNaN(d.getTime())` → `Number.isNaN(d.getTime())`
- Reason: global `isNaN` is unsafe (coerces non-number inputs); `Number.isNaN` is strict

**3. `lint/suspicious/noTemplateCurlyInString` in IssueDetailSheet.test.tsx:763**
- Fixed: changed `it('calls openUrl with ${jiraBaseUrl}/browse/...')` from single-quote to backtick with escaped `\${}`
- Reason: the string contained `${}` pattern that biome flagged as a template literal mistake

**4. `biome-ignore` for `\x00` sentinel in WikiRenderer.tsx:560**
- Added: `// biome-ignore lint/suspicious/noControlCharactersInRegex: \x00 (null byte) is intentionally used as a unique sentinel delimiter`
- Reason: null byte is a deliberate design choice — it cannot appear in wiki markup text, making false-positive matches impossible. A biome-ignore is appropriate here (genuine false positive for this use case).

**5. `TS2322` type error: `asChild` not in PopoverTrigger props (AioCycleDetailPage.tsx:167)**
- Fixed: `<PopoverTrigger asChild><Button .../></PopoverTrigger>` → `<PopoverTrigger render={<Button />}>children</PopoverTrigger>`
- Reason: The project uses `@base-ui/react/popover` (NOT Radix UI). Base-UI's Trigger does not have an `asChild` prop; the correct API is `render={<element />}`. This pattern is used throughout the codebase (e.g. UnifiedFilterBar.tsx:79).

**6. `jira-watchers.test.ts`: operation label mismatch**
- Fixed: expected `'Load Issue Detail'` → `'Load Watchers'`
- Reason: The operation-label audit (quick task 260518-wmy) updated the label in `jira-watchers.ts` but the test was not updated alongside it.

**7. `jira/sprints.test.ts`: operation label mismatch**
- Fixed: expected `'Load Sprint Board'` → `'Move to Sprint'`
- Reason: Same as above — label was corrected in production code during the audit but test was not updated.

**8. `AioTestRunsSection.test.tsx`: mock-queue leakage (10 pre-existing failures)**
- Added `mockFetchTraceability.mockReset()` to the inner `beforeEach` of the "Gap 1 + Gap 2" describe block
- Root cause: `vi.clearAllMocks()` (called in outer `beforeEach`) clears call history but does NOT clear `mockResolvedValueOnce` queued responses. The passing test at line 626 queued `mockResolvedValueOnce([])` as its second call (for the old component that called `fetchAioTraceabilityTestCases` twice). After the commit `fix(aio): remove unused requirement traceability call` (44066103) reduced the component to one call, that second `[]` response remained unconsumed. When the next test ran, the `[]` from the previous test was the first item in the queue — the component received an empty array and returned `null`, rendering `<div />`. Fix: add `mockReset()` for `mockFetchTraceability` in the inner `beforeEach` to clear the once-queue between tests.
