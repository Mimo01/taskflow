  <name>Task 1: Add changelog extraction to Jira and system note parsing to GitLab in notifications service</name>
  <files>taskflow/src/services/notifications.ts</files>
  <action>
**Jira — changelog expansion (fetchIssueUpdates inner function):**

1. Add `&expand=changelog` to the JQL search URL (append to existing `&fields=...&maxResults=20`).

2. After fetching, for each issue extract the changelog entries that fall within the polling window (i.e. `created > since`). The Jira response shape for changelog is:
   ```
   issue.changelog.histories[]: { created: string, items[]: { field: string, fromString: string, toString: string } }
   ```

3. Filter changelog items to only `field === 'status'` or `field === 'assignee'` (per user decision — skip priority, sprint, labels, etc.).

4. Build a `changeLines: string[]` array from matching items:
   - `"Status: {fromString} \u2192 {toString}"` (use actual Unicode arrow)
   - `"Assignee: {fromString || '(none)'} \u2192 {toString || '(none)'}"` (handle null/empty from/to)

5. If `changeLines.length > 0`:
   - Set `bodyPreview` to `changeLines.join(' | ')` (truncated to ~120 chars — slightly more than current 80 since changes are more information-dense)
   - Set `fullBody` to `changeLines.join('\n')`
   - Set `author` to `history.author.displayName` from the most recent matching changelog entry (the person who made the change, not the assignee)
6. If `changeLines.length === 0`: fall back to current `"Status: {statusName}"` behavior (no regression).

**GitLab — system note parsing (fetchNewGitlabNotes):**

1. Stop unconditionally skipping system notes. Instead, for system notes (`note.system === true`), check if the body matches actionable patterns:
   - State change: body matches `/^(closed|merged|reopened)/i` — extract as `"State: {previous} \u2192 {new}"`. The note body contains the new state; infer previous from the action (e.g. "merged" implies previous was "opened", "closed" implies was "opened", "reopened" implies was "closed/merged").
   - Reviewer: body matches `/^requested review from/i` or `/^removed review request/i` — use body as-is for bodyPreview.
   - Label: body matches `/^(added|removed) ~"/i` — use body as-is for bodyPreview.

2. For matching system notes, create a NotificationItem with:
   - `id: 'gitlab-system-${note.id}'`
   - `notificationType: 'mr-note'` (reuse existing type)
   - `bodyPreview` and `fullBody` set to the parsed change description
   - Keep existing cursor filtering (`note.created_at <= since` break) and own-note filtering

3. Non-matching system notes (e.g. "mentioned in commit", "changed the description") continue to be skipped.

**Important:** Do NOT modify NotificationItem type or the store — the existing `bodyPreview` and `fullBody` fields are sufficient to carry the arrow-format text. No schema changes needed.
