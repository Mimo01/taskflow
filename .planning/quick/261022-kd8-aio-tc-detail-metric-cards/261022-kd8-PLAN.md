  <behavior>
    - Empty results array → all counts 0, cases 0, minPerCase 0, maxPerCase 0, unavailable 0.
    - One loaded result with steps [PASS, PASS, FAIL, BLOCKED, NOT_EXECUTED] → passed 2, failed 1, blocked 1, notRun 1, executed 4, total 5, cases 1, min 5, max 5.
    - Two loaded results with 3 and 7 steps → total 10, cases 2, minPerCase 3, maxPerCase 7.
    - A result with isError true, and a result whose data is null, are excluded from every count and each increments `unavailable`.
    - A still-pending result (isPending true, no data) is excluded and does NOT count as unavailable.
    - A step status of "IN_PROGRESS" or an unknown string counts toward notRun (not executed).
    - A loaded result with zero steps counts as a case with 0 steps (cases +1, minPerCase 0).
  </behavior>
  <action>
Create `taskflow/src/lib/aio-step-stats.ts` exporting:
- `interface StepStatsTotals { passed; failed; blocked; notRun; executed; total; cases; minPerCase; maxPerCase; unavailable }` (all number). executed = passed + failed + blocked; total = all steps across loaded cases; cases = results with non-null data (the denominator for steps-per-case, per RESEARCH pitfall 7 — never runs.length); unavailable = results with isError or data === null.

- `function aggregateStepStats(results: readonly StepQueryResult[]): StepStatsTotals` — single pass; classify each step with `normalizeStatus(step.status)` from `@/lib/aioUtils`; 'pass'/'fail'/'blocked' map to their counters, everything else ('notRun','inProgress') to notRun. min/max are 0 when cases is 0. Short doc comment explaining that pending results are neither counted nor unavailable.
Write the tests from <behavior> first in `aio-step-stats.test.ts` (vitest, plain fixtures; build step objects with `{ id, step: 's', status }`), then implement. One commit containing tests + implementation.
