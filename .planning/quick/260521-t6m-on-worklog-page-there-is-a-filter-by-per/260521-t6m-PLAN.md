<objective>
Redesign the "Filter by person" control on the Worklogs page.

Today:
- Combobox `<input>` holds the search **query** (free text).
- A separate `Badge` chip renders to the LEFT of the input when a person is selected.
- No default — on mount no one is selected and Tempo returns worklogs for the whole project.

Target:
- Combobox `<input>` value IS the selected person's display name (selection-as-input).
- No `Badge` chip. The input itself shows the current selection.
- Default selection on mount = the currently authenticated Jira user ("me"), pulled from `useAuthStore` (`jiraUsername` + `jiraUserDisplayName`). Tempo query runs immediately with `[jiraUsername]`.
- A small `×` button inside/next to the input clears the selection. After clearing, the input is empty and the placeholder reads "Filter by person".
- Visual styling matches the existing filter-bar inputs (date inputs, BacklogFilterBar combobox): same border, rounded-md, h-7, text-xs, focus:ring-1 focus:ring-ring, etc.

Purpose: The user is almost always looking at their own worklogs first, so defaulting to "me" removes a click. Eliminating the redundant chip + free-text input duality reduces visual noise and makes the control behave like a normal "selected value" picker.

Output: Updated `WorklogsPage.tsx` and updated tests; behavior verified by the test suite and a brief human visual check.
</objective>
