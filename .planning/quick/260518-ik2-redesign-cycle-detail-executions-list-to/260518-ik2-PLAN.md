# Quick Task 260518-ik2: Redesign cycle detail executions list to use fast paged endpoint

## Goal

Replace the slow `GET /rest/aio-tcms-api/1.0/project/{key}/testcycle/{key}/testrun` endpoint
with the fast `POST /rest/aio-tcms/1.0/project/{id}/testcycle/{id}/testcasewithrun/paged`
endpoint on the cycle detail page executions list.

## Context

- Current: `fetchAioTestRunsForCycle` in `issue-runs.ts` paginates via GET, taking long time
- New: POST paged endpoint under `aio-tcms/1.0` (same base path as `fetchAioCyclesWithDetail`)
  returns `{ items: [...] }` with test case + latest run in one shot
- `jiraProjectId` (numeric) and `cycleNumericId` already available in the component
- Pattern already established by `fetchAioCyclesWithDetail` in `cycles.ts`

## Tasks

### Task 1 — Add `fetchAioCycleTestCasesWithRuns` to `cycles.ts`

**Files:** `taskflow/src/services/aio/cycles.ts`

**Action:**
- Add `RawTestCaseWithRun` type for new endpoint response shape
- Add inline `TESTCASE_STATUS_MAP` to map numeric statusID → chip status string
- Add `fetchAioCycleTestCasesWithRuns(baseUrl, token, jiraProjectId, cycleNumericId, cycleKey)`
  - POSTs to `/project/{jiraProjectId}/testcycle/{cycleNumericId}/testcasewithrun/paged?c_pId={id}&t={ts}`
  - Uses `AIO_PROJECTS_API_PATH` base
  - maxResults: 500 (single-shot fetch, no pagination loop needed)
  - Maps items to `AioTestRun[]`
- Export from `cycles.ts` (auto-re-exported via `index.ts`)

**Verify:** TypeScript compiles, function exported from barrel
