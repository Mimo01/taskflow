# Quick 261116-ez8: Fix v1.14 audit tech debt

Source: `.planning/v1.14-MILESTONE-AUDIT.md` tech_debt items (Phases 92-95 extension audit).

Inline per the trivial-fix preference: each finding was checked against the code first, and the only real one is a few lines with a regression test.

## Triage

1. **Edit-release does not refresh RM data (93/94).** Not a defect. RM week data is independent of the Jira fix version. The package cell is matched on the client from the version's date and name against the weeks, and `jira-fix-versions` is already invalidated on save, so the match re-derives from fresh inputs. → no change.
2. **Breakdown seed never invalidated (93/94).** Not a defect. `['jira-version-counts','breakdown',…]` is `enabled:false` and is written only by `setQueryData` when a batch chunk resolves. Invalidating it would be a no-op (see the enrichment-invalidation-noop memory), and every batch refetch rewrites it. → no change.
3. **Backlog PAT not re-read on credential save (92).** Real. Global search keeps `useGhBacklogData` mounted, but the hook re-read the PAT only on a `jiraBaseUrl` change. After `queryClient.clear()` and the revision bump, it refetched with the old token. `useGlobalSearchSources` re-read on the revision, but its first render after the bump still passed the old token to `useBoardId`. → fix.

## Task 1: tie the PAT to the revision it was read at (both readers)

- files: `src/services/jira/greenhopper/useGhBacklogData.ts`, `src/hooks/useGlobalSearchSources.ts`, both test files
- action: store `revision` with the secret, re-read on `credentialsRevision`, and trust the token only when `baseUrl` and `revision` both match the current values. This mirrors the existing WR-06 base-URL guard.
- verify: the new tests fail against the HEAD sources and pass with the fix; the full suite runs green in the pre-commit hook.
- done: no request uses the old PAT after a credential save.
