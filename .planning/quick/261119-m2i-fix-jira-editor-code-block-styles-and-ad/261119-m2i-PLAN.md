<objective>
Fix the unreadable code-block styling in the Jira wiki editor and add syntax highlighting for the CODE_LANGUAGES values, in both the TipTap editor and the read-only WikiRenderer, following the app theme.

Purpose: Code blocks are currently gray-200 text on a near-white surface in light mode, because Tailwind Typography's `pre` colour leaks through CodeBlockView's `bg-transparent` pre. Saved blocks get a fixed gray-800 prose slab that ignores the theme. Users want readable, highlighted code that looks the same while editing and after saving.

Output: a shared `lib/wiki/highlight.ts` (lowlight with an explicit language map and a post-sanitize rehype plugin), an editor decoration plugin, shared frame classes, unlayered theme-aware token CSS, and tests.

Decision traceability (CONTEXT.md has no D-NN numbering; the labels below refer to its bullets):
- D-scope: fix styles AND highlight in both the editor and WikiRenderer → Tasks 2 and 3
- D-theme: GitHub-light/dark tokens on the muted surface, isolated from global github-dark.css → Task 2 (CSS) and Task 3 (visual proof)
- D-no-language: bare {code}, {noformat} and unknown values stay plain, no auto-detect → Tasks 2 and 3 (strict map, custom plugin)
- Discretion: lowlight with a custom PM plugin (NOT @tiptap/extension-code-block-lowlight, which auto-detects; NOT rehype-highlight, which adds the `hljs` class). The language map follows research. Only the needed grammars are registered.
</objective>
