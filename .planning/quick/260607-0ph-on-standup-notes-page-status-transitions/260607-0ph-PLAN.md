<key_findings>
RESOLVED — the critical data-shape gap from the investigation:

- The standup transition source carries status NAMES ONLY. `fetchYesterdayJiraActivity`
  (taskflow/src/services/jira.ts ~line 666) builds each transition from the Jira changelog
  `status` item, which exposes `fromString`/`toString` (display names) — NOT a numeric
  status id, NOT a statusCategory. Confirmed: `ChangelogHistory.items` in
  `taskflow/src/services/jira-changelog.ts` (lines 22-27) is only `{ field, fieldtype?,
  fromString, toString }`. So there is NOTHING in the changelog to thread through.

- `statusPillClass(categoryKey)` needs a statusCategory KEY ('new' | 'indeterminate' |
  'done'), not a name. The legitimate name→category source already exists:
  `fetchAllJiraStatuses(baseUrl, token)` in `taskflow/src/services/jira/statuses.ts`
  returns `JiraStatus[]` with `{ name, statusCategory: { key } }`.

DECISION (no hardcoded name matching): enrich transitions inside
`fetchYesterdayJiraActivity` — it already has `base` + `token`/`headers`. Fetch the global
status list ONCE per activity load, build a `name → statusCategory.key` Map, and stamp
`fromCategory`/`toCategory` onto each transition. The map fetch must degrade gracefully
(if it fails, leave categories undefined → pills fall back to 'new' gray; activity still
renders). This keeps all data wiring inside one service function — no new query plumbing
through StandupNotesPage → YesterdayColumn props.

CONSTRAINT (markdown must not change): `generateMarkdown` and existing tests
(YesterdayColumn.test.ts ~lines 260-277) assert on `item.label` strings like
`"To Do → Done"`. DO NOT change how `label` is built. Add a SEPARATE structured field on
`SubItem` for the styled render; `label` stays the plain-text markdown source.
</key_findings>
