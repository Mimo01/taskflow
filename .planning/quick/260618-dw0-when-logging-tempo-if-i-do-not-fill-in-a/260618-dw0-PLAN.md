<objective>
When logging a worklog with no description, default the comment to `Working on issue {ISSUE-KEY}` (the actual issue key); when a description is provided, pass it through unchanged.

Purpose: Worklogs without a description are unhelpful in Tempo/Jira views — a consistent default makes every logged entry self-describing.
Output: Modified `createWorklog` service function + regression tests.

Decision (documented per investigation guidance): Apply the default at the **service layer** in `createWorklog`, NOT the component layer. Rationale:
- `createWorklog` is the single entry point for *creating* worklogs and already receives `issueKey`, so interpolation is trivial and consistent regardless of UI entry point.
- The only caller, `LogWorkPopover.tsx`, already passes `comment.trim() || undefined`, so the service receives `undefined` for blank input — the service is the correct, DRY place to substitute the default.
- Scope is limited to creation (`createWorklog`). `updateWorklog` is intentionally excluded: editing an existing worklog is an explicit user edit, and blanking a field there should not be silently overwritten.
</objective>
