<rules>
These rules apply to EVERY task in this plan. A diff that violates any of them is a defect.

**R1 — Edits are strictly ADDITIVE.**
Retain the existing baseline utility verbatim and append the density variants after it.
Correct: `py-2` → `py-2 density-compact:py-1 density-comfortable:py-3`.
Defect: `py-2` → `py-1.5 density-compact:py-1`. Changing, reordering into a different value, or
removing a baseline spacing class is out of scope and must be rejected. At `default` density the
rendered output must be pixel-identical to the pre-change app — that is the safety property that
makes this sweep low-risk.

**R2 — Both variants, always (LOCKED decision).**
Every surface touched gets `density-compact:` AND `density-comfortable:`. Never one without the
other. CONTEXT.md states this unconditionally: the only sanctioned discretion is skipping an
ENTIRE surface as N/A (R9), never applying one-sided variants to a surface you do touch.

Single narrow exception — a **genuine zero-floor**: the baseline value is already `0`, so the R4
table offers no lower step (e.g. `[&_li]:my-0`, and the `[&_li]:my-0` inside the `prose-xs` block
at `DiscussionThreads.tsx:335`). Only those may add `density-comfortable:` alone, and each such
case MUST be recorded in the SUMMARY.

`py-0.5` and `space-y-0.5` are NOT floors — R4 gives them the compact values `py-0` and
`space-y-0`. Apply the real compact value; do not treat them as exceptions.

**R3 — Vertical axis only (LOCKED decision).**
Vary only `py-*`, `p-*`, `my-*`, vertical `space-y-*` / `gap-*` on vertical stacks, `min-h-*`,
and `leading-*`. NEVER vary `text-*` (font size is owned solely by the Text Size setting and the
two scales would compound), `px-*`, horizontal `gap-*` in a `flex items-center` row, border
widths, `rounded-*`, or avatar `size` props.

**R4 — Use the RESEARCH.md conventions table verbatim. Do not invent scales.**

| Baseline | `density-compact:` | `density-comfortable:` |
|---|---|---|
| `py-0.5` | `py-0` | `py-1` |
| `py-1` | `py-0.5` | `py-2` |
| `py-1.5` | `py-1` | `py-2.5` |
| `py-2` | `py-1` | `py-3` |
| `py-2.5` | `py-2` | `py-3` |
| `py-3` | `py-1.5` (tables/rows) or `py-2` | `py-4` |
| `p-2` | `p-1` | `p-3` |
| `p-3` | `p-2` | `p-4` |
| `p-4` | `p-3` | `p-5` |
| `space-y-N` / vertical `gap-N` | one step down | one step up |

**R5 — The `min-h-*` no-op pitfall (the single most important rule).**
`min-height` beats reduced padding. Adding `py-*` variants to an element that also carries a
fixed `min-h-*` produces a silent no-op — this is the root cause of the reported "AIO pages and
Epics page don't compact enough". For EVERY element you touch that has a `min-h-*`, add a matching
`density-compact:min-h-*` (roughly 25-30% smaller) and `density-comfortable:min-h-*` (roughly 15%
larger). Known instances: `AioTestRunsSection.tsx:365` `min-h-11`, `EpicsPage.tsx:46`
`min-h-[3rem]`, `SprintBoardTab.tsx:183,533,708` `min-h-[80px]`, `SubtasksPanel.tsx:77` and
`MrHealthPanel.tsx:63` `min-h-[160px]`.
Per-task verification: grep each touched file for `min-h` and confirm either none present, or a
matching `density-compact:min-h-` exists on the same element.

**R6 — Group wrappers keep their arbitrary child selector.**
Standup notes use `[&>*]:py-2` wrappers. Correct form is
`[&>*]:py-2 density-compact:[&>*]:py-1 density-comfortable:[&>*]:py-3`. Do NOT move the padding
down onto the child component — that would break the wrapper's `divide-y` rhythm.

**R7 — Do NOT touch `components/ui/card.tsx` or any `components/ui/*` shadcn primitive.**
A `density-compact:[--card-spacing:…]` on the Card primitive is exactly the token-driven global
approach the user rejected. Density belongs on the consumer container, never the primitive.

**R8 — Virtualized lists: never change `estimateSize` constants.**
Three surfaces use `@tanstack/react-virtual`. `BacklogPage.tsx` has `useVirtual = false`, so CSS
classes work unmodified. `SprintBoardTab.tsx` (`estimateSize: () => 120`) and
`NotificationPopover.tsx` (`estimateSize: () => 64`) are dynamically measured, so the estimate is
only an initial guess and measured heights replace it on mount. Apply CSS classes only. IF the
UAT checkpoint shows rows misaligned after flipping density while the Sprint Board is mounted,
the fix is a `virtualizer.measure()` call in an effect keyed on
`useSettingsStore(s => s.density)` — NOT JS-computed row heights. Do not pre-emptively add it.

**R9 — Skipping is allowed; silence is not.**
If a surface in the RESEARCH inventory turns out to be genuinely density-neutral, skip it and
record it in the SUMMARY disposition table with a one-line reason. Never drop a surface silently.

**R10 — Stale-claim corrections.**
There is NO TipTap/ProseMirror in this repo; wiki rendering is react-markdown +
`@tailwindcss/typography`, and `WikiRenderer.tsx` is the single attach point.
`issue-detail/ChangelogEntry.tsx` is NOT already covered — it is a gap.
</rules>
