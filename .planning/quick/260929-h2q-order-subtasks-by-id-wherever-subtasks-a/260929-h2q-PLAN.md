Helper contract (Task 1 creates it; Tasks 2 and 3 consume it). Types:
- `KeyLike = { key: string }`
- `compareIssueKeysNumeric(a: string, b: string): number` splits each key on the LAST '-'. It compares the prefixes with localeCompare, then compares the suffixes as integers. If either suffix is not an integer (as in fixtures like `ESHOP-10-S1`), it falls back to `a.localeCompare(b, undefined, { numeric: true })`. It never produces a NaN comparison.
- `orderSubtaskKeys(keys: string[], parentSequence?: ReadonlyArray<KeyLike | string>): string[]` builds `Map<key, index>` from the sequence. Keys in the sequence come first, by index. Keys not in the sequence follow, by compareIssueKeysNumeric. An undefined or empty sequence means a pure numeric sort. The function is pure and returns a new array.
- `orderSubtasks<T extends KeyLike>(subtasks: T[], parentSequence?)` is the same rule applied to objects by `.key`. It returns a new array.
- `orderSubtasksWithinParents<T extends KeyLike>(flat: T[], parentSequenceFor: (parentKey: string) => ReadonlyArray<KeyLike|string> | undefined, getParentKey: (s: T) => string | undefined): T[]` is group-stable. Each parent group keeps the position of its first appearance in the original list, and the items inside a group are reordered with orderSubtasks. Items with no parent key keep their original slot.
