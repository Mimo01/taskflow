# Quick 261119-nm6: Stray ``` after {noformat} blocks in WikiRenderer

Planned and executed inline. The diagnosis was line-precise before planning.

## Root cause
preprocessJiraMarkup strips one trailing newline from every {code}/{noformat} body. That is correct
for {code}, because jira2md's code template emits `\n` before the closing fence. jira2md converts
{noformat} by plain `{noformat}` → ``` substitution, though, so the closing fence glued onto the last
line (`foo bar````). It never closed, and it swallowed the rest of the document.

## Task 1 (TDD): failing tests, then fix at the conversion step
- RED: pipeline.test.tsx covers: trailing block, no trailing newline, mid-document (prose after
  must stay outside), two consecutive blocks, body glued to the tags, a literal ``` in the body,
  and a {code} control.
- GREEN: preprocess.ts puts the newline back outside the placeholder for {noformat}. In
  wikiToMarkdown, a block whose body has a 3+ backtick run gets both fences widened past the longest run.
- Verify: the whole lib/wiki suite (equivalence, corpus, editor round-trip), wiki-editor and
  WikiRenderer consumers, tsc, and biome.
