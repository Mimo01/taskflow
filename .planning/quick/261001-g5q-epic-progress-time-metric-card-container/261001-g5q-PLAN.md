<interfaces>
Current lib contracts (taskflow/src/lib/epic-progress.ts):
- type Metric = 'count' | 'sp'   -> becomes 'count' | 'sp' | 'time'
- weightOf(s, metric, spKey): number
- StatusBucket { id, name, cat, count, points, value }   -> add `seconds` (sum of aggregate original estimate, always computed)
- AssigneeBucket { id, name, done, inProgress, todo, remaining }   -> add `logged` and `estimate` (seconds, always computed)
- deriveBurnup / deriveStatusBuckets / deriveAssigneeBuckets / deriveForecast(stories, metric, spKey, ...)

Duration formatter (taskflow/src/services/jira/duration.ts):
- formatDuration(totalSeconds: number): string. Uses hours and minutes only: "0m", "45m", "2h", "2h 30m", "120h". It never produces days.

Card (taskflow/src/components/ui/card.tsx): Card (size 'default' | 'sm', role-less div, rounded-xl ring-1 bg-card, overflow-hidden), CardHeader, CardTitle (div), CardAction (col-start-2, right-aligned), CardContent.

Chart tooltip (taskflow/src/components/ui/chart.tsx): ChartTooltipContent accepts `labelFormatter` and `formatter(value, name, item, index, payload)`. A `formatter` replaces the whole row, so the indicator, label and value must be rendered by the formatter itself.

base-ui Tooltip (@base-ui/react 1.3.0, import { Tooltip } from '@base-ui/react/tooltip'): parts Root, Trigger (props `delay`, `closeDelay`, `render`), Portal, Positioner (sideOffset), Popup, Provider.
JSDOM EVIDENCE (probed by the planner with a scratch vitest file, then deleted): `userEvent.hover(trigger)` opens the popup on a `render={<div/>}` trigger. `userEvent.tab()` focusing a default button trigger opens it. fireEvent pointerEnter/mouseEnter also opens it. With `delay={0}`, `await screen.findByText(...)` finds popup text. Conclusion: use base-ui and do not build a hand-rolled popover.
</interfaces>
