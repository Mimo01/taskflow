# Quick 261116-fe7: Notifications data-loss fixes

Source: todos `notifications-jira-poll-page-cap` (high) and `notifications-due-reminder-id-and-cursor` (95-REVIEW WR-05/WR-06). The user picked these at the v1.14 close.

## Task 1: page the Jira notification searches
- files: `src/services/notifications.ts`, `src/services/notifications.test.ts`
- action: add a `searchAllNotificationPages` helper: 50 per page, step by the number of issues returned, bounded at 20 pages. A first-page failure returns null and the query yields nothing; a later-page failure keeps the pages fetched so far. Use it in queries A–D and drop `maxResults=20`.
- verify: with 35 issues and an instance capping pages at 20, all 35 come back via startAt 0 and 20.

## Task 2: cursor follows server time only
- files: `src/hooks/useNotificationPolling.ts`, its test
- action: exclude `due-date-reminder` items, which are stamped with the client clock, from the Jira cursor advance.
- verify: a poll returning a server event plus a later-stamped reminder sets the cursor to the server event.

## Task 3: due-day reminder id and label
- files: `src/services/notifications.ts`, test
- action: compare local calendar dates (string `YYYY-MM-DD`) instead of parsing the due date as UTC midnight. On the due day, append `-today` to the id; the day before keeps the date-only id, so stored items still dedupe.
- verify: tests with a pinned clock at 00:30 on the due day and 23:30 the day before.
