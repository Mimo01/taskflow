## SVG Design Patterns for Flow Motifs

### Cubic Bezier Curves
Use `C` (cubic bezier) commands in SVG `<path>` for smooth flowing curves. Key technique:

```svg
<!-- Smooth S-curve wave -->
<path d="M 200,512 C 350,300 500,700 700,400" stroke="#0ea5e9" stroke-width="40" fill="none" stroke-linecap="round"/>
```

- `M` = start point
- `C` = control-point-1, control-point-2, end-point
- Chain multiple `C` segments for complex waves
- Use `S` (smooth cubic) for automatic symmetric control points

### Design Principles for Small-Size Readability
1. **Minimum stroke width:** 40-60px at 1024x1024 scale (becomes ~1.5-2px at 32x32)
2. **Avoid thin details:** Anything under 30px at 1024 disappears at favicon size
3. **High contrast:** Blue/orange on white have excellent contrast; use them as primary strokes
4. **Simple silhouette:** The icon should be recognizable as a filled silhouette shape
5. **Safe zone:** Keep all content within the 824x824 squircle area with 60px inner padding (effective area ~700x700)
6. **No text:** Already confirmed -- text illegible at 32x32

### Color Usage
| Color | Hex | Contrast on White | Role |
|-------|-----|-------------------|------|
| Blue | #0ea5e9 | 3.0:1 (decorative OK, not text) | Primary flow element |
| Orange | #f97316 | 3.2:1 (decorative OK, not text) | Secondary flow element |
| Gray | #94a3b8 | 3.0:1 | Accent only |

Both blue and orange pass for large graphical elements but not for small text (WCAG AA requires 3:1 for large elements, 4.5:1 for text). This is fine for an icon.

### Composition Ideas (Claude's Discretion)
Possible approaches for "flow + tasks" abstract symbol:
1. **Intertwining waves** -- two curved strokes (blue + orange) weaving or flowing together
2. **Arrow-wave hybrid** -- flowing curve that resolves into a forward direction
3. **Circular flow** -- curves forming a cycle/loop suggesting continuous flow
4. **Gradient wave** -- single path transitioning from blue to orange via linearGradient
5. **Stacked flow lanes** -- parallel curved paths suggesting a kanban/stream

### SVG Gradient Technique
```svg
<linearGradient id="flow-grad" x1="0%" y1="0%" x2="100%" y2="0%">
  <stop offset="0%" stop-color="#0ea5e9"/>
  <stop offset="100%" stop-color="#f97316"/>
</linearGradient>
<path d="..." stroke="url(#flow-grad)" stroke-width="50" fill="none"/>
```

## Common Pitfalls

### Pitfall 1: SVG Filters at Small Sizes
**What goes wrong:** `feDropShadow` and blur filters become muddy blobs at 32x32.
**How to avoid:** Either remove filters from the sidebar variant (AppIcon.tsx) or use very subtle values (stdDeviation <= 4 at 1024 scale). Current icon uses stdDeviation=12 which is aggressive.

### Pitfall 2: Stroke Detail Vanishing
**What goes wrong:** Elegant thin curves at 1024px become invisible hairlines at 32px.
**How to avoid:** Test at 32x32 early. Minimum effective stroke: 40px at 1024 scale.

### Pitfall 3: Rasterization Artifacts
**What goes wrong:** `rsvg-convert` and browser renderers handle curves slightly differently; anti-aliasing can cause color fringing.
**How to avoid:** Use `stroke-linecap="round"` and `stroke-linejoin="round"` on all paths. Avoid very tight curves.

### Pitfall 4: JSX Attribute Conversion
**What goes wrong:** SVG uses kebab-case (`stroke-width`, `clip-path`, `flood-color`), React JSX uses camelCase (`strokeWidth`, `clipPath`, `floodColor`).
**How to avoid:** The existing AppIcon.tsx already handles this correctly. Follow the same pattern.

### Pitfall 5: Unique Filter/ClipPath IDs
**What goes wrong:** If AppIcon is rendered multiple times on a page, duplicate `id` attributes cause cross-references to break.
**How to avoid:** Current code prefixes IDs with `app-` (e.g., `app-sq`, `app-gC`). Keep this pattern.

## AppIcon.tsx Conversion Pattern

The existing component shows the pattern clearly. Key rules:
- `viewBox="0 0 1024 1024"` -- always 1024x1024
- `className` prop for external sizing (parent sets w-8 h-8 etc.)
- kebab-case SVG attributes become camelCase in JSX
- Filter IDs prefixed with `app-` for uniqueness
- macOS squircle clipPath applied to root `<g>`
