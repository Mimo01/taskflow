<objective>
Make more attachment file types previewable in the issue-detail attachment preview overlay — XML first (the user's example), then the other common text/config/code formats.

Root cause (verified in code): `resolvePreviewKind` only consults the filename extension when the MIME is empty, `application/octet-stream`, or `text/*`. Jira commonly reports XML as `application/xml`, JSON as `application/json`, YAML as `application/x-yaml`, etc., so those fall straight through to `'other'` and AttachmentsSection excludes them from the previewable list. The extension maps are also narrow (no sql, properties, ini, toml, diff, tsv, ...).

The preview pipeline itself (TextPreview / CodePreview in AttachmentPreviewModal, useAuthBlob.getText, the 2 MB pre-fetch cap and 256 KB truncation notice, ViewerToolbar font zoom, portal + usePreviewEscape + BACKDROP_ATTR) already exists and is NOT changed. The PDF data: URI path (WKWebView blob gotcha) is not touched. Images/video/audio already preview; only cheap extension additions are made there.

Output: extended classifier + highlighter languages + tests; tile icon for textual MIME types.
</objective>
