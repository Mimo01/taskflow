<objective>
Make the three dashboard cards (MY ISSUES, UPCOMING RELEASES, PAST 7 DAYS) look good and tell the truth when their data fails to load (wrong PAT, connection error).

What is wrong today (verified by reading the code):
1. Every card renders the full-page `ErrorState`: a red-bordered destructive `Alert` with an absolutely-positioned right-side button (`pr-18`). Inside a card it looks like a foreign red box, unlike the centred compact `EmptyState` the same cards use for their empty and no-sprint states. The generic branch also renders an empty `<AlertDescription />`.
2. The cards are whole-card clickable (`clickableCard` → `onClick` + `onKeyDown` on the Card). Clicks on Retry/Reconnect bubble up, so the card also navigates away (/my-tasks, /releases, /worklogs). Enter/Space on the focused button bubbles to the card's keydown handler, which calls `preventDefault()` and navigates, so keyboard Retry is broken.
3. HoursCommitsChart: the error, skeleton and tempo-off bodies are 280px tall but the chart body is 300px, so the card jumps 20px. The header legend still shows "0h logged · 0 commits" while in error. GitLab commit query errors are ignored, so a bad GitLab PAT shows as "0 commits" every day.

Fix: add one shared compact `CardErrorState` built on `EmptyState` (compact) that reuses the existing `isAuthError`/`getErrorSource` classification and stops event propagation from its button. Use it in all three cards. Even out the chart heights, hide the false totals, and say so when commits are unavailable.

Output: CardErrorState in components/ui/error-state.tsx plus the three card call sites, with tests.
</objective>
