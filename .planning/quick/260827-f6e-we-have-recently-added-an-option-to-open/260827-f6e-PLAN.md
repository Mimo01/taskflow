"Open in System Default", one "Open in {browser}" item per detected browser, and
"Copy link" — building on the existing user-selectable-browser feature (quick task

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rendered wiki/markdown content → context menu href | URLs originate from Jira/GitLab issue bodies and comments, i.e. attacker-influencable text |
| Renderer → OS process launch (`openUrl(url, browserPath)`) | A URL crosses into an OS-level browser invocation |
| Renderer → system clipboard | App writes arbitrary URL text into the user's clipboard |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-f6e-01 | Elevation of Privilege | `openExternalWith(url, browserPath)` | mitigate | `browserPath` is never user-typed — it comes only from `list_browsers`, a Rust-side allowlist of hardcoded candidate paths validated by `Path::exists()`. Never accept a browser path from rendered content or from a URL parameter. |
| T-f6e-02 | Elevation of Privilege | URLs from wiki content passed to `openUrl` | accept | Unchanged risk surface: `openExternal` already passes these same hrefs to `openUrl` on left-click today. This task adds no new URL source, only a new launch target. Tauri's opener plugin scope governs the scheme allowlist. |
| T-f6e-03 | Information Disclosure | `navigator.clipboard.writeText(href)` | accept | Only writes a URL the user explicitly right-clicked and chose to copy; no token or credential is ever in scope since hrefs come from rendered content, not from `settings.store`. |
| T-f6e-04 | Spoofing | Context-menu label "Open in {browser.label}" | mitigate | `label` is React-escaped text from the Rust `BrowserInfo` struct (fixed set), never `dangerouslySetInnerHTML`, so a hostile link cannot forge a menu entry. |
| T-f6e-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — zero new dependencies. RESEARCH confirms no clipboard plugin is needed (`navigator.clipboard` already proven in `IssueDetailContent.tsx`) and `base-ui` / `@tanstack/react-query` / `@tauri-apps/plugin-opener` are all already in `package.json`. If any task attempts an install, stop and escalate. |
</threat_model>
