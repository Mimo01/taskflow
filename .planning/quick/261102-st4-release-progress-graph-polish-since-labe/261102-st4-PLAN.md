# Quick 261102-st4: Release Progress graph polish

Follow-up to 261102-rzm (non-overlapping labels, commit 88d24fda). User-chosen decisions (locked):

## Decisions

1. **"since" header aside** → `since 1.4.2 · Oct 1` — previous release name, then muted date.
   - Name in `text-foreground/80` (or similar, slightly stronger than the muted date); `·` and date stay muted.
   - The version name truncates first (min-w-0 + truncate on the name span; date `shrink-0`); never wraps (one line).
   - No previous release (`axis.previousName === null`) → `since Oct 1` exactly as today.
   - Keep a hover title with the full text (and include the year in the title).
   - Date includes the year when the start is not in the current year (e.g. `Nov 20, 2025`).
2. **End-point dots** — small dot (r≈2.5–3) at the last point of the scope line (muted) and done line (green), with a background-coloured ring so it reads on the area fill. Merged scope==done → one dot. Dots must not collide with end labels (labels already offset; adjust layout padding if needed and keep the property tests green).
3. **Breathing room on short rows** — on the 110px compact band the inner plot is ~64px; reduce wasted vertical space (top headroom/marker band, x-tick row gap, margins) so lines get more height, without reintroducing overlaps. Flipped end labels must not mask a steep line: shrink/trim the label background rect (tight padding, or halo-only text) so at most the halo touches the line.
4. **Softer marker labels** — TODAY/RELEASE: smaller (10px), lighter (muted at ~70% opacity), keep uppercase + tracking. They must stay legible in dark mode. Update layout widths (char width) so collision math matches the new font size.
5. **Year on axis when needed** — when the axis range is not entirely in the current year, or it crosses a year boundary, the first tick and the first tick of each new year show the year (`Dec 2026`, `Jan 2027` style already exists for long ranges — make short ranges consistent, e.g. `Dec 28, 2025`). If changing `timeTicks` in lib/epic-progress.ts, check its other consumers (epic progress charts) — prefer a burnup-local formatter if the shared change would alter other pages.
