<objective>
Release detail "Not covered by tasks above" list: evaluate MERGED MRs for the TASK reason so they get the real 'Not in version' / 'No task' pill plus the existing Fix actions, and HIDE CLOSED MRs from that list. LOCKED MRs stay muted "Not evaluated".

Purpose: merged MRs have shipped code on the release branch, so a missing/out-of-version task is a real coverage gap the user should be able to fix in place; closed MRs never landed and "fixing" them would wrongly add work to the release.

Locked user decisions (from the request):
- MERGED: run `evaluateTaskDrift` → taskReason 'no-linked-task' | 'not-in-fix-version' (or null when covered). Same Fix actions as open MRs (Jira "add to <version>"; "link a release task" MR-title edit — GitLab allows editing a merged MR's title).
- CLOSED: removed from the secondary list only. NOT removed from driftRows / primary task rows / +N extras / donut / label counts.
- LOCKED: unchanged (muted "Not evaluated").
- BR/MS stay open-only: merged rows keep br/ms 'na' and `evaluated: false`; countBrMsFlaggedMRs / countBranchFlaggedMRs / countMilestoneFlaggedMRs results do not change.

Output: updated driftDetection.ts + UnifiedTaskTable.tsx doc comments, updated/added tests, one commit.
</objective>
