<objective>
Make the onboarding wizard versioned. When an app update adds or changes a wizard step, users who already finished onboarding go through the wizard again on next launch, with everything pre-filled, starting on the first step that changed.

Purpose: new setup (e.g. Release Management, added in 261112-lrr) actually reaches existing users without making them re-enter credentials.
Output: a pure versioning/pre-fill module, a persisted `onboardingVersion`, an in-memory `rerunActive` gate, a launch-time check hook, and the manual reset moved onto the shared helper.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-m5v-01 | Information disclosure | startWizardRerun | accept | Same readSecret-into-memory path as the existing manual reset. The store is not persisted and nothing is logged. Do not add tokens to any console/debug output. |
| T-m5v-02 | Tampering | settings migrate v37 | mitigate | Only sets onboardingVersion when undefined, and coerces from `onboardingComplete === true`. Unit-tested so it can never set a version above WIZARD_VERSION. |
| T-m5v-03 | Denial of service | useWizardRerunCheck | mitigate | Ref guard plus a `!rerunActive` check stop a re-entry loop. A stale version only re-triggers on a new launch, and that is the intended behavior. |
</threat_model>
