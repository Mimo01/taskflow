   Extract this as a named type alias `NotificationType` so it stays DRY across both files. Define it in `notifications.store.ts` and import in `notifications.ts`.

2. **Add GitLab @mention detection** inside `fetchNewGitlabNotes`:
   - In the non-system note handling (the existing `results.push` at line ~319), check if the note body contains `@{currentUsername}` where currentUsername is a new parameter.
   - If the note body mentions the current user, set `notificationType: 'gitlab-mention'` instead of `'mr-note'`.
   - Add `currentUsername: string | null` to `fetchNewGitlabNotes` params. Pass it from `fetchNewNotifications`. The caller (polling hook) will need to provide this -- for now, accept `null` (Task 2 wires it).

3. **Add Jira all-comments fetcher** inside `fetchNewJiraComments`:
   - Add a new inner function `fetchAllComments()` that runs a JQL query: issues where `assignee = "{username}" OR reporter = "{username}" OR watcher = "{username}"` with comments updated since cursor.
   - For each comment (excluding self-authored, checking `comment.author.displayName !== displayName`), create a NotificationItem with `notificationType: 'jira-comment'` and `id: 'jira-allcomment-{commentId}'`.
   - Add this to the `Promise.allSettled` array alongside existing `fetchIssueUpdates()` and `fetchCommentMentions()`.

4. **Add MR approval fetcher** as `fetchGitlabApprovals` (new function):
   - For each MR in mrList where `mr.author.id === currentUserId`, call `GET /api/v4/projects/{project_id}/merge_requests/{iid}/approvals`.
   - Parse response for `approved_by` entries with `approved_at` after cursor. Also check if `approved` boolean changed.
   - Create NotificationItems with `notificationType: 'mr-approval'`, `id: 'gitlab-approval-{mrIid}-{approver.user.id}'`.
   - Body: "Approved by {name}" or "Changes requested by {name}".

5. **Add pipeline failure fetcher** as `fetchGitlabPipelineFailures` (new function):
   - For each MR in mrList where `mr.author.id === currentUserId`, call `GET /api/v4/projects/{project_id}/merge_requests/{iid}/pipelines?per_page=5&sort=desc`.
   - Filter pipelines with `status === 'failed'` and `updated_at` after cursor.
   - Create NotificationItems with `notificationType: 'pipeline-failure'`, `id: 'gitlab-pipeline-{pipeline.id}'`.
   - Body: "Pipeline #{id} failed on {mr.source_branch}".

6. **Add Jira issue assignment fetcher** inside `fetchNewJiraComments` (or as sibling):
   - In the existing `fetchIssueUpdates`, when parsing changelog histories, detect `item.field === 'assignee'` where `item.toString` matches the current user's displayName AND `item.fromString` does NOT match (newly assigned, not self-assign).
   - For these, emit a SEPARATE NotificationItem with `notificationType: 'issue-assignment'`, `id: 'jira-assign-{issueKey}-{history.created}'`.
   - This is in ADDITION to the existing issue-update notification for the same changelog entry.

7. **Add due date reminder** as `fetchJiraDueDateReminders` (new function):
   - JQL: `assignee = "{username}" AND duedate >= now() AND duedate <= endOfDay("+1")` with `fields=summary,duedate,status`.
   - Create NotificationItems with `notificationType: 'due-date-reminder'`, `id: 'jira-duedate-{issueKey}'`.
   - Body: "Due {duedate}" (format as relative: "Due tomorrow", "Due today").

8. **Wire all new fetchers into `fetchNewNotifications`**:
   - Add `gitlabUsername: string | null` to opts.
   - Pass `gitlabUsername` to `fetchNewGitlabNotes` for @mention detection.
   - Add `fetchGitlabApprovals` and `fetchGitlabPipelineFailures` to the GitLab tasks array.
   - Add `fetchJiraDueDateReminders` to the Jira tasks array.
   - All new fetchers use `Promise.allSettled` pattern -- failure of one does not break others.
