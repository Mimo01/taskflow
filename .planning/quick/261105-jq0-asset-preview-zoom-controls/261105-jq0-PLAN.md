<objective>
Give both asset-preview surfaces (attachment preview modal and wiki/AIO inline-image lightbox) one shared viewer with best-practice controls. Image controls: zoom buttons, Ctrl/Cmd+wheel and pinch zoom toward the cursor, drag pan, Fit, 100%, live % readout, double-click toggle, rotate, keyboard shortcuts, Download and Open externally. Text/code previews get font-size zoom. PDF/video/audio keep their native controls and gain Download and Open externally.

Purpose: The user wants viewer-grade control (at minimum zoom) whenever they open a supported asset.
Output: Pure viewer math module plus tests, save/open helper plus capability fix, shared ImageViewer/ViewerToolbar/useImageViewer, both surfaces rewired, and a hardware checkpoint for real trackpad/wheel input in the Tauri build.

Locked decisions honoured (from CONTEXT.md, referenced as D-01..D-05 in tasks):
- D-01: BOTH surfaces use ONE shared zoomable image viewer component.
- D-02: Image controls = zoom in/out buttons; Ctrl/Cmd+wheel and trackpad pinch toward cursor; drag to pan when zoomed; Fit, 100% (1:1), live % readout, double-click toggle; rotate 90 deg.
- D-03: Keyboard shortcuts (+ / - / 0 at minimum); toolbar Download and "Open in external app".
- D-04: Existing Esc / Left / Right behaviour keeps working without conflicting with panning (arrows pan only when zoomed past fit, else navigate).
- D-05: Engine = hand-rolled reducer + hook (research rejected react-zoom-pan-pinch: no Safari gesture* events, no rotation, no Cmd+wheel, no natural-px 100%). Must work in macOS WKWebView.
- Orchestrator decision: Download keeps its current behaviour (save, then auto-open). Open externally is an additional action. The opener capability is fixed (opener:allow-open-path, narrowly scoped) because both depend on it.
- Discretion (decided here): text/code get font-size zoom. PDF/video/audio stay native and get only Download + Open externally. The toolbar is a bottom-centre bg-black/60 rounded-full pill with white/80 ghost icon buttons on one compact row.
