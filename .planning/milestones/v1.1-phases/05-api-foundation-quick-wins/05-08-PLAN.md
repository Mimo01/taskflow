Purpose: User sees releases from their selected Jira project, not from some default/random project.
Output: Corrected URL + response unwrap in jira.ts; setState-based guard in auth.store.ts; updated/added tests.

From taskflow/src/stores/auth.store.ts (onRehydrateStorage, lines ~79–83):

```typescript
// BUG: Direct mutation on `state` object is overwritten when Zustand applies
// the hydrated snapshot from async Tauri storage. The null is set but then
// overwritten milliseconds later by the storage callback.
onRehydrateStorage: () => (state) => {
  if (state && state.activeJiraProject && /^\d+$/.test(state.activeJiraProject)) {
    state.activeJiraProject = null;  // <-- overwritten by async hydration
  }
},

// FIX: Use useAuthStore.setState() — this runs AFTER hydration completes.
// The callback pattern: outer () returns inner (state) => void.
// The inner callback is called by Zustand after state is fully hydrated.
// Using setState here correctly replaces the stale field in the live store.
onRehydrateStorage: () => (state) => {
  if (state && state.activeJiraProject && /^\d+$/.test(state.activeJiraProject)) {
    useAuthStore.setState({ activeJiraProject: null });
  }
},
```

Note: `useAuthStore` is the const exported from the same file — it's in scope. The callback runs post-hydration so the setState takes effect on the already-hydrated store, not the pre-hydration state object.
