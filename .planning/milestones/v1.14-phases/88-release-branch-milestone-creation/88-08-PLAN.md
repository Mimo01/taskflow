<objective>
Close the pure-logic half of CR-03 (blocker, RELBR-04): `resolveBranchState` currently maps
`branchExists === undefined` to `{ kind: 'loading' }`, which is *also* the value produced when
the `gitlab-branch` query errors. `fetchBranch` throws on any non-404 (401/403/500/timeout), so
a real failure is indistinguishable from an in-flight request.

This plan changes only the React-free module and its unit tests, establishing the contract the
hook and sidebar consume in Plan 88-09 (interface-first ordering — the consumer plan receives
the type, it does not have to discover it).

Also closes WR-07: two tests in `releaseBranch.test.ts` contain literal unescaped `0x01` and
`0x7F` bytes; any formatter or encoding round-trip silently inverts them into assertions that a
valid ref name is invalid.

Purpose: give the branch state machine an error state so the UI can offer recovery instead of a
permanent spinner.
Output: a `'check-failed'` `BranchState` variant, a `branchCheckFailed` parameter, and tests.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-88-08-01 | Tampering | `resolveBranchState` precedence | mitigate | The `check-failed` branch is inserted strictly AFTER `isValidGitRefName`, so an error state can never bypass ref validation and expose a create action for an invalid ref. Asserted by a line-order acceptance criterion and by the two precedence tests. |
| T-88-08-02 | Elevation of privilege | Create-branch reachability | mitigate | `check-failed` is a terminal display state; it does not render or enable a create action (that stays gated on `'missing'` in Plan 88-09). A failed permission check therefore never becomes an accidental write affordance. |
| T-88-08-03 | Information disclosure | Error state payload | mitigate | `check-failed` carries only `branchName` — no error object, no status code, no URL. The PAT and response bodies cannot reach the UI through this state. |
| T-88-08-SC | Tampering | npm installs | mitigate | No new dependencies. If an install appears necessary, stop and raise a blocking human checkpoint. |
