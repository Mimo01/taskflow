<objective>
Close CR-01 (blocker, RELBR-03): the Releases-list "No release branch" indicator currently
defaults to "drift" on absence of evidence. It is derived from bare Set membership over
`releaseBranches ?? []`, so it renders a false positive on every page load until the query
resolves, and permanently whenever the query errors (401/403/500/timeout).

Also closes WR-04 (missing-milestone indicator fires on undated / already-released versions,
duplicating the existing "No date set" badge) and WR-06 (icon-only indicators have no
accessible name), both of which live in the exact JSX being edited for CR-01.

Purpose: the whole point of this indicator is a trustworthy drift signal. It must fire on
*confirmed* absence, never on unknown state.
Output: guarded drift derivation in `ReleasesTab.tsx`, a branch-fetch-error chip, and three
new regression tests that fail against current `main`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitLab REST API → renderer | Milestone titles and branch names originate on a remote server and are rendered into the Releases list |
| Query error object → UI copy | Error state from a failed authenticated fetch drives a user-visible chip |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-88-07-01 | Information disclosure | Branch-fetch-error chip in `ReleasesTab.tsx` | mitigate | The chip renders a fixed literal string ("GitLab unavailable") and a fixed `title`. It never interpolates the query's `error` object, the request URL, or the PAT. Acceptance criteria assert the exact literal. |
| T-88-07-02 | Spoofing / Repudiation | Drift indicator trustworthiness | mitigate | This plan's core change: the indicator now requires `isSuccess` before asserting absence, so a suppressed or failed response cannot fabricate a drift claim the user would act on. |
| T-88-07-03 | Tampering | Rendered milestone/branch names | accept | Titles are rendered as React text children (auto-escaped) and into `title` attributes; no `dangerouslySetInnerHTML` is introduced. No new sink. |
| T-88-07-SC | Tampering | npm installs | mitigate | No new dependencies are added by this plan. If the executor finds an install is required, stop and raise a blocking human checkpoint. |
</threat_model>
