# Phase 91.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (already initialized — `components.json` present) |
| Preset | `base-nova` (baseColor: neutral, cssVariables: true) |
| Component library | radix (via shadcn) |
| Icon library | lucide-react |

This phase adds **no new shadcn components**. It reassembles existing primitives already used by `IssuesSection.tsx` / `MrDriftSection.tsx`: `Badge`, `Progress`, `CachedAvatar`, plus raw `div`/`button`/`span` (div+flex row pattern — no `<table>`, per D-01 and the project's recorded table-vs-flex-row lesson).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (`gap-1`), cell internal padding |
| sm | 8px | Row internal gaps (`gap-2`), header-to-badge spacing |
| md | 16px | Sub-line indent (D-03 "~16px"), section padding |
| lg | 24px | not used in this phase's surface |
| xl | 32px | not used in this phase's surface |

Exceptions:
- **28px** action-cell width (`w-[28px]`) — carried verbatim from P90 `DriftMarkCell`/`DriftActionCell`; do not round to the 8pt scale, it is a deliberately fixed hit-target inherited unchanged.
- **20px** avatar size (`size={20}` on `CachedAvatar`) — carried verbatim from both source files.
- Row vertical rhythm stays `py-1` (task rows may use `py-1.5` to match today's `IssuesSection`, sub-lines `py-1`) — not on the 8pt scale but inherited from the two files being merged; do not invent a new value.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Task row (key/summary/status) | 14px (`text-sm`) | 400 (regular) | 1.5 (Tailwind default for `text-sm`) |
| MR sub-line (D-03: "one size smaller, muted") | 12px (`text-xs`) | 400 (regular) | 1.5 |
| Section heading / column header labels | 12px (`text-xs`) | 500 (medium, `font-medium`) | 1.2 |
| Badge / state pill text | 10-12px (`text-[10px]`/`text-xs`, matches existing `Badge` usage) | 500 (medium, shadcn Badge default) | 1 |

Only two weights declared: **400 regular** (body/sub-line content) and **500 medium** (headings, badges, section titles) — matches what both source files already use; no bold (700) anywhere in this surface.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--card` (theme token) | Page/section background |
| Secondary (30%) | `--muted` at low opacity (`bg-muted/30`, `bg-muted/40`) | Header strip background, row hover |
| Accent (10%) | `--primary` (theme token, renders as blue in this app) | Task key link, linkified ticket keys inside MR titles, `!iid` GitLab link hover-underline |
| Destructive | `--destructive` / literal `red-600`/`red-400` (existing P90 convention) | Sticky fix-cell error state ONLY (`AlertTriangle` in red, click-to-retry) |

Accent (`--primary`, rendered as blue) reserved for:
- Task row key button (`row.issue.key`, opens full issue)
- Linkified Jira ticket keys inside an MR sub-line title (`matchTicketKeyInTitle` matches)
- Nothing else — MR `!iid` link uses `text-xs hover:underline` with no color override (inherits foreground, not accent), matching the current `MrDriftSection` treatment (not `IssuesSection`'s per-state coloring, which this phase supersedes with the badge-only state signal)

Semantic (non-primary/non-destructive) colors carried unchanged from P89/P90, used only where already established:
- **Orange** (`orange-600`/`orange-400`, `orange-50`/`orange-950` bg) — flagged/warning state: BR/MS flag glyph, degraded-milestone banner, `⚠ No merge request` line, out-of-scope-key warning glyph
- **Green** (`green-600`/`green-400`) — resolved/ok state: BR/MS check glyph, merged-MR badge tint
- **Blue** (`blue-600`/`blue-400`) — opened-MR badge tint (distinct from accent/primary; this is the `Badge variant="outline"` state ternary, unchanged from both source files)
- **Gray/muted** (`text-muted-foreground`, `gray-400`/`gray-500`) — closed-MR badge tint, degraded "MR status unavailable" line, `—` placeholders, loading placeholder text

These four semantic colors are pre-existing, established across P89/P90, and re-hosted, not introduced. Do not add a fifth.

## Component & Layout Contract

(Phase-specific addendum — the structural contract the checker/planner/executor need beyond the standard template sections.)

### Primary table — shared column grid (D-02)

Both task rows and MR sub-lines share one span-width grid (mirrors `MrDriftSection`'s existing header strip geometry):

| Column | Width | Task row content | MR sub-line content |
|--------|-------|-------------------|----------------------|
| Key | `w-[72px]` flex-none | Jira key (click → full issue, overlay-button pattern) | `!iid` (click → GitLab MR) |
| Summary | `flex-1 min-w-0` | Issue summary (`truncate`/`line-clamp-1`) | Linkified MR title (ticket keys → `onNavigateToIssueFromMR`) |
| Assignee/Author | flex-none, `CachedAvatar size={20}` + name | Jira assignee | MR author |
| Status | flex-none | `statusPillClass` pill (wrapped in a flex div, per the recorded pill-needs-flex-parent lesson) | State `Badge` (merged/opened/other tint ternary) |
| BR gutter | `w-[28px]` flex-none | **empty** (D-06 — no rollup) | `DriftActionCell` (retarget), re-hosted verbatim from P90 |
| MS gutter | `w-[28px]` flex-none | **empty** (D-06) | `DriftActionCell` (assign-milestone), re-hosted verbatim from P90 |

The TASK drift column is dropped entirely from the presented grid (criterion 4) — do not reserve its width.

### Visual hierarchy — what the eye lands on

Primary anchor is the **task row**: the accent-colored Jira key plus the status pill are the first read, at `text-sm`/weight 500. MR sub-lines are deliberately secondary — indented, `text-xs`, muted foreground — so a task with N MRs still scans as one unit rather than N+1 competing rows. Drift marks in the BR/MS gutters are the only elements permitted to pull attention *away* from that order, and only when a drift is actually present (semantic orange against an otherwise neutral row). Nothing else on the surface competes for first read.

### Row anatomy (D-01, D-03, D-04, D-05)

- Structure: `div` + flex rows, not `<table>`. One div per task row, one div per MR sub-line, all inside one section container.
- Task row: `border-b border-border/50` separator, normal weight/size (`text-sm`), full-row click via **overlay-button pattern** — an `absolute inset-0` `<button>` as a sibling of the key `<button>`, never `div[role=button]` wrapping a nested button (recorded project pattern, mandatory).
- MR sub-line: indented ~16px (`pl-4` or equivalent), `text-xs`, `text-muted-foreground`-weight treatment, **no border** between sibling sub-lines — only the parent task row carries the boundary rule.
- Hover/reveal scope: `group/row` boundary sits on the **individual MR sub-line** (D-05), not the task block — reveal must not cascade from hovering the task row or from hovering a sibling MR line. This is a deliberate narrowing of P90's original `group/row` (which scoped to the whole drift row); rename/rescope the group class during re-hosting, don't leave it task-row-scoped by accident.
- MR sub-line has no line-wide click target — only `!iid`, linkified keys, and BR/MS cells are interactive.

### State line variants inside the MR-slot (mutually exclusive per task, D-07/D-08/D-17)

1. **Streaming/pending** — `loading merge requests…`, muted, while MR channel queries are in flight. Must render for every task on initial load; must never coexist with state 2.
2. **Resolved-empty (healthy)** — `⚠ No merge request`, orange-muted glyph + text.
3. **Resolved-empty (degraded)** — `— MR status unavailable`, neutral grey, tooltip explains no milestone matched.
4. **One or more MR sub-lines** — normal render, shared grid.

States 2 and 3 must never render while state 1's condition holds (D-17 hard constraint) — this is a state-machine correctness requirement, not merely a visual one, and the checker should treat a flash of state 2/3 before MR data resolves as a defect.

### Secondary table (D-10 through D-13)

- Same row renderer as an MR sub-line, key column repurposed to show either the flagged out-of-scope key (warning glyph + tooltip) or a plain `—` for keyless MRs.
- Full BR/MS fix cells active (same `DriftActionCell` instances, same behavior as primary table).
- Whole section (heading included) is conditionally rendered — absent entirely when there are zero uncovered MRs.

### Header (D-14, D-15)

- One heading row carries both: the Jira `N / M done` `Badge` + `Progress` bar (existing `IssuesSection` treatment, unchanged), and a new flagged-count `Badge` — count is **distinct MR ids with BR-or-MS flagged, deduped across both tables** (a multi-key MR counts once; an MR flagged on both channels counts once).
- Exact placement of the flagged-count badge relative to the done badge is Claude's/executor's discretion (CONTEXT confirms this is undecided) — recommend placing it immediately after the done badge, same `gap-1.5` rhythm as today's `flaggedCount` badge in `MrDriftSection.tsx:349`.

### Degraded banner (D-16)

- Single `AlertTriangle` + text banner, `orange-300`/`orange-950` border/bg treatment (verbatim styling from either existing banner — they're visually identical today), positioned **above the primary table**, not duplicated below a second section.
