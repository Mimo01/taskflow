## UAT-91.1-A: two rounds in one live session

**Round 1 (tasks 1-2, prior commits `81112c97`, `7ea40c82`).** The developer walked the

> was before."

This is recorded here as the gap's live outcome; **`91.1-UAT.md` is deliberately left untouched

consolidated table.

## Accomplishments (task 4 — consolidation)

- `TaskRow` gains a compound MR cell placed after Status and before BR/MS. It renders the
  pre-v1.14 look verbatim per the developer's request ("like it was before"): `GitMerge` icon +
  state-coloured `!iid` link (green/merged, blue/opened, grey/other) + outline state badge
  showing the state text.
- `selectDisplayMr(mrs)` (exported, pure) picks which MR to show when a task carries 2+: a
  flagged MR wins, ties broken by highest `iid`; with no flag, highest `iid` wins. Every MR
  stays in the data — nothing is dropped — and any extras surface via a `+N` marker
  (`mr-extra-count`) whose title tooltip lists the hidden MRs' `!iid`s.
- The task row's BR/MS cells stopped being blank spacers: they now render the selected MR's
  verdicts through the same `DriftActionCell`/`DriftMarkCell` components `MrSubLine` used,
  including the full pending/error/actionable/inert state machine and `useMrFixMutation` wiring.
- The four `MrSlot` states (`mr-slot-pending`, `mr-slot-failed`, `mr-slot-none`,
  `mr-slot-unavailable`) moved into the same MR-cell space on the same row, keeping identical
  `data-testid`s, tooltip strings and precedence order (pending > failed > verified-empty) as
  before — plans 06/08's state coverage keeps asserting unmodified.
- Row interactivity preserved via the existing sibling-overlay pattern: the MR link and both
  drift-action cells get `relative z-10` (win the click above the row's full-width overlay
  button); the slot-state text/badge/marker get `pointer-events-none` (clicks fall through to
  open the row). `group/row` moved from the (now-removed) sub-line onto the task row itself so
  the BR/MS action-icon hover-reveal still works.
- Per-task-group `border-b` separators (established in task 2) are unaffected — they still
  divide one task's row from the next, and there's now only ever one row per task to separate.
- `MrSubLine` is untouched and still renders the secondary (uncovered-MRs) table exactly as
  before — title linkification via `matchTicketKeyInTitle`, the `taskReason`-driven key-cell
  variants, and the `isFlagged` text-muting from plan 09's task 2.
- Badge filtering (plan 09) needed no new code: `UnifiedTaskTable`'s existing
  `filteredPrimaryRows` already restricts each task's `mrs` to the active category's matches
  before `TaskRow` renders, so `selectDisplayMr` automatically prefers a filter match.
