<objective>
Close VERIFICATION gap 1 (CR-01 + WR-02) and the resolver half of gap 3
(CR-03/CR-04) inside the pure verdict module.

Today `TrackingMR` does not project `target_branch` and step 4 accepts ANY
`state === 'merged'` MR as merge-back evidence. In the git-flow shape this
feature exists to police, `release/X` is merged by two MRs — one into `master`,
one into `develop`. If only the `master` MR merged (the exact failure MERGE-01
exists to detect), the row renders a green "Merged into develop" citing the
`master` MR. Separately, steps 2 and 3 map "channel permanently unavailable" to
`{ kind: 'loading' }` with no terminal fallback — the same defect class
`releaseBranch.ts` already guards against with its `check-failed` /
`unresolvable` kinds.

Purpose: the verdict has to be trustworthy and terminal, not merely rendered.
Output: a corrected 11-step resolver plus regression cases that fail against
today's code.
</objective>
