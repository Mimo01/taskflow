## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitLab/Jira API data → pure logic | MR titles, source branches and milestone objects originate from external systems and are parsed for Jira keys here |
| Pure logic → React render layer | The `DriftRow[]` this module returns is rendered directly; any string it passes through reaches the DOM |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-89-05 | Denial of Service | `extractTicketKeys` applied to every MR title and source branch across a full-project MR set | accept | `linkEngine`'s regexes are anchored, non-backtracking key patterns already applied at the same scale by the shipped `buildWrongMilestoneMap`; the union is bounded by the project's MR count, not by attacker-controlled repetition. |
| T-89-06 | Tampering | Attacker-chosen MR title containing a Jira key of an unrelated release | accept | Key linkage is an advisory reconciliation signal, not an authorization decision — a mislabelled MR surfaces as drift, which is the intended outcome. No write action is taken on this data in this phase (phase boundary is read-only). |
| T-89-07 | Information Disclosure | `DriftRow.mr` carries the full `GitLabMR` object into the render layer | mitigate | Only list-endpoint fields are present (no `description`, no discussions, no approvals). Keep the row type carrying `GitLabMR`, not `GitLabMRDetail`; do not widen it. |
| T-89-08 | Repudiation | D-10/D-11 semantics silently reverted by a later refactor toward DRIFT-07/DRIFT-08's literal text | mitigate | The `state classification` describe block contains a named regression test asserting a draft MR IS evaluated and flagged, plus an inline D-10 comment at the `state === 'opened'` gate. |
| T-89-SC | Tampering | npm/pip/cargo installs | n/a | No packages installed in this phase (RESEARCH § Package Legitimacy Audit: not applicable). |
