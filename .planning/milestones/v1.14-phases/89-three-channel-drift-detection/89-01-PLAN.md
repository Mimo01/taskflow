<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tauri app → GitLab REST API | Outbound authenticated request; branch names and milestone titles (GitLab-sourced strings) are interpolated into the request URL |
| GitLab REST API → app | Untrusted JSON response parsed as `GitLabMR[]` with no runtime validation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-89-01 | Tampering | `fetchBranchTargetedMRs` URL construction | mitigate | `encodeURIComponent(targetBranch)` — release branch names contain `/` and must not be able to inject additional query params or path segments. Asserted in the unit test (Task 3 behavior: `release/33.5.0` percent-encoded). |
| T-89-02 | Information Disclosure | PAT in `PRIVATE-TOKEN` header, devtools instrumentation | mitigate | All calls go through `apiFetch('gitlab', ...)`, which already redacts credentials in its devtools instrumentation and marks disconnect on 401. No raw `fetch` is introduced (D-19). |
| T-89-03 | Denial of Service | `while(true)` pagination loop with no page cap (D-17) | accept | Loop terminates on `data.length < perPage`; GitLab returns an empty array past the last page, which is a short page. A page cap is explicitly forbidden by D-17 because it reintroduces the GGX-WARN-01 silent-truncation bug. Risk is a slow fetch on a very large project (RESEARCH A4), not an infinite loop. |
| T-89-04 | Spoofing | Response shape trusted without runtime validation (`as GitLabMR[]`) | accept | Matches the existing convention for every fetcher in `gitlab.ts`; the endpoint is an authenticated first-party GitLab instance. Assumption A2 (field presence) is resolved by the Task 1 probe rather than by runtime schema validation. |
| T-89-SC | Tampering | npm/pip/cargo installs | n/a | This phase installs no packages (RESEARCH § Package Legitimacy Audit: "Not applicable"). No supply-chain checkpoint required. |
</threat_model>
