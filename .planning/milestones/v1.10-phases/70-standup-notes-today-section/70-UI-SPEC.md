## Scope Boundary

This spec covers **only the Today column** — the right 50% of `/standup-notes` currently
rendered by `TodayColumnPlaceholder`. The page shell, header, left column (Yesterday), and
all Phase 69 patterns are out of scope and must not be changed.

The Today column replaces `<TodayColumnPlaceholder />` at `StandupNotesPage.tsx` line ~323
with a new `<TodayColumn />` component (plus per-section subcomponents) under
`src/routes/standup-notes/`.

## Spacing Scale

Standard 8-point scale in use across the app. No phase-specific exceptions.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-text gaps (`gap-1`), sub-item indent fine-tuning |
| sm | 8px | Row vertical padding (`py-2`), inter-subitem gap (`gap-2`) |
| md | 16px | Column horizontal padding (`px-6` = 24px; see note), section gap |
| lg | 24px | Column horizontal padding (`px-6`), column top padding (`py-4`) |
| xl | 32px | Between sections when section has content |
| 2xl | 48px | Not used in this column |
| 3xl | 64px | Not used in this column |

Note: The existing right-column wrapper uses `overflow-auto` with no padding
(`<div className="w-1/2 overflow-auto">`). The inner `TodayColumn` component must apply
`px-6 py-4` to its root div — matching the Yesterday column's wrapper padding pattern
(see `TodayColumnPlaceholder`: `className="flex flex-col h-full px-6 py-4"`).

Log Work button touch target: 32px min-height (`h-8` = 32px); acceptable because it is
a secondary action and not the only affordance on the row.

## Row Anatomy

### In Progress Row / Up Next Row

Each row is an interactive `<button>` (full width, whole-row click → `onIssueClick(key)`).
A secondary Log Work trigger sits at the right edge — must stop propagation to prevent
navigating on click.

```
<button type="button" class="w-full flex items-center gap-2 rounded px-2 py-2 text-left
                              hover:bg-muted/50 focus-visible:ring-2 focus-visible:ring-ring">
  <IssueTypeIcon typeName={issueType} class="size-4 shrink-0" />          -- issue-type icon
  <span class="text-xs text-muted-foreground font-mono shrink-0">KEY</span>-- e.g. "PROJ-123"
  <span class="flex-1 min-w-0 truncate text-sm">Summary text</span>       -- truncates
  {storyPoints && (
    <span class="shrink-0 rounded bg-muted px-2 py-1 text-xs text-muted-foreground">
      {storyPoints} pts
    </span>
  )}
  {loggedTime && (                                                         -- In Progress only
    <span class="shrink-0 rounded bg-muted px-2 py-1 text-xs text-muted-foreground ml-1">
      {loggedTime}
    </span>
  )}
  <LogWorkPopover                                                          -- secondary action
    issueKey={key}
    jiraBaseUrl={jiraBaseUrl}
    initialDate={todayString()}
    onClick={(e) => e.stopPropagation()}
  />
</button>
```

Notes:
- `IssueTypeIcon` reused from `@/components/ui/issue-type-icon` (same as YesterdayColumn).
- Issue key sits before summary, in monospace muted text — matches `IssueActivityGroup` convention.
- SP badge: "N pts" (`N` = story points value). Shown when the field is populated. Omit when null.
- Logged-time chip: formatted duration string (e.g. "4h", "1h 30m") using `formatDuration()` from
  `@/services/jira/duration`. Shown on In Progress rows when today's Tempo worklogs exist for
  the issue. Not shown on Up Next rows.
- Log Work button: uses `LogWorkPopover`'s built-in trigger (Clock icon + "Log Work" label).
  The popover trigger is a `<Button variant="ghost" size="sm">` — the built-in trigger from
  `LogWorkPopover.tsx` is acceptable as-is; do not re-skin it.
- Row border: `divide-y divide-border` on the parent wrapping div separates rows.

### MRs Awaiting You Row

No Log Work trigger. The row is NOT navigable (MRs don't use `onIssueClick`). It is a static
display row. If the app has an MR detail page, a future phase can add navigation; for Phase 70
the row is non-interactive (no `<button>` wrapper, no cursor-pointer).

```
<div class="flex items-center gap-2 py-2 px-2">
  <GitBranch class="size-4 shrink-0 text-muted-foreground" />     -- Lucide GitBranch icon
  <span class="text-xs text-muted-foreground font-mono shrink-0">!{iid}</span>
  <span class="flex-1 min-w-0 truncate text-sm">{title}</span>
  <span class={reviewStateLabelClass}>{reviewStateLabel}</span>   -- right-aligned label
</div>
```

Review state label classes:
- "awaiting review" → `text-xs text-muted-foreground shrink-0`
- "changes requested" → `text-xs text-amber-600 dark:text-amber-400 font-semibold shrink-0`

Review state derivation: use `review_state` from the MR object returned by `fetchReviewerMRs`.
When `review_state === 'approved'`, the MR is not "awaiting you" — filter it out entirely.
Show only MRs with `review_state === null` (never reviewed) or `review_state === 'changes_requested'`.

### Pinned Row

Two variants — Jira issue and AIO cycle — share the same row structure but differ in icon and
click behavior.

```
<button type="button" class="w-full flex items-center gap-2 rounded px-2 py-2 text-left
                              hover:bg-muted/50 focus-visible:ring-2 focus-visible:ring-ring">
  <!-- Jira issue: -->
  <IssueTypeIcon typeName={issueType} class="size-4 shrink-0" />
  <span class="text-xs text-muted-foreground font-mono shrink-0">{key}</span>
  <span class="flex-1 min-w-0 truncate text-sm">{summary}</span>

  <!-- AIO cycle: -->
  <ListChecks class="size-4 shrink-0 text-muted-foreground" />   -- Lucide ListChecks
  <span class="text-xs text-muted-foreground font-mono shrink-0">{projectKey}</span>
  <span class="flex-1 min-w-0 truncate text-sm">{name}</span>
</button>
```

No Log Work trigger on pinned rows (D-08: read-only).

## Empty / Loading / Error States

### Per-section loading state (query is pending)

Three skeleton bars matching the YesterdayColumn `LoadingSkeletons` pattern:

```tsx
<div class="flex flex-col gap-2 py-2">
  <Skeleton class="h-4 w-full" />
  <Skeleton class="h-4 w-full" />
  <Skeleton class="h-4 w-full" />
</div>
```

Use `useDelayedLoading` hook to prevent flicker on fast loads (existing app convention).

### Per-section error state (query failed, D-03)

Render `<ErrorState>` with a Retry handler — do NOT hide the section silently.

```tsx
<ErrorState
  error={query.error}
  onRetry={() => void query.refetch()}
  viewName="In Progress items"   // or "Up Next items", "MRs awaiting you", "Pinned items"
/>
```

`ErrorState` is imported from `@/components/ui/error-state` (same as YesterdayColumn).

### Per-section — no items (query resolved, 0 items)

Per D-03: hide the section entirely. Do NOT render the section header or an empty state
within it. Only the full-column empty state fires.

### Full-column empty state (all sections empty)

Fire only when all four queries have resolved successfully with 0 items AND the sprint
query is not loading.

```tsx
<EmptyState
  icon={Clock}
  title="Nothing planned for today"
  subtitle="No items in progress, nothing up next, no MRs awaiting review, and no pinned items."
/>
```

`EmptyState` imported from `@/components/ui/empty-state`. `Clock` from lucide-react.

### Jira not connected (sprint queries disabled because `!jiraBaseUrl || !jiraToken`)

Do not render In Progress, Up Next, or Pinned-Jira sections. Show a per-section inline note:

```
<p class="text-xs text-muted-foreground">Jira not connected. Configure Jira in Settings → Integrations.</p>
```

### GitLab not connected (MRs query disabled)

Do not render MRs Awaiting You section. No inline note needed — hiding is appropriate
for a section that requires a disabled integration (consistent with D-03).

## Interaction Contracts

### Row navigation

- Whole-row `<button>` click → `onIssueClick(key)` via outlet context.
- Log Work button click → opens `LogWorkPopover`; must call `e.stopPropagation()` to
  prevent the outer row button from also triggering navigation.
- MRs Awaiting You rows are non-navigable in this phase (no `onMRClick` wired yet).
- Pinned AIO cycle rows → navigate to AIO cycle detail using existing cycle-tab navigation
  (same pattern as `PinnedTabStrip`). Exact navigation call: reuse the cycle navigation
  util already used by the pinned tab strip.

### Log Work Popover

- Pre-fills `initialDate` with today's date string via `todayString()` (YYYY-MM-DD, TZ-safe).
- Pre-fills `issueKey` with the row's Jira issue key.
- On success, invalidate the Tempo worklogs query so logged-time chips refresh.
  Invalidate key: `['standup', 'tempo', ...]` matching the query key in `StandupNotesPage`.

### Hover states

- Issue rows: `hover:bg-muted/50` on the `<button>` element.
- No hover state on MRs Awaiting You rows (non-interactive).
- No hover state on section headers.

### Focus management

- All `<button>` rows: `focus-visible:ring-2 focus-visible:ring-ring` — matches existing
  app keyboard navigation pattern.
- Tab order: column heading → first In Progress row → its Log Work button → next row → ...
  → Up Next rows → MRs rows → Pinned rows.
