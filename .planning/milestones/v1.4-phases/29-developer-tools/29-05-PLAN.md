**Part B — WaterfallTab.tsx (full rewrite):**

Replace the current global-timeline approach with a per-operation scoped design:

1. **Per-operation timelines**: Each operation row computes its own 0-to-wallClockMs timeline. Do NOT use a single global timeline spanning all operations. This is the root cause of bars being invisible slivers.

2. **Header**: Replace the current 3-value time axis with a simple title row: "Operation" (left column) and "Timeline" (right column).

3. **Source filter controls**: Add a row of filter buttons above the operations list:
   - "All" (default), "Jira", "GitLab" — filter operations by the `source` field of their fetches
   - Use small pill-style buttons with `sourceBadgeClass` styling for Jira/GitLab
   - Track active filter in local state

4. **Sort control**: Add a toggle next to filters — "Newest" (default, by timestamp desc) vs "Slowest" (by wallClockMs desc).

5. Pass each `<WaterfallBar>` only the operation data — it will self-scope its own timeline internally.

**Part C — WaterfallBar.tsx (full rewrite):**

Replace the current implementation with a usable, self-scoped design:

1. **Self-scoped timeline**: The operation bar spans the full width of the timeline area (it represents 0% to 100% of its own duration). No `leftPct` positioning — each operation fills its lane.

2. **Operation summary row** (always visible):
   - Left: operation label (truncated, 200px)
   - Center: A single colored bar spanning full width. Color based on dominant source (`jira` = orange-500/20, `gitlab` = purple-500/20, mixed = blue-500/20). Show `wallClockMs` as text inside (or to the right if bar is narrow). Add small fetch count badge: e.g., "(3 fetches)".
   - Right: expand/collapse chevron

3. **Vertical gridlines**: Inside the timeline area, render 4 evenly spaced dashed vertical lines using CSS (`border-left: 1px dashed`). Below each gridline at the bottom of the expanded area, show time labels (0ms, 25%, 50%, 75%, 100% of wallClockMs). Use absolute positioned divs inside a relative container.

4. **Expanded fetch bars** (when open):
   - Each fetch positioned by `(fetch.startTime - operation.startTime) / operation.wallClockMs * 100`%
   - Width: `fetch.durationMs / operation.wallClockMs * 100`% (min 2%)
   - Color: Use `fetchBarColor` — jira=orange-400, gitlab=purple-400, error=red-400 (stronger colors than current bg-muted)
   - Overlapping fetches shown on separate rows to visualize parallelism: Sort fetches by startTime, then place each on the first row where it doesn't overlap with existing bars (simple greedy lane assignment algorithm)

5. **Smart duration labels**: If bar width > 60px, show duration inside the bar. Otherwise, show it to the right of the bar.

6. **Hover tooltips**: On each fetch bar, use the `title` attribute with: `${fetch.method} ${fetch.url}\nStatus: ${fetch.status ?? 'error'}\nDuration: ${fetch.durationMs}ms`

7. **Fetch detail text**: Below each fetch bar row, show a small monospace label: `METHOD source /path` (truncate URL to last path segment).
