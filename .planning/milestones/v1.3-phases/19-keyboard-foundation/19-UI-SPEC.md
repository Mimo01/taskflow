| Token | Value | Usage |
|-------|-------|-------|

## Color

All values reference CSS custom properties from `src/index.css`. Both light and dark modes are handled by the existing token system.

| Role | Token | Light Value | Dark Value | Usage |
|------|-------|-------------|------------|-------|
| Dominant (60%) | `--background` | oklch(1 0 0) white | oklch(0.145 0 0) near-black | Dialog backdrop surface, page |
| Secondary (30%) | `--card` / `--muted` | oklch(1 0 0) / oklch(0.97 0 0) | oklch(0.205 0 0) / oklch(0.269 0 0) | Dialog popup background, `<kbd>` badge fill |
| Accent (10%) | `--primary` | oklch(0.205 0 0) near-black | oklch(0.922 0 0) near-white | `<kbd>` border color only |
| Destructive | `--destructive` | oklch(0.577 0.245 27.325) red | oklch(0.704 0.191 22.216) red | Not used this phase |

Accent (`--primary`) reserved for: `<kbd>` badge border only. No other element in this phase uses the accent/primary color.

`<kbd>` badge appearance: `bg-muted text-foreground border border-border rounded-sm` — a neutral bordered badge that looks like a physical key. Does not use the accent color as fill; accent is reserved for the border to give a subtle pressed-key outline effect consistent with the neutral palette.

Backdrop: `bg-black/50` — matches CreateEpicDialog exactly (source: CONTEXT.md canonical ref).

Category heading color: `text-muted-foreground` — matches SearchOverlay section header pattern.

## Interaction Contract

### ? key — Open shortcuts panel
- Trigger: `useHotkeys('?', openPanel)` via `react-hotkeys-hook@^5.2.4`
- Guard: default behavior (no `enableOnFormTags`) — does NOT fire when focus is inside `<input>`, `<textarea>`, `<select>` (KEYS-07 satisfied by library default)
- If panel is already open: do nothing (idempotent)
- Placement: hook lives in the component that owns panel open state (App root or layout component)

### Escape — Close shortcuts panel
- Trigger: @base-ui/react Dialog handles Escape natively when `open={true}`
- No explicit `useHotkeys` needed for this — the dialog's built-in behavior covers KEYS-02

### SearchOverlay Escape migration
- Remove: `window.addEventListener('keydown', ...)` raw listener in `SearchOverlay.tsx`
- Replace: `useHotkeys('escape', onClose, { enableOnFormTags: true })` — `enableOnFormTags: true` is intentional here so Escape works while typing in the search input

### Focus management
- On panel open: Dialog.Popup receives focus (base-ui default)
- On panel close (Escape): focus returns to previously focused element (base-ui default)
- No custom focus trap needed — @base-ui/react/dialog handles this
