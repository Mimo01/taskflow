## Skeleton Component Contract

This section is Phase 44-specific. It defines the visual contract for each new skeleton component.

### Primitive

All skeletons MUST use the shadcn `Skeleton` primitive from `src/components/ui/skeleton.tsx`:
```
<Skeleton className="..." />
```
This produces: `bg-accent animate-pulse rounded-md` — the only approved skeleton fill. Do NOT use raw `div` with `bg-muted animate-pulse` (the legacy pattern being replaced).

### Animation

Use shadcn Skeleton default: `animate-pulse` (CSS pulse, 2s ease-in-out infinite). No custom animation overrides.

### Per-View Skeleton Dimensions

| View | Skeleton Component | Layout Shape | Row Count | Row Height |
|------|-------------------|-------------|-----------|------------|
| Sprint board | SprintBoardSkeleton | Header bar (full-width h-9) + N columns side-by-side, each with stacked card placeholders (h-20) | 3 columns, 3 cards each | h-9 header, h-20 cards |
| Backlog | BacklogSkeleton | Header bar (full-width h-9) + table rows | 6 rows | h-10 |
| My tasks | MyTasksSkeleton | Stacked rows, full-width | 5 rows | h-10 |
| Workload | WorkloadSkeleton | Stacked rows, full-width | 5 rows | h-8 |
| Sprint progress | SprintProgressSkeleton | Stacked rows, full-width | 5 rows | h-8 |
| Epics | EpicsSkeleton | Stacked rows, full-width | 5 rows | h-10 |
| Releases | ReleasesSkeleton | Stacked rows, full-width | 5 rows | h-10 |
| MR attention | MrAttentionSkeleton | Stacked rows, full-width | 5 rows | h-10 |

### Dashboard Widget Skeletons

One generic pattern per widget, co-located with the widget file. Two widget skeleton shapes exist:

| Widget Shape | Components Using It | Visual |
|-------------|--------------------|----|
| Text-line skeleton | SprintProgressWidget (already using Skeleton), WorkloadWidget (already using Skeleton) | 3 stacked Skeleton lines at h-4, varied widths (w-full, w-3/4, w-5/6) |
| Row skeleton | MrAttentionWidget, ReleasesWidget, CustomJqlWidget, SprintHealthWidget, MrHealthWidget, NotificationsWidget, PinnedIssuesWidget, SavedFiltersWidget | 3 stacked Skeleton rows at h-6, full-width |

Note: SprintProgressWidget and WorkloadWidget already use the Skeleton primitive correctly — do not modify their loading pattern, only ensure they are consistent with the new contract.

### Flicker Prevention

`useDelayedLoading` hook:
- Input: `isPending: boolean`
- Output: `showSkeleton: boolean`
- Behavior: returns `false` for first 200ms after `isPending` becomes `true`; returns `true` if still `isPending` after 200ms
- Threshold: 200ms uniform across all views (CONTEXT.md D-08)
- Location: `src/hooks/useDelayedLoading.ts`

Refresh button behavior: Refresh calls `queryClient.invalidateQueries()` scoped to the view's query keys. The skeleton delay is bypassed on manual refresh — `showSkeleton` is `true` immediately when refresh is triggered while query is pending. This gives visible feedback that reload is in progress (CONTEXT.md D-11, user requirement from specifics).

### Progressive Loading

**Sprint board (CONTEXT.md D-05):**
- Stage 1: Parent issues (story headers) query resolves → render story column headers immediately, show subtask placeholder rows beneath each
- Stage 2: Subtask query resolves per-parent → subtasks replace placeholders progressively
- Subtask placeholders: `<Skeleton className="h-8 w-full" />` per expected subtask slot

**Backlog (CONTEXT.md D-06):**
- Stage 1: Main issues query resolves → render backlog table rows immediately, epic badge column shows `<Skeleton className="h-4 w-16" />` placeholder per row
- Stage 2: Epic metadata query resolves → epic badge fills in, replacing skeleton placeholders
- Row renders without epic badge first; badge placeholder is inline within the row, not a separate overlay
