    **Strategy:** Use `queryClient.fetchQuery` (not `prefetchQuery`) for `jira-board-id` to get the resolved `boardId` value, then chain a `queryClient.prefetchQuery` for `jira-backlog-view` using that boardId. Since `jira-board-id` has `staleTime: Infinity`, the first call does a network request (~200ms) and all subsequent calls return instantly from cache.

    **Step 2: Update the `/backlog` branch in `prefetchForPath`**

    Replace the comment "skip prefetch for backlog-view itself" with a chained prefetch. Change the `/backlog` case (currently inside the `path === '/backlog' || path === '/epics'` branch) to:

    ```typescript
    } else if (path === '/backlog' || path === '/epics') {
      queryClient.prefetchQuery({
        queryKey: ['jira-epics-basic', activeJiraProject, jiraBaseUrl],
        queryFn: () => fetchEpicsBasic(jiraBaseUrl, jiraToken, activeJiraProject, epicNameFieldKey, epicColorFieldKey),
        staleTime: 5 * 60 * 1000,
      });
      if (path === '/backlog') {
        // Resolve boardId first (staleTime: Infinity — instant from cache after first load),
        // then prefetch the backlog view with the resolved boardId.
        queryClient.fetchQuery({
          queryKey: ['jira-board-id', activeJiraProject, jiraBaseUrl],
          queryFn: () => fetchBoardId(jiraBaseUrl, jiraToken, activeJiraProject),
          staleTime: Infinity,
        }).then((boardId) => {
          if (boardId != null) {
            queryClient.prefetchQuery({
              queryKey: ['jira-backlog-view', activeJiraProject, jiraBaseUrl],
              queryFn: () => fetchBacklogView(jiraBaseUrl, jiraToken, activeJiraProject, boardId, storyPointsFieldKey, epicLinkFieldKey, epicNameFieldKey),
              staleTime: STALE_TIME_MS,
            });
          }
        }).catch(() => {
          // Board discovery failed — silently skip backlog prefetch.
          // User will still get a normal load when they navigate.
        });
      }
    }
    ```

    **Key design points:**
    - `queryClient.fetchQuery` (not `prefetchQuery`) is used for `jira-board-id` because we need the resolved value to pass to `fetchBacklogView`. `fetchQuery` returns the data; `prefetchQuery` returns void.
    - The `staleTime: Infinity` on the board-id fetch means after the user has visited any page that calls `useBoardId()` (sprint board or backlog), subsequent sidebar hovers resolve the board ID instantly from cache with zero network cost.
    - The `queryKey` for `jira-backlog-view` is `['jira-backlog-view', activeJiraProject, jiraBaseUrl]` — this matches BacklogPage.tsx line 203 exactly (no `boardId` in key).
    - The `.catch()` silently swallows errors — prefetch failures should never surface as user-visible errors.
    - The `fetchBacklogView` call passes `storyPointsFieldKey`, `epicLinkFieldKey`, and `epicNameFieldKey` to match the BacklogPage queryFn signature.
