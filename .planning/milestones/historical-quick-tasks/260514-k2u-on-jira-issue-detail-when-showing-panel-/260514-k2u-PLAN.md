<objective>
Fix the "huge internal padding" inside `{panel}` (and `{info}` / `{warning}` / `{note}`) callouts rendered on the Jira issue detail view.

Purpose: The panel's own padding is fine (`p-3`, 12px). The visible "huge padding" comes from `@tailwindcss/typography`'s `prose` styles cascading into the callout `<div>`: `<p>` children inside the panel inherit `prose-sm` margins (`margin-top` / `margin-bottom` ~1.14em ≈ 16px), and the FIRST and LAST `<p>` inside the panel contribute their full margin on top of the panel's `p-3`. Combined, top and bottom each look ~28-30px, hence "huge".

Output: A surgical Tailwind arbitrary-variant tweak to `calloutStyles` in `WikiRenderer.tsx` that zeroes the first-child top margin and last-child bottom margin, plus a regression test in `WikiRenderer.test.tsx`. Spacing BETWEEN panel paragraphs is preserved; spacing OUTSIDE callouts is unchanged.
</objective>

<investigation_summary>
**Confirmed culprit** (no rewrite needed):
- `taskflow/src/routes/dashboard/WikiRenderer.tsx:312-317` — `calloutStyles` map applies `p-3 my-2` to all four callout types.
- `taskflow/src/routes/dashboard/WikiRenderer.tsx:445` — the entire renderer is wrapped in `<article class="prose prose-sm dark:prose-invert max-w-none">`.
- `taskflow/src/index.css:2` — `@plugin "@tailwindcss/typography";` is active.
- The callout `<div>` is rendered INSIDE `prose`, so any `<p>` element produced by react-markdown for the panel body inherits `prose-sm`'s default `<p>` margins. The first `<p>`'s top margin and the last `<p>`'s bottom margin stack on top of the panel's own `p-3`, producing the doubled-padding effect the user sees.
- Same wrapper (same `calloutStyles[type]` formula, all share `p-3 my-2 rounded-r-md border-l-4`) is used for info / warning / note. Per the planner's note, the fix must apply uniformly to all four so unrelated macros are not over-tightened — uniform application is the SAFER choice here because all four currently have the same too-loose spacing.
- The renderer also emits an `inline-block` `<span data-callout>` form for callouts that appear inside table cells (line 376). That form uses the SAME `calloutStyles[calloutType]` string, so the fix applies there too via the same selector; no separate change required.

**What this plan does NOT do:**
- Does not change `p-3`, `my-2`, the border, the background, or any color.
- Does not touch the renderer pipeline, the preprocess pipeline, or the sanitize schema.
- Does not change behavior for content outside callouts.
</investigation_summary>
