<objective>
Take the unification work from quick task 260517-pjv (which unified Jira/AIO **status** pills) and extend it to **every other pill and badge** across the app so the entire visual language is consistent.

Purpose: After 260517-pjv, status pills are uniform but the rest of the app still has at least four other chip dialects living side-by-side:

1. The shared `Badge` component itself uses `rounded-4xl` (very rounded pill shape) — so any `<Badge variant="secondary|outline|default|destructive">` doesn't match the unified status pill (`rounded` — rounded rectangle).
2. Hand-rolled `rounded-full border px-2 py-0.5 text-xs font-medium` chips in: MergeRequestDetailPage (labels), ReleaseDetailPage (labels), MergeRequestListPage (labels), FieldsSection (epic pill + epic color swatch), EpicsPage (epic name pill), StoryHeaderRow (epic pill), BacklogRow (epic pill), WikiRenderer (mention badge), BacklogPage (section header Active/Backlog chip), sprint-move-menu-items.
3. Hand-rolled `rounded-full ... bg-{color}-100 text-{color}-800 border-{color}-300` heavy color palette in: MergeRequestListPage (MR state badge — note: this one actually uses `rounded` already, but its sibling `MergeRequestDetailPage.MRStateBadge` uses `rounded-full`), MergeRequestDetailPage (MR state + pipeline status badges), MrRow (Stale chip), BacklogPage (section Active/Backlog chip). These should also adopt the muted-tint family for color consistency with status pills.
4. Solid-color `<Badge>` overrides like `bg-green-600 text-white` / `bg-amber-500 text-white` / `bg-orange-500 text-white` in ReleaseDetailPage and ReleasesTab and ReleasesWidget — these clash with the muted-tint status pills next to them on the same page.

The goal is **one** visual language: rounded-rectangle (`rounded`), `text-xs font-medium`, muted-tint colors (`bg-{color}-500/15 text-{color}-{600|400 dark}`). Identity-color chips (per-epic color, per-GitLab-label color) keep their source colors but adopt the same geometry. Circles that exist for a reason (notification count dots in tabs/topbar, status dots in lists, progress bars, toggle switches) are NOT pills and stay as-is.

Output:
- `badge.tsx`: change `rounded-4xl` → `rounded`. Add a `tone` variant prop (`blue | green | red | orange | amber | purple | muted`) that maps to the muted-tint palette (`bg-{color}-500/15 text-{color}-{600|400 dark}`). Existing `variant` prop (`default | secondary | destructive | outline | ghost | link`) stays for backwards compatibility — `default` and `secondary` are the most common uses and remain valid.
- `statusStyles.ts`: add a tiny `tonePillClass(tone)` helper that returns just the color portion (so a hand-rolled chip using `STATUS_PILL_LAYOUT_CLASS` for layout can grab the matching color tokens without re-importing Badge). One source of truth for the muted-tint palette.
- 14 consumer files updated: hand-rolled chip geometry replaced by either `<Badge tone="...">` or a literal `STATUS_PILL_LAYOUT_CLASS`-based string. Solid `bg-green-600` etc. Badge color overrides replaced by `tone="green"` / `tone="amber"` / etc. variants.
- Identity-color chips (epic color, GitLab MR label color) keep their inline `style={{ backgroundColor, color, borderColor }}` BUT change their className geometry from `rounded-full` to `rounded` to match the unified shape.
</objective>
