<objective>
When a user clicks a rendered Jira or GitLab link that resolves to an internal route via `tryInternalPath` (added in quick task 260518-pq2), push the **current** page onto the breadcrumb trail (`useBreadcrumbStore.push({ path, label })`) before calling `navigate()`. The destination detail pages (`IssueDetailPage`, `MergeRequestDetailPage`, `AioTestRunDetailPage`) already render the back-arrow + breadcrumb header from the same store, so the user can immediately return to where they came from.

Purpose: Today a user clicking a Jira link inside, e.g., an MR description on `/mr/99/42` is dropped onto `/issue/PROJ-123` with no breadcrumb — there is no "back to MR !42" affordance. This change makes the navigation symmetric with how IssueDetail's "drill issue → issue" already behaves: the source page is recorded so the user can return.

Output: Two modified call sites and one regression test, asserting the breadcrumb push happens before the navigate() on an internal hit and that fallback (openUrl) paths do NOT push.
</objective>
