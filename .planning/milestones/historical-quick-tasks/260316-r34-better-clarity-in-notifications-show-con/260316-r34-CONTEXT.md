# Quick Task 260316-r34: Better clarity in notifications - Context

**Gathered:** 2026-03-16
**Status:** Ready for planning

<domain>
## Task Boundary

Improve notification clarity by showing what specifically changed in Jira issue updates and GitLab MR notifications. Currently notifications show generic "Issue update" with no context about what changed. The goal is to surface field-level changes (e.g., "Status: In Progress → Done") so users can triage notifications without opening the source.

</domain>

<decisions>
## Implementation Decisions

### Fields to Track
- **Jira:** Status and assignee changes only — these are the most actionable
- Skip priority, sprint, fix version, labels, etc. — keep it focused

### Change Display Format
- Arrow format: "Status: In Progress → Done", "Assignee: → John Smith"
- Compact before/after text replacing the generic body preview for issue-update notifications
- Show in both notification row (body preview) and detail panel (full body)

### GitLab Coverage
- Apply same treatment to GitLab MR notifications
- Show MR state changes (opened → merged), reviewer assignments, label changes
- Same arrow format for consistency

</decisions>

<specifics>
## Specific Ideas

- Jira REST API `changelog` expand can provide field-level diffs
- For Jira: use `expand=changelog` on issue fetch, extract recent changes within the polling window
- For GitLab: system notes contain state change info that's currently filtered out — parse these instead
- Multiple field changes in one update should be listed on separate lines
- If no changelog data available, fall back to current generic "Issue update" behavior

</specifics>
