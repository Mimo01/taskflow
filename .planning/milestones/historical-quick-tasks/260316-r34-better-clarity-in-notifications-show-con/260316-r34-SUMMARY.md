# Quick Task 260316-r34: Better Clarity in Notifications Summary

Arrow-format changelog extraction for Jira (expand=changelog, status/assignee fields) and GitLab (system note parsing for state/reviewer/label changes) with multi-line UI rendering in notification feed and detail views.

## What Changed

### Jira Changelog Extraction (notifications.ts)
- Added `expand=changelog` to the JQL search URL for issue updates
- Extracts status and assignee changes from `issue.changelog.histories[]` within the polling window
- Builds arrow-format strings: `Status: In Progress -> Done`, `Assignee: (none) -> John Smith`
- Sets `author` to the person who made the change (from changelog history), not the assignee
- Falls back to generic `Status: {current}` when no changelog entries exist in the window

### GitLab System Note Parsing (notifications.ts)
- No longer unconditionally skips all system notes
- Parses state changes (`closed`, `merged`, `reopened`) into arrow format with inferred previous state
- Passes through reviewer request and label change system notes as-is
- Non-actionable system notes (description changes, commit mentions) still skipped
- System note notifications use `gitlab-system-{id}` IDs to avoid collision with regular note IDs

### UI Rendering (NotificationRow.tsx, NotificationDetail.tsx)
- NotificationRow splits pipe-separated changes into block spans for multi-line display within line-clamp-2
- NotificationDetail renders newline-separated changes as individual divs with py-0.5 spacing
- Arrow character presence used as rendering mode signal (arrow = structured, no arrow = linkified HTML)
- Comment mentions and regular MR notes render unchanged
