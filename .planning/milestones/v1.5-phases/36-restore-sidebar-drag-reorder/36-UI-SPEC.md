## Interaction Contract

This phase is primarily an interaction contract, not a visual one. The following defines the drag-and-drop behavior precisely.

### Row Layout (D-01, D-02)

```
[GripVertical 16x16] [gap-2] [Checkbox 16x16] [gap-3] [Label text-sm]
```

- GripVertical icon: `size-4` (16x16px), rendered inside a `<button>` element
- Drag handle button receives `setActivatorNodeRef`, `{...attributes}`, `{...listeners}`
- Checkbox and label remain fully clickable, isolated from drag events

### Drag Behavior

| Property | Value | Source |
|----------|-------|--------|
| Sensor | PointerSensor | Existing project pattern (SprintBoardTab) |
| Activation constraint | distance: 5px | Prevents accidental drags on click |
| Axis constraint | restrictToVerticalAxis | Modifier from @dnd-kit/modifiers |
| Collision detection | closestCenter | Standard for vertical sortable lists |
| Sorting strategy | verticalListSortingStrategy | From @dnd-kit/sortable |
| List structure | Single flat SortableContext | D-03, D-04: free reorder across sections |

### Drag States

| State | Visual Treatment |
|-------|-----------------|
| Idle | Normal row appearance with GripVertical handle visible |
| Handle hover | Handle icon transitions from muted-foreground to foreground |
| Dragging (source position) | Opacity 0.5, item remains in flow as placeholder |
| Drag overlay (floating clone) | bg-background, border border-border, shadow-md, scale-[1.02], rounded-md |
| Drop target | Automatic via @dnd-kit/sortable CSS transforms (items shift to make space) |
| After drop | 200ms transition on transform via useSortable transition property |

### Section Headers in Settings (D-04)

- Section headers (Work / Views / Tools) render as non-draggable plain `<span>` elements
- Section headers are NOT included in the SortableContext items array
- Section headers appear between groups visually but do not participate in drag

### Store Integration (D-05)

- `onDragEnd` maps `active.id` and `over.id` to store indices via `sidebarItems.findIndex()`
- Calls `reorderSidebarItem(fromIndex, toIndex)` -- existing tested action
- No new store fields, no migration needed

### DragOverlay Pattern

- Track `activeId` state via `onDragStart` (set) and `onDragEnd` (clear)
- Render overlay as a static clone of the item row (handle + checkbox + label)
- Overlay renders via React portal (DragOverlay default behavior)
