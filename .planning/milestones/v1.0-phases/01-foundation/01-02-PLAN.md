    - 200 response → returns { displayName: string, emailAddress: string }
    - 401 → throws Error('Invalid token or token has expired')
    - 403 → throws Error('Token valid but lacks required permissions')
    - network failure (fetch throws) → throws Error('Cannot reach [baseUrl] — check the base URL')
    - non-ok status not 401/403 → throws Error('Cannot reach [baseUrl] — check the base URL')

    jira.ts — listJiraProjects:
    - returns Array<{ id: string; key: string; name: string }> from GET /rest/api/2/project
    - uses Bearer auth header

    gitlab.ts — validateGitLab:
    - 200 response → returns { id: number; name: string; username: string }
    - 401 → throws Error('Invalid token or token has expired')
    - 403 → throws Error('Token valid but lacks required permissions')
    - network failure → throws Error('Cannot reach [baseUrl] — check the base URL')

    gitlab.ts — listGitLabGroups:
    - returns Array<{ id: number; name: string; full_path: string }> from GET /api/v4/groups
    - uses PRIVATE-TOKEN header

    AUTH note: Implement Bearer for Jira. Include a comment explaining the Bearer vs Basic ambiguity
    (Jira Server 8.14+ supports Bearer; older instances may need Basic base64(:token)).
    Do not implement Basic fallback in Plan 02 — that's a Phase 2 concern once we have a real instance.
    The service function signature allows adding a configurable strategy later without changing callers.
  </behavior>
