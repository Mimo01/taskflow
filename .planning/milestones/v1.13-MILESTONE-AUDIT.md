## What Changed Since the Prior Audit

The earlier v1.13 audit flagged **one blocker — MYTASK-01**: the `/my-tasks` route was reachable by URL, but the sidebar entry was invisible for every existing install because the settings store had no migration to inject the `my-tasks` sidebar item. That blocker is now **CLOSED**:

- `settings.store.ts` bumped to **version 27**; `appendMyTasksItemIfMissing` added (line 238) and called under `if (version < 27)` (lines 463–466), mirroring the existing `appendWorklogsItemIfMissing` (v21) and `appendStandupNotesItemIfMissing` (v23) pattern.
- 3 unit tests pin the helper (`settings.store.test.ts:503–526`); the stale version assertion was fixed.
- The integration checker confirmed the full chain is WIRED end-to-end: `migrate()` → `sidebarItems` → `Sidebar.tsx:241–253` `visibleIds` → `SIDEBAR_NAV_ITEMS` → NavLink → lazy `MyTasksPage`.
- Commits: `5c2ac903`, `cfd70efb`, `28e29785`.

With the blocker gone and no other unsatisfied requirements, the FAIL gate does not trigger. The milestone drops to **tech_debt** — accumulated dead code, stale comments, and one uncommitted working-tree change, none of which block close.
