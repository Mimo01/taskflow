# Phase 38 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase UI Scope

Phase 38 is a service and infrastructure layer. By decision D-01 (CONTEXT.md), update checks run completely silently — no UI indication is rendered during routine background checks. No new dialogs, banners, progress bars, or visual surfaces are introduced in this phase. The only observable UI artifact is the `updateCheckInterval` setting being persisted in the settings store, which will be exposed in the settings UI in Phase 40.

This contract documents the design system state, tokens, and copywriting standards that all Phase 38 code must conform to — ensuring consistency when Phase 39 and 40 build atop this foundation.

## Copywriting Contract

Phase 38 has no user-visible UI surfaces. The following copywriting standards apply to the internal developer tools log entries only (D-02: errors logged to Developer Tools request log).

| Element | Copy |
|---------|------|
| Primary CTA | None — Phase 38 introduces no user-facing actions |
| Empty state heading | Not applicable — no list or data views introduced |
| Empty state body | Not applicable |
| Error state (dev tools log) | "Update check failed: {error message}" |
| Update check log entry | "Update check: {status} — {version or 'up to date'}" |
| Destructive confirmation | None — Phase 38 has no destructive actions |

Note: These log entries appear only in the Developer Tools panel (an existing internal debugging surface), not in any user-facing UI.

## Interaction Contract

Since Phase 38 is silent infrastructure, the interaction contract describes what must NOT happen, not what should happen.

| Scenario | Required Behavior | Decision Source |
|----------|------------------|----------------|
| Update check in progress | No spinner, no loading indicator, no status text shown | D-01 |
| Update not found | No notification, no toast, no badge update | D-01 |
| Update check fails (network error) | No error toast, no error banner, no user alert | D-02 |
| Update check fails | Log entry written to Developer Tools request log | D-02 |
| First check timing | Check fires ~7 seconds after app mount, never before | D-03 |
| Manual interval setting | `updateCheckInterval` stored in settings; no UI exposed until Phase 40 | D-07 |

## State Machine Visual Contract

The `UpdateStatus` state machine (`update.store.ts`) will drive Phase 39 and 40 UI. Phase 38 must define all states correctly so downstream phases can map them to visual representations without refactoring.

| State | Phase 39 Will Render | Phase 40 Will Render |
|-------|---------------------|---------------------|
| `idle` | Nothing | Nothing |
| `checking` | Nothing (silent per D-01) | Nothing |
| `available` | Update prompt dialog | "Update available" badge in Settings nav |
| `downloading` | Progress bar in update dialog | — |
| `ready` | "Restart to update" prompt | — |
| `error` | Nothing to user; logged to dev tools | — |

Phase 38 delivers this store fully typed and transition-complete. No states may be added or renamed in Phase 39 without updating this contract.
