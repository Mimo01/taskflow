# Phase 73 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope Note

Phase 73 is primarily a data-layer rewrite. The existing SprintBoardTab visual design is **unchanged and not re-specified here**. This contract locks only the **four new or modified surfaces**:

1. `timeInColumn` badge on each card
2. "Reload board" toolbar action (replaces "Reload workflow transitions")
3. Orphan subtask card rendering
4. StatusPopover anchoring for multi-target drag-to-transition drops

All other board surfaces (column headers, story swimlane headers, card chrome, drag handles, skeleton loading, stale-data banner, QuickCreateInput, sprint goal banner, filter bar) inherit from the existing implementation without change.

## New Surface Specifications

### 1. timeInColumn Badge

**Location:** Bottom-right of the card, inside the existing bottom row (`flex items-center justify-between mt-1`), placed **after** the story-points chip within the right-side `shrink-0` container.

**Slot:** Append inside `<div className="flex items-center gap-1.5 shrink-0">` at `TaskCard.tsx:144`, after the story-points badge and before the `showStatus` badge.

**Render condition:** Only when `issue.timeInColumn?.enteredStatus` is truthy. Suppress silently if absent.

**Markup contract:**
```tsx
<span
  className="text-[11px] text-muted-foreground bg-muted rounded-full px-1.5 py-0.5 font-mono leading-none"
  title={`Entered status ${formatDistanceToNow(new Date(issue.timeInColumn.enteredStatus))} ago`}
>
  {formatDistanceToNowStrict(new Date(issue.timeInColumn.enteredStatus))}
</span>
```

**Classes:** identical to story-points chip at `TaskCard.tsx:147` (`text-[11px] text-muted-foreground bg-muted rounded-full px-1.5 py-0.5 font-mono leading-none`).

**`title` attribute:** `"Entered status N ago"` where N is `formatDistanceToNow(...)` (not strict — natural phrasing). Per D-05a, this is the only tooltip; no Radix Tooltip wrapper.

**Text format:** `formatDistanceToNowStrict(new Date(enteredStatus))` output verbatim (e.g. `"3 days"`, `"5 hours"`, `"2 minutes"`). date-fns is already in the dependency graph (planner verifies via `package.json`).

**Accessibility:** `title` attribute provides the tooltip; no additional `aria-label` needed as the badge is decorative metadata.

### 2. "Reload board" Toolbar Action

**Replaces:** Phase 72's "Reload workflow transitions" `<button>` at `SprintBoardTab.tsx:1153-1161`. The `<Workflow>` icon button is **removed** and replaced with this action.

**Also consolidates:** The existing bare `<RefreshCw>` button at `SprintBoardTab.tsx:1140-1152` is **merged into** the "Reload board" action (one reload action replaces two). The resulting toolbar has a single reload control.

**Location:** Same absolute-positioned right-side toolbar div at `SprintBoardTab.tsx:1130`. Single icon button in place of the two previous buttons.

**Icon:** `RefreshCw` from `lucide-react` (size `size-3`) — reuses the existing refresh icon. Remove `Workflow` import if no longer used elsewhere.

**Label / aria-label:** `"Reload board"` — used as both `aria-label` and `title` attribute.

**Loading state:** While the invalidation/refetch is in flight, apply `animate-spin` to the `RefreshCw` icon (Tailwind utility). Disable the button (`disabled` attribute) during loading to prevent double-clicks.

**Inline feedback (aria-live):** Keep the `role="status" aria-live="polite"` span at `SprintBoardTab.tsx:1133`. On success, set its text to `"Board reloaded"`. On error, set it to `"Failed to reload board"`. Auto-clear after 3 seconds (mirrors Phase 72 timeout pattern at `SprintBoardTab.tsx:757`).

**Invalidation scope (D-07):** `['gh-all-data', boardId]` + `['gh-transitions', currentProjectId]` + `['jira-statuses']`.

**Button className:** Inherits from existing `"inline-flex items-center gap-1 text-xs text-muted-foreground hover:text-foreground transition-colors"`.

**No toast.** The project has no `sonner` / Toaster setup. All feedback is inline via the `aria-live` span. Do NOT introduce a toast library.

### 3. Orphan Subtask Cards

**Decision (D-04b):** Render as standalone cards in their `statusCategory` bucket. Visually **indistinguishable** from story cards.

**No special styling.** Do not add a border accent, badge, or icon to mark orphan cards. The `warnOnce(\`orphan-subtask:${parentId}\`)` console warning is the only signal; it must not appear in the rendered UI.

**Rationale:** Minimum-surprise behavior. Orphans are rare (subtask assigned to sprint without its parent). A visual callout would add noise for an edge case.

**Render path:** Same `TaskCard` component, `isSubtask={false}`, no `onToggle` / `subtaskCount` props. The card is a sibling of story rows in its column bucket.

---

### 4. StatusPopover for Multi-Target Drag-to-Transition

**Trigger:** When a card is dragged into a bucket where more than one legal transition exists (i.e. `filteredTransitions.length > 1`), anchor `StatusPopover` at the drop target position and let the user pick. Single legal transition → apply immediately without popover.

**Component reuse:** Use the existing `StatusPopover` component (`StatusPopover.tsx`) with no structural changes. The component already accepts `projectId`, `issueTypeId`, `currentStatusId`, `currentStatus`, and `onSelect`.

**Pre-filtering:** Pass `currentStatusId` from the dragged card. `StatusPopover` internally calls `filterTransitionsForStatus` — this already narrows to transitions valid from the card's current status. No additional pre-filtering is needed in the caller.

**Anchor contract:** Render `StatusPopover` inside a `Popover` with `open={true}` anchored to the dropped card element (use the card's bounding `DOMRect` via a ref or `data-card-key` attribute). The `PopoverContent` should appear at `side="bottom"`, `align="start"` (matching existing StatusPopover usage in `TaskRow.tsx:111`).

**Dismissal:** If the user dismisses the popover without selecting (Escape or click-outside), treat as a cancelled drop — do not transition the card. Restore the card to its original column (rollback, same as an error path).

**Keyboard:** Popover is keyboard-navigable by default via Radix `Popover` — no additional keyboard handling needed.
