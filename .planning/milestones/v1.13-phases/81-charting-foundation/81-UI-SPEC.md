## Spacing Scale

Declared values (multiples of 4 — standard 8-point scale):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chart legend glyph-to-label gap, description top margin |
| sm | 8px | Compact element spacing, chart tooltip padding |
| md | 16px | Default element spacing, card body padding |
| lg | 24px | Section padding, ChartWrapper card padding |
| xl | 32px | Layout gaps between chart sections |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**ChartWrapper height contract (explicit-height guard — CONTEXT.md D-03):**

- Outer `<div>` carrying the chart area must declare an explicit pixel height, not `height="100%"`.
- Smoke-test chart: `min-h-[240px]` (240px). This prevents 0×0 WebKit collapse.
- Downstream chart consumers (Phase 83+) may choose their own fixed heights (e.g. 300px for donut, 200px for sparkline), but must always use an explicit px value.

Exceptions: none beyond the explicit-height rule above.

## Component Contracts

### ChartWrapper (new — CHART-03)

The canonical wrapper all chart consumers (Phases 83–85) must use. This is the full visual contract; the executor must not deviate without updating this spec.

**Card chrome:**
- Renders as a card (`bg-card`, `rounded-[var(--radius)]`, `border border-border`, `p-6`)
- `title` (string, required): `text-base font-semibold text-foreground`
- `description` (string, optional): `text-sm text-muted-foreground mt-1` (4px top margin — `xs` spacing token)
- Title + description stack vertically above the chart area with `mb-4` gap to the chart

**Chart area:**
- Explicit-height outer `<div>` — passed as `style={{ height: heightPx }}` where `heightPx` is a prop (number, px). Default: `240`.
- Chart children render inside this div only in success state (not loading, not error, not empty)

**State rendering (status-prop card — CONTEXT.md D-05):**

| State | Trigger | Rendered element | Copy |
|-------|---------|-----------------|------|
| Loading | `isLoading={true}` | `<Skeleton className="w-full h-full rounded-md" />` inside the explicit-height div | (no text) |
| Error | `error` prop is non-null | `<ErrorState error={error} onRetry={onRetry} viewName={title} />` replacing chart area | "Couldn't load {title}" + Retry button |
| Empty | `isEmpty={true}` | `<EmptyState icon={BarChart2} title="No data yet" subtitle="Data will appear here once available." />` replacing chart area | See Copywriting section |
| Success | none of the above | `{children}` rendered inside explicit-height div | — |

**Compiler escape hatch:** File must contain `'use no memo'` directive at module scope (CONTEXT.md D-04).

**Props signature (informative — executor may refine names but must cover these semantics):**

```
ChartWrapper({
  title: string
  description?: string
  height?: number          // default 240
  isLoading?: boolean
  error?: unknown
  isEmpty?: boolean
  onRetry?: () => void
  children: ReactNode
})
```

## Interaction Contracts

### Animations
- `isAnimationActive={false}` on all Recharts series (Pie, Bar, Line, etc.) — locked by CONTEXT.md D-04.
- Skeleton loading pulse uses the standard `animate-pulse` CSS animation (Tailwind utility, inherited).
- No other motion in this phase.

### Theme switching
- Charts inherit theme via the `.dark` class on `<html>` (set by `loadTheme()` in `main.tsx` before `createRoot`).
- `ChartContainer` from `chart.tsx` handles the CSS-var binding automatically — no JS listener needed.
- Correct colors on first paint is a verified requirement (CHART-01).

### Responsive width
- Chart width is responsive (fills the card's content width) via the `responsive` prop on Recharts components.
- Height is always a fixed pixel value — never `height="100%"` (WebKit collapse guard, CONTEXT.md D-03).

### Lazy loading (no interaction, but visible behavior)
- Dashboard route becomes `React.lazy()`. First load of `/dashboard` shows `<route-spinner>` Suspense fallback until the chunk loads.
- This spinner is already implemented in `taskflow/src/components/ui/route-spinner.tsx` — no new loading UI needed.
