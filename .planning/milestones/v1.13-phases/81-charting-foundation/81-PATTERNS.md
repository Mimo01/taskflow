## Pattern Assignments

### `src/components/ui/chart.tsx` (ui primitive, copy-paste)

**Created by:** `npx shadcn@latest add chart` — do not hand-write this file.

**Analog:** `src/components/ui/skeleton.tsx`

The shadcn copy-paste tier means the file is owned by the project but generated by the CLI. `skeleton.tsx` is the simplest example of this pattern in the codebase — a named export, no index barrel, uses `cn()` from `@/lib/utils`.

**Skeleton.tsx structure** (`src/components/ui/skeleton.tsx`, lines 1–13):
```typescript
import { cn } from '@/lib/utils';

function Skeleton({ className, ...props }: React.ComponentProps<'div'>) {
  return (
    <div
      data-slot="skeleton"
      className={cn('bg-accent animate-pulse rounded-md', className)}
      {...props}
    />
  );
}

export { Skeleton };
```

**What to expect from `npx shadcn@latest add chart`:** The generated `chart.tsx` will export `ChartContainer`, `ChartTooltip`, `ChartTooltipContent`, `ChartLegend`, `ChartLegendContent`, `ChartStyle`, and `ChartConfig` (type). It imports from `recharts` and uses `cn()`. The executor must run the CLI command and commit the generated file as-is — no hand-rolling.

**Import path consumers use:**
```typescript
import { ChartContainer, ChartTooltip, ChartTooltipContent } from '@/components/ui/chart'
import type { ChartConfig } from '@/components/ui/chart'
```

Note: `'use no memo'` is a module-level directive that must appear as the **first statement** of the file (before imports per React docs, but the compiler accepts it as first line). Place it at line 1.

**Card chrome pattern** (`DashboardInProgressCard.tsx` line 108):
```typescript

```

`ChartWrapper` uses `p-6` (UI-SPEC: `lg` spacing token = 24px) and `rounded-[var(--radius)]` (matches shadcn convention):
```typescript
<div className="bg-card rounded-[var(--radius)] border border-border p-6">
```

**Loading state pattern** (`DashboardInProgressCard.tsx` lines 117–124) — project uses inline pulse div, but `ChartWrapper` should use the `<Skeleton>` component:
```typescript
// DashboardInProgressCard inline style (do NOT copy this):
```

**Status-prop branching pattern** (derived from `DashboardInProgressCard.tsx` structure, D-05 in CONTEXT.md):
```typescript

  if (isLoading) return <Skeleton className="w-full h-full rounded-md" />

  if (isEmpty) return (
```

### `src/components/chart-wrapper.test.tsx` (test, render)

**Analog:** `src/components/ui/error-state.test.tsx`

This is the closest match: tests a component that uses `useNavigate` internally (so needs router mock), uses `render`/`screen` from `@testing-library/react`, mocks with `vi.mock()`, groups with `describe`/`it`, and uses `expect(...).toBeTruthy()` style (not `.toBeInTheDocument()` for the simpler assertions, though both are available via `@testing-library/jest-dom`).

**Imports pattern** (`error-state.test.tsx` lines 1–11):
```typescript
import { fireEvent, render, screen } from '@testing-library/react';
import { beforeEach, describe, expect, it, vi } from 'vitest';

const mockNavigate = vi.fn();
vi.mock('react-router-dom', () => ({
  useNavigate: () => mockNavigate,
}));

import { ErrorState } from './error-state';
```

For `chart-wrapper.test.tsx`, the router mock is needed for tests that trigger the `error` branch (because `ErrorState` calls `useNavigate`). The loading and empty branches do not need router context. Use `MemoryRouter` wrapper for the error branch test:

```typescript
import { MemoryRouter } from 'react-router-dom';
// ...
render(<MemoryRouter><ChartWrapper error={new Error('oops')} ...>...</ChartWrapper></MemoryRouter>);
```

**Test structure pattern** (`error-state.test.tsx` lines 17–35):
```typescript
describe('ChartWrapper — loading state', () => {
  it('renders Skeleton when isLoading={true}', () => {
    render(<ChartWrapper title="Test" isLoading height={200}><div>chart</div></ChartWrapper>)
    // Skeleton renders a div with data-slot="skeleton" + animate-pulse
    expect(document.querySelector('[data-slot="skeleton"]')).toBeTruthy()
  })
})

describe('ChartWrapper — success state', () => {
  it('renders children when no loading/error/empty', () => {
    render(<ChartWrapper title="Test"><div>my chart</div></ChartWrapper>)
    expect(screen.getByText('my chart')).toBeTruthy()
  })
})
```

**No `beforeEach` needed** unless mocking console.error for the ErrorState logging side-effect (copy pattern from `error-state.test.tsx` line 14):
```typescript
beforeEach(() => {
  vi.clearAllMocks();
  vi.spyOn(console, 'error').mockImplementation(() => {});
});
```

**Test coverage required** (from RESEARCH.md Validation Architecture):
- `isLoading={true}` → Skeleton renders, children do not
- `error` non-null → ErrorState renders, children do not
- `isEmpty={true}` → EmptyState renders, children do not
- success state → children render, no Skeleton/ErrorState/EmptyState

## Shared Patterns

### `'use no memo'` directive
**Source:** CONTEXT.md D-04, RESEARCH.md Pattern 2
**Apply to:** `src/components/chart-wrapper.tsx` only
**Position:** First line of the file, before imports

```typescript
'use no memo'

import ...
```

This is a React Compiler escape hatch. No existing file in the codebase uses it yet — it is new for Phase 81. Place it at line 1.

### CSS-var color passthrough
**Source:** CONTEXT.md D-08; `src/index.css` lines 33–37 and 105–109
**Apply to:** `SmokeTestChart.tsx` and all future chart consumers
**Rule:** Always pass `"var(--chart-N)"` strings as `fill`/`stroke` props. Never use hex, `getComputedStyle`, or any JS-side resolution.

```typescript
fill="var(--chart-1)"
color: 'var(--chart-1)'  // in ChartConfig
```

### `@/` path alias
**Source:** All existing source files; `tsconfig.json`
**Apply to:** All new files
**Pattern:** Always import using `@/components/...`, `@/lib/...` etc. — never with relative `../../` paths that cross feature boundaries.

### Named exports (not default exports) for UI components
**Source:** `src/components/ui/skeleton.tsx`, `src/components/ui/empty-state.tsx`, `src/components/ui/route-spinner.tsx`
**Apply to:** `src/components/chart-wrapper.tsx`
**Pattern:** `export function ChartWrapper(...)` — named export, not `export default`.

`SmokeTestChart.tsx` may use a named export too: `export function SmokeTestChart()`.

### `isAnimationActive={false}` on all Recharts series
**Source:** CONTEXT.md D-04
**Apply to:** `SmokeTestChart.tsx` and all future chart consumers
**Pattern:** Every Recharts chart component (`BarChart`, `PieChart`, `LineChart`, etc.) must receive `isAnimationActive={false}`.
