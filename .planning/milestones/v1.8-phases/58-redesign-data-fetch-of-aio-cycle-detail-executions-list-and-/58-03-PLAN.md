<objective>
Refactor `AioCycleDetailPage.tsx` to (a) drive the progress bar from `fetchAioCycleSummaries` (one fast POST) instead of waiting on the full run enumeration, (b) pass raw `jiraDefectIDs` to `DefectRow` so resolution happens through TanStack Query's cache layer (already correctly implemented in DefectRow), and (c) optionally switch the runs-list data source to the new fetch function from Plan 02 if probe found one.

Purpose: Fixes Pitfalls 2 and 3 from RESEARCH (progress bar blocking on full run load, defect re-resolution on every refetch). For a 261-test cycle with 3 defects, this changes the page from ~264 sequential HTTP round trips before any progress info appears, to a single summary POST that renders the progress bar in <1s while the run list loads in parallel.

Output: Refactored page component with `summaryQuery`, `jiraProjectIdQuery`, and `cycleNumericIdQuery` (or `useDetail` extraction) wired correctly; updated test file covering decoupled progress bar; AION-03/AIOC-01 behaviours preserved.
