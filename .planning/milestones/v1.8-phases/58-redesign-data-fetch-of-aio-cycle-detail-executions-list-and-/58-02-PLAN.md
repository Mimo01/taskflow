<objective>
Refactor the AIO service layer to remove the N+1 defect-resolution pattern from `fetchAioTestRunsForCycle`, and optionally add a new paged run-list fetch function in `cycles.ts` if Wave 0 probe found a `/rest/aio-tcms/1.0` run-listing endpoint. The component layer (Plan 03) will resolve defects per-key using TanStack Query so duplicate defect keys across runs deduplicate automatically.

Purpose: Eliminates the 261-test cycle's worst-case ~264 sequential HTTP round-trip pattern (paginated runs + serial defect resolution) by moving defect resolution into the cache-aware component layer. Also adds the fast-path endpoint when available so the run-list itself loads in one or two requests instead of paginating.

Output: Refactored `issue-runs.ts` + updated tests; optionally new `fetchAioTestRunsPaged` in `cycles.ts` with its tests; updated `index.ts` barrel if a new function is added.
</objective>
