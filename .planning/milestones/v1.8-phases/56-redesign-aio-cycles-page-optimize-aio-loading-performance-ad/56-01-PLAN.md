## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stronghold ↔ React | `readSecret('jira-pat')` crosses from native Tauri Stronghold into JS heap; token must not be logged, persisted, or appended to query keys |
| useQuery key serialization | TanStack devtools serialize query keys to localStorage in development — token must never appear in any queryKey array |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-56-01-01 | Information Disclosure | `useAioCredentials` return value | mitigate | Hook returns token via React state only; never logs to console; never adds to query keys (existing convention preserved — query keys use `jiraBaseUrl`, not token). Verified by absence of `console.log` / `console.error` involving the token in the hook source. |
| T-56-01-02 | Tampering | `readSecret('jira-pat')` argument | accept | Argument is a literal string constant `'jira-pat'`; not user-controlled. No injection vector. |
| T-56-01-03 | Denial of Service | Repeated readSecret calls if hook used in many components | mitigate | useEffect deps `[]` ensures one call per hook instance; Plans 02/03 will prop-drill token to row components (per D-16 / Pitfall 6) rather than re-calling the hook per row. |
| T-56-01-04 | Repudiation | Hook errors silently swallow exceptions | accept | `.catch(() => setToken(null))` is intentional per existing pattern; UI surfaces auth failure via empty/error state on the consuming page. No security log is required for read-only token retrieval. |
</threat_model>
