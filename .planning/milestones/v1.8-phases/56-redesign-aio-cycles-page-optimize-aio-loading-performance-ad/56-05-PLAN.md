<objective>
Fix Gap 3: the Defects tab always appears empty because `normalizeTestRun` maps `defects` from `raw.defects` (always absent on the real API) instead of resolving the `jiraDefectIDs: number[]` on the latest `RawRunExecution` to Jira issue keys.

The fix is entirely in the service layer (`issue-runs.ts`): after fetching test runs for a cycle, resolve each run's `jiraDefectIDs` to `{ key: string }` via `GET /rest/api/2/issue/{numericId}?fields=key`, then store the resolved keys in `AioTestRun.defects[]`. The page (`AioCycleDetailPage.tsx`) already derives `allDefects` from `run.defects[]` — if the service layer is fixed the Defects tab becomes populated automatically.

A mandatory probe step inspects the live endpoint for: (a) whether a `defects: string[]` field already exists somewhere on the raw run payload (avoiding the extra API calls entirely), and (b) confirming that `GET /rest/api/2/issue/{numericId}` returns `{ key }`.

Purpose: Satisfies AIOC-03 defects tab correctness gap found in Plan 04 verification.
Output: Fixed service layer, updated tests, populated Defects tab on real AIO data.
</objective>
