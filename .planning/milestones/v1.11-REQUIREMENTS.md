# Requirements Archive: Taskflow — v1.11 GreenHopper API Migration

**Archived:** 2026-06-01 (milestone close)
**Defined:** 2026-05-28
**Core Value:** Developers and PMs can see everything they need — tasks, merge requests, sprint state, notifications, and test execution health — in one place, without switching between Jira, GitLab, and AIO.

**Milestone goal:** Eliminate Jira API n+1 bottlenecks by migrating the app's Jira backbone to the on-prem GreenHopper API (`/rest/greenhopper/1.0/xboard/*`). Reference: `.planning/research/GREENHOPPER-API.md`.

---

## v1.11 Requirements (All Complete)

### Adapter Layer

- [x] **GH-ADAPT-01**: GreenHopper API client module created under `services/jira/greenhopper/` with typed responses for `allData`, `data`, `details`, and `transitions` — **Outcome: `greenhopperFetch` wrapper + 12 response interfaces shipped in Phase 71**
- [x] **GH-ADAPT-02**: Entity-map resolver helpers (statusId → Status, priorityId → Priority, typeId → Type, epicId → Epic) so existing UI components can keep consuming the existing UI `Issue` / `Status` / `Epic` types — **Outcome: `buildEntityMaps` + resolver helpers shipped in Phase 71 (71-04)**
- [x] **GH-ADAPT-03**: Issue adapter mapping GreenHopper `Issue` shape (numeric IDs, `estimateStatistic.statFieldValue.value`, `parentId`/`epicId` resolved via lookup maps) onto the existing app `Issue` type used by board/backlog UI — **Outcome: `adaptIssue` + `createAdapter` shipped in Phase 71 (71-05)**

### Sprint Board (`allData.json`)

- [x] **GH-BOARD-01**: Sprint board fetches all issues, columns, swimlanes, statuses, priorities, types, and epics in a single `allData.json` call — **Outcome: `useGhAllData` + single-call migration shipped in Phase 73**
- [x] **GH-BOARD-02**: Per-issue `timeInColumn.enteredStatus` is surfaced on the card — **Outcome: `TaskCard` timeInColumn badge shipped in Phase 73 (73-02)**
- [x] **GH-BOARD-03**: Sprint board renders columns from GreenHopper `columnsData` and groups by `parentId` — **Outcome: `statusCategory`-based CATEGORY_COLUMNS bucketing; `columnsData.columns[]` not consumed (accepted per D-03/D-03a — design note in tech debt)**
- [x] **GH-BOARD-04**: Existing sprint-board features (drag-to-transition, QuickCreateInput, epic/quick-filter/label filters, sprint goal banner) work unchanged — **Outcome: All features verified passing in Phase 73 + Phase 72 UAT**

### Backlog (`data.json`)

- [x] **GH-BACKLOG-01**: Backlog view fetches the flat issue list via a single `data.json` call — **Outcome: `useGhBacklogData` + single-call migration shipped in Phase 74**
- [x] **GH-BACKLOG-02**: Existing backlog features (move-to-sprint, create story, filter by epic/label/assignee, virtualized rendering) work unchanged — **Outcome: All features verified passing in Phase 74 UAT (3/3 passed)**

### Issue Detail (Progressive Rendering)

- [x] **PERF-DETAIL-01**: Issue detail panel renders the header as soon as the base issue fetch resolves — **Outcome: Header visible at TTFMP 1180ms (changelog gates "fully loaded" at TTI 1682ms)**
- [x] **PERF-DETAIL-02**: Each detail section loads via its own independent request and shows a localized skeleton while pending — **Outcome: 3 independent section queries with 200ms-gated skeletons shipped in Phase 75 (75-02)**
- [x] **PERF-DETAIL-03**: Existing detail-panel features work unchanged on the existing REST v2 paths — **Outcome: All features verified passing; detail panel stays on Jira REST v2**

### Workflow Transitions (`transitions.json`)

- [x] **GH-TRANS-01**: `transitions.json` is fetched once per project and cached — **Outcome: `useGhTransitions` cache keyed by `projectId × issueTypeId → workflow → transitions[]` shipped in Phase 72**
- [x] **GH-TRANS-02**: Sprint-board drag-to-transition and issue-detail status change read available transitions from the cached map — **Outcome: 4 call sites swapped in Phase 72 (72-02)**
- [x] **GH-TRANS-03**: Cache is invalidated on project/workflow change; manual refresh action available — **Outcome: `invalidateGhTransitions` + "Reload workflow transitions" toolbar action shipped in Phase 72**

### Cutover & Verification

- [x] **GH-CUT-01**: Hard cutover per surface — old REST paths for board/backlog/transitions deleted as replacements ship — **Outcome: `fetchSprintSubtasks` deleted in Phase 73; legacy backlog fetchers deleted in Phase 74; legacy `fetchTransitions` GET deleted in Phase 72**
- [x] **GH-CUT-02**: Performance verification — capture before/after request counts and TTFMP/TTI for sprint-board, backlog, and issue-detail open — **Outcome: Artifact `taskflow/docs/perf/75-issue-detail-progressive.md` with live TTFMP/TTI measurements; sprint-board + backlog reduction from multi-call to single-call verified in network log**

## Out of Scope

| Feature | Reason |
|---------|--------|
| Migrating Jira write actions (status transitions POST, comment post/edit, inline field edit, attachment upload, worklog CRUD, createmeta) | GreenHopper provides reads; writes stay on existing REST v2 services |
| Migrating global search / JQL search | Not covered by the four GreenHopper endpoints in scope |
| Coexistence feature flag / staged rollout | User chose hard cutover per surface — REST removed in place |
| Unifying `jira.ts` (60 imports) and modular `services/jira/` split | Pre-existing tech debt; out of scope |
| Multi-board switching UI | Board ID is supplied by existing settings |
| Migrating issue detail to GreenHopper `details.json` | Descoped mid-milestone — Phase 75 rescoped to progressive rendering of existing REST v2 panel |
