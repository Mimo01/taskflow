### Integration Warnings

**BLOCKER — GH-BOARD-04 / GH-TRANS-02: Sprint board stale after issue-detail status change**

`FieldsSection.tsx:263` fires legacy invalidation keys (`['jira-sprint-stories']`, `['jira-issues', 'sprint-board']`) that have no active subscriber after Phase 73. It does NOT call `invalidateGhAllData`. Result: sprint board shows old status for up to `POLL_INTERVAL_MS` (~60s) after a status change initiated from the issue detail panel. Drag-to-transition within the board is unaffected.

**Fix:** add `invalidateGhAllData(queryClient, boardId)` to `FieldsSection.transitionMutation.onSettled`, mirroring the existing `invalidateGhBacklogData` call. `boardId` is accessible via the board store.

**WARNING — GH-CUT-01: Phantom `jira-sprint-stories` key on secondary surfaces**

`main.tsx:382` and `RecentItemsPopover.tsx:58` use `getQueriesData({ queryKey: ['jira-sprint-stories'] })` to look up sprint issue titles and recent items. After Phase 73 cutover, no component registers `useQuery` with this key — both reads silently return empty. Sprint issues are invisible in the title resolver and recent-items lookup.

**INFO — GH-TRANS-02: Orphaned transition consumers (pre-existing)**

`QuickCreateInput` and `BulkActionBar` correctly call `getGhTransitions` but are not rendered by any production parent. This was also true before Phase 72.

**INFO — GH-CUT-01 VERIFICATION drift**

Phase 73 VERIFICATION.md claims `handleReloadBoard` invalidates 5 cache keys. Post-milestone cleanup removed `fetchBoardQuickFilters`; live code has 4 keys. Current behavior is correct; the artifact is stale.
