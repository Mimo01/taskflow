## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding (icon `size-4` = 16px) |
| sm | 8px | Compact element spacing (button px-2.5, dialog gap-2) |
| md | 16px | Default element spacing (dialog p-4, banner px-3) |
| lg | 24px | Section padding within dialog content |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Progress bar height: 8px (h-2) — smaller than xs intentionally for track appearance
- Dialog max-width: `sm:max-w-sm` (384px) — inherits from dialog.tsx default
- Hard minimum overlay: `fixed inset-0 z-[200]` — full viewport, no padding constraint

Source: Observed from `dialog.tsx`, `stale-data-banner.tsx`, `button.tsx` size variants

## Typography

All sizes use Geist Variable at `font-sans`. Weights match the base-nova preset and the existing dialog/button patterns. Maximum 2 weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (regular) | 1.5 |
| Label | 12px (text-xs) | 400 (regular) | 1.4 |
| Heading | 16px (text-base) | 600 (semibold) | 1.2 |
| Display | 20px (text-xl) | 600 (semibold) | 1.2 |

Notes:
- Dialog title uses `text-base font-semibold` (16px/600) — override `DialogTitle` default to align with 2-weight contract
- Progress percentage label uses `text-xs text-muted-foreground` (12px/400) — from RESEARCH.md code example
- Changelog rendered via react-markdown uses `@tailwindcss/typography` prose styles — do not override heading/body sizes within changelog scroll area; let prose defaults apply
- Version numbers (e.g. "v1.6.0 → v1.7.0") use `text-sm` (14px/400)

Source: `taskflow/src/components/ui/dialog.tsx`, `taskflow/src/index.css`

## Color

All tokens are OKLCH CSS variables from `taskflow/src/index.css`. Both light and dark modes are supported via `.dark` class.

| Role | Token | Light Value | Usage |
|------|-------|-------------|-------|
| Dominant (60%) | `--background` | oklch(1 0 0) — white | App background, dialog surface (`bg-background`) |
| Secondary (30%) | `--muted` / `--secondary` | oklch(0.97 0 0) — near-white | Dialog footer (`bg-muted/50`), banner background (`bg-muted`), secondary buttons |
| Accent (10%) | `--primary` | oklch(0.205 0 0) — near-black | Primary CTA buttons only (Update Now, Got it, Restart Now) |
| Warning | `--chart-1` (amber proxy) | oklch(0.809 0.105 251.813) | Soft minimum banner warning icon only — use `text-amber-500` / `text-warning` if available, fall back to Lucide `TriangleAlert` icon in `text-muted-foreground` |
| Destructive | `--destructive` | oklch(0.577 0.245 27.325) — red | Error state in UpdateDialog (download error message text + Retry button variant="destructive") |

Accent (`--primary`) reserved for:
- "Update Now" button (variant="default") in UpdateDialog available view
- "Update Now" button in SoftMinimumBanner
- "Update Now" button in HardMinimumOverlay
- "Got it" button in WhatsNewDialog
- "Restart Now" button (if user cancels countdown and manually triggers restart)

Destructive (`--destructive`) reserved for:
- Error message text in UpdateDialog error view
- "Retry" button (variant="destructive") in UpdateDialog error view — signals that the previous action failed

Source: `taskflow/src/index.css` CSS variable definitions

## Component Inventory

Components to create in `taskflow/src/components/update/`:

### UpdateDialog

Single dialog component driven by `useUpdateStore.status`. Uses existing `Dialog`, `DialogContent`, `DialogHeader`, `DialogFooter`, `DialogTitle` from `@/components/ui/dialog`.

**States and their visual treatment:**

| Status | View Name | Dismissable | Footer Buttons | Primary Focal Point |
|--------|-----------|-------------|----------------|---------------------|
| `available` | AvailableView | Yes (Later) | "Update Now" (default), "Later" (outline) | Changelog scroll area |
| `downloading` | DownloadingView | No | "Stop Download" (outline) only | Progress bar |
| `ready` | ReadyView | No (during countdown; yes after cancel) | "Restart Later" (outline) to stop countdown | Countdown seconds display |
| `error` | ErrorView | Yes (Dismiss) | "Retry" (destructive), "Dismiss" (outline) | Error message text |

**AvailableView layout:**
```
DialogHeader
  DialogTitle: "Update Available"
  DialogDescription: "v{currentVersion} → v{availableVersion}"
[Changelog scroll area — max-h-48 overflow-y-auto]
  react-markdown prose-sm content
DialogFooter
  "Later" button (variant="outline")
  "Update Now" button (variant="default")
```

**DownloadingView layout:**
```
DialogHeader
  DialogTitle: "Downloading Update"
  DialogDescription: "v{availableVersion}"
[Progress bar — w-full bg-muted rounded-full h-2]
  [bg-primary h-2 rounded-full transition-all]
[Label row: "{downloadProgress ?? 0}%  ·  {bytesDownloaded} / {totalBytes}"]
DialogFooter
  "Stop Download" button (variant="outline")
```

**ReadyView layout:**
```
DialogHeader
  DialogTitle: "Ready to Restart"
  DialogDescription: "Restarting in {seconds}s…"
[Countdown visual — large text-xl font-semibold centered: "{seconds}"]
DialogFooter
  "Restart Later" button (variant="outline") — stops countdown, returns to available state
```

**ErrorView layout:**
```
DialogHeader
  DialogTitle: "Download Failed"
  DialogDescription: [error message text in text-destructive]
DialogFooter
  "Dismiss" button (variant="outline")
  "Retry" button (variant="destructive")
```

**Blocking behavior:**
- `downloading` and `ready` (during active countdown): `DialogContent` renders with `showCloseButton={false}`; `Dialog.Root` has no `onOpenChange` prop — prevents ESC and backdrop dismiss
- `available` and `error`: `DialogContent` renders with `showCloseButton={false}` (no X button; dismiss is only via explicit footer button); `Dialog.Root` has `onOpenChange` wired to handle close

## Interaction States

### UpdateDialog — State Machine Visual Transitions

```
idle → [no dialog rendered]
available → AvailableView (dismissable via "Later")
  └─ Later → idle (resetToIdle; polling will re-open on next check)
  └─ Update Now → downloading
downloading → DownloadingView (non-dismissable)
  └─ Stop Download → available (or idle; preserve availableVersion)
  └─ [auto on complete] → ready
ready → ReadyView (10s countdown, non-dismissable during countdown)
  └─ Restart Later → available (stop countdown; user defers restart)
  └─ [auto at 0s] → [relaunch()]
error → ErrorView (dismissable)
  └─ Dismiss → idle
  └─ Retry → downloading
```

### Countdown Timer Behavior

- Starts at 10 seconds
- Decrements by 1 every 1000ms using `setInterval` inside `useEffect`
- `useEffect` cleanup: `clearInterval` on unmount or when `seconds` reaches 0
- At `seconds === 0`: calls `relaunch()` — fire and forget (`catch(() => {})`)
- Restart Later button: clears interval, calls store `setAvailable()` to return user to AvailableView

### Download Progress Display

- `downloadProgress` is a 0–100 integer from `useUpdateStore`
- Progress bar `width` style: `${downloadProgress ?? 0}%`
- Label shows: `{downloadProgress ?? 0}%`
- Bytes display: show `{bytesDownloaded} / {totalBytes}` in `text-xs text-muted-foreground` below bar — only when `contentLength` is available from the progress event; hide row if `contentLength` is null/0

### Soft Minimum Banner Dismissal

- Rendered when: `softMinimumActive && !softNagDismissed`
- "X" dismiss: `setSoftNagDismissed(true)` — session state only
- "Update Now": triggers same `handleUpdateNow` flow as dialog — opens UpdateDialog in available state
- Reappears on next app launch (not persisted)

### Hard Minimum Overlay — Interaction

- No interactive elements except "Update Now" button
- "Update Now" button: triggers update check + opens UpdateDialog flow
- If update check fails (network error): show inline error below the button — `text-sm text-destructive` — "Couldn't check for updates. Check your connection."
- No keyboard shortcut to dismiss (ESC is suppressed)

### What's New Dialog — Trigger Logic

```typescript
// In AppLayout, evaluated on mount:
const showWhatsNew =
  settings.lastSeenVersion !== buildInfo.version &&
  settings.lastSeenChangelog !== null;

// On "Got it" dismiss:
setLastSeenVersion(buildInfo.version);
// lastSeenChangelog is NOT cleared — kept for future reference
```

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Hard minimum overlay focus trap | Base UI Dialog handles focus trap natively when `open={true}`; HardMinimumOverlay uses a Dialog primitive with no `onOpenChange` |
| UpdateDialog — keyboard ESC | Suppressed during `downloading` and `ready` states by omitting `onOpenChange` |
| Progress bar | `role="progressbar" aria-valuenow={downloadProgress} aria-valuemin={0} aria-valuemax={100}` on the outer div |
| Countdown | `aria-live="polite"` on the seconds display element |
| SoftMinimumBanner dismiss | Dismiss X button has `<span className="sr-only">Dismiss update reminder</span>` |
| HardMinimumOverlay heading | `<h1>` or DialogTitle with `role="alertdialog"` — screen reader announces immediately |
| Color contrast | All text on `bg-muted` or `bg-background` meets WCAG AA (OKLCH neutrals verified) |
